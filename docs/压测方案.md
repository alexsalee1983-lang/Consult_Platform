# 压测方案（M5 ⑥）

依据：开发计划 S5 ⑥、决策记录 2026-11-13“M5 压测方法与通过标准”。只在测试机本地运行，只用虚拟项目（默认 LOAD-A）和压测账号，不在生产环境运行（压测账号命令在 `APP_ENV=prod` 拒绝执行）。

## 1. 工具与文件

| 文件 | 作用 |
|---|---|
| `loadtest/locustfile.py` | Locust 场景：每个虚拟用户一个压测账号，按顾问日常操作比例混合请求，结束时按阈值判定，未达标退出码 1 |
| `loadtest/requirements.txt` | `locust==2.47.0`，只装在测试机的独立虚拟环境里，不进后端镜像（理由：压测是测试机上的一次性工具，与平台运行无关） |
| `python -m app.cli loadtest-accounts` | 建或重置 `lt-01`…`lt-NN` 顾问账号，加入压测项目；没有 D5 大纲时建大纲（每人一章）；凭据只写进 `--out` 文件（权限 600），不打印；`--disable` 停用全部压测账号并注销会话 |

动态码防重放，同一账号 30 秒内只能登录一次，所以每个虚拟用户必须用独立账号；账号数不少于并发用户数。

## 2. 场景（每个虚拟用户，操作间隔 3～10 秒）

| 权重 | 请求名 | 内容 |
|---|---|---|
| 4 / 4 / 2 | projects.list / projects.detail / auth.me | 浏览项目 |
| 3 / 3 / 2 | evidences.list / deliverables.detail / confirmations.list | 证据、交付件、确认卡 |
| 3 | kb.search | 知识检索（通用安全管理用语） |
| 1 / 1 | notes.create / documents.upload | 录入观察、上传小文本资料（内容每次不同） |
| 2 | sections.write | 写 D5 自己那一章（新建版本） |
| 1 | deliverables.export | 导出 D5 Word |
| 1 | runs.start | 发起交付链（同一项目同时只能有一个运行，409 视为正常） |
| 1 | chat.stream | 顾问对话（经网关走模型，读完整个流） |

交付链只写 D3、D4，压测写章节和导出用 D5，互不干扰。

## 3. 通过标准

| 项 | 标准 |
|---|---|
| 错误 | 10 人持续 30 分钟，失败 0 次 |
| 普通接口 | 每个请求名 p95 < 1 秒（`API_P95_MS`） |
| 知识检索 | p95 < 2 秒（`SEARCH_P95_MS`） |
| 顾问对话 | 模拟模型轮次 p95 < 5 秒（`CHAT_P95_MS`）；真实模型轮次只记录，按模型实际情况另定 |
| 后台任务 | 结束 5 分钟内无积压（`python -m app.cli jobs` 无 queued / running 堆积） |
| 资源 | 内存和数据库连接数不持续上涨（压测前、中、后各记一次 `docker stats --no-stream` 和连接数） |
| 尖峰 | 20 人 5 分钟不崩（不要求阈值，但不能有 5xx） |

前三项由脚本自动判定；后三项人工记录。

## 4. 步骤（测试机，仓库根目录）

```bash
# 0. 整套启动；第一轮用模拟模型（只测平台）
docker compose --profile mock-llm up -d --build      # .env 里 LLM_BASE_URL=http://mock-llm:8000/v1
python3 -m venv ~/lt-venv && ~/lt-venv/bin/pip install -r loadtest/requirements.txt

# 1. 准备 20 个压测账号（10 人轮次和 20 人尖峰共用），凭据拷到 loadtest/accounts.json（已在 .gitignore）
docker compose exec -T backend python -m app.cli loadtest-accounts --count 20 --out /tmp/lt.json
docker compose cp backend:/tmp/lt.json loadtest/accounts.json && chmod 600 loadtest/accounts.json
docker compose exec -T backend rm -f /tmp/lt.json

# 2. 资源基线
docker stats --no-stream
docker compose exec -T postgres psql -U consult -d consult -tc "select count(*) from pg_stat_activity"

# 3. 10 人 30 分钟
cd loadtest && ~/lt-venv/bin/locust -f locustfile.py --headless -u 10 -r 2 -t 30m -H http://localhost:8080 \
  --csv /tmp/lt-10 --html /tmp/lt-10.html; echo "退出码 $?"
# 中途（约 15 分钟）再记一次第 2 步的资源数据

# 4. 结束后：资源、后台任务积压
docker stats --no-stream; docker compose exec -T backend python -m app.cli jobs

# 5. 20 人尖峰 5 分钟（等第 3 步结束 30 秒后再开始，避开动态码时间窗）
~/lt-venv/bin/locust -f locustfile.py --headless -u 20 -r 10 -t 5m -H http://localhost:8080 --csv /tmp/lt-20

# 6. 收尾：停用压测账号、删凭据文件
cd .. && docker compose exec -T backend python -m app.cli loadtest-accounts --disable && rm -f loadtest/accounts.json
```

HTTPS 部署时 `-H https://localhost:8443`，自签测试证书加环境变量 `REQUESTS_CA_BUNDLE=$PWD/../deploy/tls/server.crt`（在 loadtest 目录下运行时）。

第二轮（公司模型接入后）：`.env` 改为公司模型地址，重复第 1～6 步，`CHAT_P95_MS` 按模型实际情况放宽，只记录对话时延。测试机与生产配置差距大时，上线前在生产服务器再跑一轮。
