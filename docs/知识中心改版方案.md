# 知识中心改版方案（v3）

2026-11-27 负责人与统筹讨论定稿。示意页：`design/screens/08-知识中心改版示意.html`；后台逻辑与闭环：`design/screens/09-知识中心后台逻辑.html`。决策见 `docs/决策记录.md` 2026-11-27 条。

## 一、原则

1. 页面只放人要做的事。Agent 和程序在后台做的事不上日常页面，采用**隐藏**（不灰显）。只有两处用灰字：投料人自己交的东西显示“处理中”，健康格子显示“自动补齐中”。
2. 外部经验（公开资料）长期自动获取、自动保鲜，结果只体现在知识健康看板。
3. 新建服务产品、行业、地区，或知识到期、法规变更，都由系统自动识别缺口并自动获取，规划内的缺口不找人。
4. 需要人时由系统推卡，没有“人要定期去看”的环节。
5. 数据保护红线、资质边界不因此放松。

## 二、界面

| 页面 | 谁用 | 做什么 |
|---|---|---|
| 待我处理 | 知识专家、负责人 | 只有必须由人判断或担责的卡片；处理完即空 |
| 知识健康 | 所有人只读 | 产品 × 行业覆盖矩阵（按地区筛选）、就绪度与趋势、保鲜率、引用命中率；格子注明是否需要人 |
| 投料箱 | 顾问 | 零星提交与批量上传（文件夹或压缩包）；“我交的 · 我报的”看批次结果、退回原因、反馈回执 |
| 规划与规则 | 负责人 | 新建或停用产品、行业、地区；新增来源；自动发布门槛 |
| 驾驶舱 · 结项复盘 | 项目经理 | 勾选候选、确认去标识、提名黄金样例，成批交出 |
| 系统 · 运行与审计 | 负责人 | 排查与对账用，归拢现有页面：审计、指标看板、入库批次、来源登记、对比评测、质量事件、模型与运行配置 |
| 条目详情 | 所有人 | 内容、出处（可点开原件）、来历（谁起草、谁审核、谁认可、何时复审） |

删除：总览全景、知识运转（流水线、卡住项、来源巡检、抽检信任度）。这些是机器的工作台，卡住超时自动变成“待我处理”的卡。

不做文件夹浏览与管理功能：分类由机器做，找知识靠搜索和健康看板，查原件经条目出处。

### 待我处理的卡片

- 知识专家：公司做法认可、黄金样例认可、冲突裁决（含审核两次不一致、依据变更引起的做法冲突）、公司经验到期复认、抽检卡（每周 5 张）。同类可批量同意；页面显示当日预计用时与每日 25 分钟预算。
- 负责人：泄漏事件（永远置顶）、新增或失效来源、Agent 变更上线、卡住与超时升级、门槛调整建议。

完整的人工触点对照见示意页“人工触点对照”：逻辑图里每一处要人的地方，界面上都必须有落点。

## 三、资料类型

| 类型 | 谁指定 | 发布 |
|---|---|---|
| 法规原文切片、控制项解读、映射关系、方法模板、常见坑、经验数值 | 机器分类 | 过门槛自动发布 + 抽检 |
| 公司做法 | 人勾“这是公司做法”；机器拆出的疑似做法也推候选 | 专家认可 |
| 黄金样例 | 人勾“推荐为黄金样例”并写一句理由；结项复盘按指标推荐候选 | 专家认可 |

黄金样例定义：已签署、客户验收、可作为某产品 × 行业某章节写作范本的交付件或章节。门槛：签署终版、结构完整、去标识后可读、不与已有样例重复。同一产品 × 行业同一章节保留 1～3 份，更好的替换旧的，旧的降为普通参考。

## 四、后台主线（8 步）

触发（规划变更与立项预检、定时保鲜、使用信号、人交来的）→ 1 缺口池 → 2 获取（白名单内自动出采集包；白名单外生成“新增来源”卡）→ 3 入口闸（读取、机密级检测、去标识）→ 4 知识编写 Agent 分类、拆条目 → 5 去重与冲突比对 → 6 知识审核 Agent 换模型独立审 → 7 按类型分流发布 → 8 待我处理。发布后建索引，供顾问对话、交付链写稿使用，使用埋点回到缺口池。

知识侧 Agent 只有两个：知识编写、知识审核；初筛、仲裁是步骤，不是 Agent；采集机不调模型。

## 五、闭环（12 个）

1. 缺口：缺口 → 获取 → 发布 → 就绪度重算 → 关闭。3 次获取失败标“暂无可用来源”并在健康格注明，每月自动再试。
2. 质量：抽检错误率按类型自动调整抽检比例，门槛变更只出建议给负责人；顾问报“有误” → 条目暂停引用 → 复审 → 修正或下线 → 回执给反馈人。
3. 保鲜：到期或法规变更 → 写变更影响 → 审核 → 公开类自动更新；公司经验到期，期间被引用 ≥ 5 次且无负面反馈的自动续期并通知专家，否则推复认卡。条目更新或下线时提示未签署交付件“引用已变”。
4. 公司经验：交付期间静默记录 → 结项复盘候选 → 项目经理勾选并确认去标识 → 专家认可 → 下个项目写稿取用 → 引用次数作为续期依据。
5. 投料回执：每批告知入库数、退回数及原因、处理中数；入库后显示被引用次数。
6. 卡住：超时或连续失败 → 自动重试 → 仍失败推负责人卡；同一原因合并成一张。
7. 人不响应：卡片 3 个工作日未处理提醒，7 天升级负责人；未认可的条目只是不发布，不阻塞其他条目和交付。
8. 客户删除：见第六节。
9. 泄漏应急：已发布条目发现残留客户信息 → 立即下线 → 同批、同来源全部复查 → 检测规则补强并回归 → 记质量事件台账 → 负责人卡。
10. 依赖级联：条目记录依赖（解读、映射、做法 → 依据原文）；依据一变，依赖条目自动进复审，公司做法与新依据冲突的推专家。
11. Agent 自身变更：换模型、改提示词、改规则先跑回归评测，不低于原分数才可切换，切换由负责人确认；运行中按周比对审核通过率与抽检错误率，漂移告警并回退。`agents/*.md` 修改仍按现行规则须负责人同意。
12. 价值与淘汰：12 个月零引用降权归档（不删）；常被驳回进复审。

其他约束：交付件签署时固定所引条目版本（签署快照）；复盘来的条目泛化防再识别（规模用区间、地区只到大区、不写独特事件）；后台模型日用量设上限，超限排队，不影响顾问对话和写稿；停用产品后相关缺口关闭、条目保留不再主动补齐；来源失效自动找替代，找不到推负责人；提醒只在平台内（侧栏角标、首页待办），不接外部通知服务。

## 六、客户删除与经验积累

依据 `docs/客户数据告知模板与合同条款.md` 第 X.3 条（项目资料保留与删除）与第 X.4 条（去标识经验积累）：

| 情形 | 方法、做法、经验数值、常见坑 | 黄金样例 |
|---|---|---|
| 正常删除（保留期满或客户要求提前删除项目资料） | 保留；删除时自动做再识别复查，不通过的下线 | 一并下线 |
| 合同勾选“不参与经验积累” | 结项复盘入口关闭，不进入 | 不进入 |
| 客户事后书面撤回经验积累同意 | 全部下线 | 全部下线 |
| 严格档 | 复盘候选只按摘要卡生成，规则同上 | 同上 |

实现：条目记录来源项目；删除流程增加“知识侧追溯”一步，列出该项目来的条目及处理方式，随删除记录由负责人确认。法务 12-10 答复后，如对交付成果归属或撤回同意有不同意见，只调整黄金样例与撤回两行。

## 七、公司内部资料接入（B37）

- 现在只收集整理，不导入平台：测试期只用虚拟数据，内部来源开放待法务答复。
- 收集建议按产品分子文件夹（另加“通用”），每个产品下分方法论、模板、交付件范例、经验总结；只放终版。
- 开放后经投料箱批量上传导入，走同一入口闸；大批量按目标格分批推专家卡。以后如公司资料有固定共享目录，再定是否只读同步；API 对接属引入外部服务，须负责人另行拍板。

## 八、落地

本 PR 只含方案、决策记录与示意稿。实现拆成工作项，先在 `docs/工作项编号.md` 登记再排期；与现有工作项的关系：B23 专家工作台二批（待我处理合并）、A17 知识使用可见与顾问反馈（报“有误”与回执）、F3 质量事件台账（泄漏应急）、F5 自动化账本与自适应抽检（抽检比例）、B37 公司内部来源（批量导入）、删除约定（知识侧追溯）。“交付期间静默记录”依赖生产 `JUDGMENT_CAPTURE` 开关，开放前结项复盘只用项目经理手工勾选。`docs/总体规划.md` 3.7 节与 F4 的经验入口口径按本方案刷新，另提 PR。
