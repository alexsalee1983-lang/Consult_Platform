# 权威映射导入说明（三期 C12，草稿）

本文只定 NIST OLIR、MITRE CTID 两类权威映射进平台的**导入格式与规则**。原件下载、清单和转换后的内容都放私有资料仓 `Consult_Knowledge`（`mappings/olir/`、`mappings/ctid/`），不进代码仓；代码仓只留本说明和测试用的虚拟样例。导入器（C12-P，线 1）按本文实现，字段名以 B19 `kb_control_mappings`（#288，知识区 k0013）现状为准，#288、B15（#240 #246 #247）合并后再对齐。

映射与挂载只用于差距分析时定位依据，不代表测评、密评或认证的判定。

## 一、统一的目标格式

两类原件都先在资料仓里转换成 B19 映射格式（与 `knowledge/controls/mappings_v0.yaml`，#245 同格式），再经 `app/kb/controls.import_catalog()` 入库，走知识审核流程：

```yaml
catalog_version: v0
source: OLIR | CTID          # 新增：来源，入库后作为映射的置信度依据
source_ref: 原件名 + 版本 + 下载日期 + sha256
frameworks:
  CSF: {name: NIST Cybersecurity Framework, version: "2.0"}
mappings:
  SOC.ORG.01:
  - {fw: CSF, clause: GV.RR-02, rel: 交集, strength: 7, why: 一句话理由, confidence: 高, via: [OLIR]}
```

- `rel` 只用 **等价 / 子集 / 超集 / 交集**（NIST IR 8477、SCF STRM；与 `app/kb/controls.RELATIONS` 同一套），方向为“控制项相对条款”。
- `strength` 1～10 整数；`why` 一句话，不复述标准原文，出现结论性用语拒收。
- 新增两个字段（C12-P 加列，迁移编号按三期计划第七节预分配表另报）：`confidence`（高 / 中 / 低）、`via`（交叉验证路径列表：`OLIR`、`CTID`、`间接:<控制项或条款>`、`逐句比对`）。

## 二、NIST OLIR

- 原件：NIST OLIR 目录中的已发布映射（关系型映射，按 IR 8477 / IR 8278A 的关系取值）。
- 关系取值转换：`equal`→等价，`subset of`→子集，`superset of`→超集，`intersects with`→交集；`not related to` / `no relationship` 不导入。原件方向是“焦点文档相对参考文档”时，按需要翻转（子集 ↔ 超集）。
- 强度：原件带 1～10 强度的照抄；没有的按关系给缺省值（等价 9、子集 / 超集 7、交集 5），标“缺省强度”待专家复核。
- OLIR 只给“条款 ↔ 条款”，挂到公司控制项要经已有映射间接推得（条款甲 → 控制项）；间接推得的行 `via` 写 `[OLIR, 间接:<条款>]`，置信度按第四节判。
- 原件字段名以下载的原件为准，转换脚本放资料仓，转换时核对。

## 三、MITRE CTID

- 原件：CTID Mappings Explorer 的已发布映射（ATT&CK 技术 ↔ 安全控制，如 NIST SP 800-53、云平台安全能力）。
- CTID 是“威胁 ↔ 控制”，不是“条款 ↔ 条款”，不直接产生等价 / 子集类关系：导入时登记框架 `ATTACK`（版本照原件），行的 `rel` 一律写交集；原件带评分的按评分定强度（minimal 3、partial 6、significant 9），没有评分的写 5。
- 用途：一是给控制项挂“可应对的 ATT&CK 技术”，供 SOC 检测覆盖类差距分析定位；二是作交叉验证路径（两个控制项经同一组 800-53 控制、同一组技术相连）。
- 原件字段名以下载的原件为准，转换时核对。

## 四、置信度与交叉验证

| 置信度 | 条件 |
|---|---|
| 高 | 有 OLIR / CTID 权威映射直接佐证这一对 |
| 中 | 无直接权威映射，但两条以上独立路径（间接映射、逐句比对）推得的关系类型一致 |
| 低 | 只有一条推理路径 |

两条路径的关系类型不一致时，这一行标“冲突”交专家，不导入为已发布映射。低置信度的行只进草稿，抽检比例按 B22 定。

## 五、与二期 `kb_mappings` 的关系

二期 MAP 条目解析表 `kb_mappings` 的关系取值“等同 / 部分覆盖 / 相关”按以下建议转换后并入控制项中枢（是否合并、何时合并在 C12-P 定）：等同→等价；部分覆盖→子集或超集（按方向人工确认，拿不准写交集）；相关→交集（强度不高于 5）。转换结果一律置信度“低”，待交叉验证后升级。
