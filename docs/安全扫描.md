# 安全扫描

CI 的 `security` 任务在每次推送、每个 PR 和每周一 09:00（北京时间）运行，发现问题即失败，不能合并。

| 扫描 | 工具 | 范围 | 失败条件 |
|---|---|---|---|
| Python 依赖漏洞 | pip-audit 2.7.3 | `backend/requirements-dev.txt`（含 `requirements.txt` 及其传递依赖） | 任何已知漏洞 |
| 前端依赖漏洞 | npm audit | `frontend/package-lock.json` | 任何已知漏洞 |
| 密钥泄露 | gitleaks 8.30.1（官方发布包，校验 SHA-256） | 全部提交历史 | 任何疑似密钥 |

镜像漏洞扫描按开发计划在 S5 加入。

## 本地运行

```bash
# backend 目录，虚拟环境中
pip install pip-audit==2.7.3 && pip-audit -r requirements-dev.txt
# frontend 目录
npm audit
# 仓库根目录（需先安装 gitleaks）
gitleaks git --redact --verbose .
```

## 扫描失败怎么办

**依赖漏洞**：升级到修复版本，在 PR 里写明漏洞编号和升级前后的版本。升级会引入新的传递依赖时，先确认它不联网调用外部服务（数据保护红线第 2 条）。确实无法升级时问负责人，不要自行加忽略。

**疑似密钥**：

1. 真密钥：立即通知负责人，**先作废这把密钥**，再从代码中删除。提交历史里的密钥删不干净，只能作废。
2. 误报（如机密级检测规则的测试样例）：把 gitleaks 输出的 `Fingerprint` 加进仓库根目录的 `.gitleaksignore`，写一行注释说明为什么是误报。只按指纹忽略单处，不按目录或规则整体放行。

测试样例尽量用明显虚构、不像真实格式的值，避免触发误报。
