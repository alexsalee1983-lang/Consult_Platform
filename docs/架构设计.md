# 安全咨询 Agent 平台架构设计

Nov 7, 2026 · @YufenXu

## 一、设计前提与原则

**客户数据按项目分两档管理。** 标准档（大多数项目）：顾问在客户办公区用公司笔记本，经 VPN 实时使用知识库和 Agent，直接基于访谈纪要和客户提供的资料起草交付物。严格档（少数高敏项目）：客户资料不出场，平台只用于场外准备。客户给我们什么由客户决定；给了的，我们按合同保护好。

**前提**

- **建设方式**：全部自建；研发线性开发，公司支持内部部署。
- **规模**：同时在线 10 人，2 台服务器，不采购 GPU。
- **模型**：使用公司私有化部署的白名单大模型，统一经模型网关调用；客户资料不出公司、不用于训练；客户现场不运行任何大模型。
- **现场联网**：标准档用客户的访客网络或手机热点，再走公司 VPN；永远不接客户的生产网络。严格档按客户规定。
- **集成**：一期只对接公司 SSO。

**七条原则**

1. **客户决定给什么**：咨询信息来自访谈和客户主动提供的资料；客户不给的不取，客户要求删除的照办。
2. **按项目定档**：立项时定标准档或严格档；标准档项目里的单个文档也可以临时升级为严格。
3. **机密级两档都不收**：账号口令、密钥、可利用的漏洞细节、完整网络拓扑和 IP 规划、客户的业务数据和个人信息样本。
4. **便利与保护并存**：标准档里，机密级拦截、项目隔离、审计都由平台完成；模型在公司内部，顾问看到的始终是真名。
5. **项目与知识分离**：项目内容不会自动进入知识库，只能经回流审核入库。
6. **删除有期限、有确认**：项目区验收后保留 6 个月，到期经人工确认后删除，并留删除记录。
7. **小而够用**：2 台服务器、无 GPU；日志、隔离、账户管理参照《会计师事务所数据安全管理暂行办法》建设。

## 二、业务架构

业务架构分四层，沿“售前到沉淀”的价值流组织。交付服务和知识服务都运行在公司平台上：标准档项目里，顾问在客户办公区经 VPN 直接使用平台；严格档项目里，平台只在场外使用。交付从知识库取知识，结项后去标识的经验经审核再回流到知识库。

【图示（见 claude.ai 原文档）： 业务架构 · 价值流 + 四层】

**角色与权限**

| 角色 | 主要入口 | 核心权限 |
| --- | --- | --- |
| 交付顾问 | 顾问工作台 | 自己参与的项目可读写；知识库只读；可以投料和反馈 |
| 项目经理 | 顾问工作台、管理看板 | 创建项目、管理成员、确认阶段 |
| 专家 | 知识运营台 | 审批本领域条目；参与萃取对话 |
| 知识库专人 | 知识运营台 | 管理全部条目和流水线；维护评测集 |
| 项目负责人 | 管理看板 | 查看统计；审批 Agent 版本发布 |
| 管理员 | 后台 | 用户、权限、Agent 配置、审计日志 |
| 售前（P2） | 售前入口 | 只读“售前可见”的条目 |

## 三、客户数据保护

**出发点：咨询信息来自访谈和客户主动提供的资料，客户不能给的，我们本来就拿不到。** 我们的责任是把客户给了的保护好，并在敏感度不同的项目上用不同的做法：大多数项目要便利，少数高敏项目要严格。

**两档项目**

|  | 标准档（大多数项目） | 严格档（少数项目） |
| --- | --- | --- |
| 现场办公 | 公司笔记本在客户办公区，经访客网络或手机热点连公司 VPN，实时使用知识库和 Agent | 按客户规定，可能使用客户终端；平台只在场外使用 |
| 能上传什么 | 顾问整理的访谈纪要、客户提供的资料（机密级和标为严格的文档除外） | 默认什么都不上传；客户书面同意后，可上传去标识摘要卡 |
| Agent 怎么用 | 直接基于纪要和资料整理事实清单、做差距分析、起草报告，交付物里直接是真名 | 场外准备和通用问答；摘要卡模式下用占位符起草，回现场回填 |
| 告知客户 | 合同附一页《AI 辅助与数据处理说明》 | 完整的《数据处理计划》，客户签字 |

**定档规则**

- 立项时，由项目经理在项目卡里选择档位。满足任一条件即为严格档：国有大行；涉及电力生产控制区；政府涉密或敏感单位；客户明确要求资料不出场；合同有相应约定。拿不准的，问客户。
- 客户可以随时要求升档。
- **按文档临时升级**：标准档项目里，顾问或客户可以把个别文档（例如渗透测试报告）标为“严格”。这类文档只留在笔记本上，不上传，平台上只显示“仅本地”。

**资料分级**

| 级别 | 典型内容 | 标准档 | 严格档 |
| --- | --- | --- | --- |
| 机密 | 账号口令、密钥、可利用的漏洞细节、完整网络拓扑和 IP 规划、客户的业务数据和个人信息样本 | 不收；上传时自动识别并拦截，顾问只记“存在什么问题” | 不收 |
| 敏感 | 客户制度、组织架构、系统清单、访谈纪要、现状问题 | 上传到项目区，按项目隔离 | 留在现场；同意后只传去标识摘要卡 |
| 一般 | 客户提供的一般资料、行业信息、公开信息 | 直接使用 | 直接使用 |

**标准档的自动保护**（顾问几乎感觉不到额外负担）

1. **上传识别与拦截**：平台识别口令、密钥、IP 段、漏洞细节等机密级内容，命中即拦截，提示顾问改写成问题描述。
2. **模型在公司内部**：白名单大模型由公司私有化部署，客户资料不出公司、不用于训练。网关保留自动假名化能力，默认关闭；以后如果接入云端模型，标准档必须开启。
3. **项目隔离**：只有项目成员能看；竞争客户的项目组之间设信息隔离墙。
4. **个人信息最小化**：访谈纪要只记角色，不记姓名。
5. **水印与留痕**：导出文件加水印，上传、读取、导出全程留痕。

**严格档的做法**

- 默认零传输：离场后只能问不含客户事实的通用问题。
- 客户书面同意时，可在现场用现场工具填写去标识摘要卡，经规则检查和顾问确认，离场后经公司网络上传。Agent 用占位符起草，草稿带回现场，按本地对照表回填真名。
- 国内大行参照四大的通常做法：驻场在行内完成，资料只进不出；进场前用平台准备资料包，申请带入行内；质量复核在行内进行。

**保留与删除**

- 项目区在验收后保留 6 个月，用于后续答疑和处理争议。
- 到期时，平台提醒项目经理；**经人工确认后**才删除，删除范围包括文件和检索索引，并留删除记录。客户要求提前删除的，按合同执行，同样需要人工确认。
- 最终交付物按公司档案制度归档。笔记本上的项目资料与项目区同步清理。

**经验回流**：回流的是做法，不是数据。只回流通用做法、判断规则、异议类型与应答思路、踩坑教训四类；用固定模板填写，经顾问和项目经理双人确认，再经脱敏审查和专家审批入库。合同不允许的项目关闭回流。

**同行通行做法与本平台的对照**

| 环节 | 通行做法 | 本平台的落点 |
| --- | --- | --- |
| 知情同意 | 告知用了哪些 AI、数据存哪、是否训练、风险和人工复核，取得明确同意；笼统模板条款不够 | 标准档附《AI 辅助与数据处理说明》；严格档签数据处理计划 |
| 按客户分级 | 大多数项目的工作底稿存放在机构自己的受控系统中；少数高敏客户在客户环境内完成 | 标准档与严格档 |
| 最小化 | 只取完成工作所需的资料；机密信息不收 | 机密级拦截；个人信息只记角色 |
| AI 白名单 | 只用公司批准、合同保证不留存不训练的 AI；客户信息不进公共 AI | 只经模型网关调用公司私有化部署的白名单模型，资料不出公司 |
| 人工复核 | AI 输出须经顾问审核署名 | 质量评审 Agent + 顾问署名 |
| 信息隔离墙 | 竞争客户的项目组之间隔离，按需知悉 | 项目区按成员授权 |
| 知识消毒 | 知识库只收去标识的方法与经验；可识别案例对外使用需客户同意 | 回流单 + 双人确认 + 专家审批 |
| 保留与销毁 | 按合同期限保留，到期销毁并留证明 | 6 个月保留，人工确认删除，留记录 |

## 四、数据架构

数据分在两处：公司服务器（项目区、知识区）和客户现场。标准档的项目资料在项目区；严格档的资料留在现场。项目区和知识区严格分开。

【图示（见 claude.ai 原文档）： 数据流向 · 标准档与严格档】

1. **① 标准档**：顾问在客户办公区经 VPN 把访谈纪要和客户提供的资料录入项目区，Agent 实时整理和起草，草稿直接是真名。
2. **② 严格档**：资料不出场；客户书面同意时，离场后只上传去标识摘要卡，草稿用占位符，回现场回填。
3. **③ 模型调用**：一律经模型网关，拦截机密级后发给公司私有化部署的白名单大模型，资料不出公司。
4. **④ 经验回流**：项目内容不会自动进入知识库，只能经回流单和审核入库。

**核心实体与存放位置**

| 实体 | 关键字段 | 标准档 | 严格档 |
| --- | --- | --- | --- |
| 项目卡 | 客户代号、行业、规模区间、数据档位、阶段 | 项目区 | 项目区 |
| 访谈纪要 | 角色（不记姓名）、要点、证据编号 | 项目区 | 现场 |
| 客户提供资料 | 文件、来源、密级标记 | 项目区（机密级和标为严格的除外） | 现场 |
| 标为严格的文档 | — | 笔记本本地 | 现场 |
| 摘要卡 | 评估项、现状、数量级、证据编号 | 不需要 | 项目区（仅客户同意时） |
| 事实清单、发现、确认卡 | 证据编号、依据、风险、建议、来源类型 | 项目区 | 项目区（基于摘要卡） |
| 交付物草稿 | 类型、版本、引用的知识版本 | 项目区（真名） | 项目区（占位符） |
| 假名化对照 | 占位符与真名 | 默认不生成；仅在开启自动假名化时，由网关按项目加密保存，用于还原 | 现场，不上传 |
| 删除记录 | 项目、范围、确认人、时间 | 服务器长期保存 | 服务器长期保存 |
| 知识条目、依据、映射、审批记录 | 层级、适用条件、来源类型、版本 | 知识区 | 知识区 |
| 审计日志 | 用户、操作、Agent、模型版本、引用条目 | 服务器 | 服务器 |

**检索设计**

- **混合检索**：关键词（条款号、标准号、专有名词）+ 语义向量 + 元数据过滤（层级、服务产品、适用条件），再重排序。
- **两区隔离**：项目区内容不进入知识库索引；每个项目的检索只在本项目范围内进行，由平台强制过滤。
- **依据走精确通道**：按“文件 + 条款号”直接查依据条款表。
- **引用快照**：交付物记录引用的条目 ID 和版本，事后可复现当时的依据。

**生命周期**

- **知识**：投料 → 加工 → 脱敏 → 冲突检测 → 审批 → 发布 → 复审（依据 6 个月，其他 12 个月）→ 替代或下线，保留历史版本。
- **项目**：立项定档 → 告知或签字 → 访谈与资料收集 → 标准档实时录入和起草（严格档按摘要卡流程）→ 验收 → 经验回流 → 保留 6 个月 → 人工确认删除 → 留删除记录。

## 五、工具与技术架构

所有 AI 能力都在公司服务器上。标准档顾问在客户办公区用浏览器经 VPN 访问平台；严格档项目在现场使用一个不联网、不跑模型的轻量工具。Agent 不直接碰数据库和模型：读写数据只能通过工具层，调用模型只能通过模型网关。

**服务器组件**

| 组件 | 推荐选型 | 说明 |
| --- | --- | --- |
| 前端 | React | 顾问工作台和知识运营台，同一应用的两种模式；只在公司网络和 VPN 内可访问 |
| 后端 | Python（FastAPI） | Agent、文档解析、检索的开源生态以 Python 为主 |
| 认证 | 公司 SSO + 第二因素 | 角色、项目成员、数据档位由平台维护 |
| 编排引擎 | 平台自写流程控制（2026-11-10 决策，原定 LangGraph） | 交付链：数据库记运行状态、后台任务推进，发确认卡时暂停、顾问处理后继续 |
| 模型网关 | 自研轻量网关（可基于 LiteLLM） | 只连公司私有化部署的白名单大模型；拦截机密级；按能力等级路由；记录模型版本和用量；保留自动假名化能力（默认关闭） |
| 上传检查 | 规则词典 + 中文实体识别 | 识别口令、密钥、IP 段、漏洞细节等机密级内容，命中即拦截 |
| 数据库 | PostgreSQL + pgvector + 中文全文检索扩展（如 zhparser） | 知识区与项目区分库，项目区再按项目做行级权限 |
| 对象存储 | MinIO | 原料、客户提供资料、交付物；项目区按项目分桶并加密 |
| 删除管理 | 自研 | 到期提醒、人工确认、按项目删除文件和索引、生成删除记录 |
| 队列与缓存 | Redis | 异步任务 |
| 版本库 | 公司内部 Git | Agent md、公共规范、模板 |
| 文档解析 / OCR / 向量化 | 开源模型，CPU 运行 | 公开知识、公司资料和标准档项目资料 |
| 文档生成 | 基于公司模板生成 Word / PPT | 标准档直接是真名；严格档带占位符 |
| 资料包导出 | 自研 | 模板、提纲、依据清单导出为 Word / PDF，供严格档带入现场 |
| 链路追踪与监控 | Langfuse、Prometheus + Grafana | 每次 Agent 运行可追溯 |
| 开发安全 | CI 中做代码、依赖和镜像扫描 | 管住开源组件的供应链风险 |

**严格档现场工具**（公司笔记本上的轻量桌面应用，不联网、不跑模型；标准档不需要）

| 功能 | 说明 |
| --- | --- |
| 摘要卡填写 | 按评估框架逐项填写；空白模板离场前从服务器下载 |
| 规则检查 | 客户名词典、人名、IP、域名、系统名、金额、日期等；命中则不允许导出 |
| 占位符回填 | 草稿下载后按本地对照表替换真名，生成正式交付物 |
| 加密存储 | 现场资料、对照表、标为严格的文档放在加密容器 |

**模型路由**

| 等级 | 用于 | 模型 |
| --- | --- | --- |
| 推理 | 依据与差距分析、方案设计、质量评审 | 白名单中推理能力最强的模型 |
| 标准 | 制度起草、报告与汇报、调研访谈、咨询师、项目交付管理 | 白名单中的通用旗舰模型 |
| 轻量 | 分类、摘要、元数据补全、检索问题生成 | 白名单中的轻量模型 |

- 客户现场不运行任何模型。
- 白名单模型为公司私有化部署，客户资料不出公司。以后如果接入云端模型，标准档必须开启自动假名化，并在《AI 辅助与数据处理说明》中写明服务名称和“不留存、不训练”条款。
- 每次调用记录模型版本；模型升级前先跑评测集。

**Agent 按档位工作**

- **标准档**：所有交付侧 Agent 直接读取项目区的纪要和资料；调研访谈 Agent 恢复“访谈纪要整理”，把顾问的笔记整理成带证据编号的事实清单。
- **严格档**：调研访谈 Agent 生成访谈提纲和空白摘要卡模板；其他交付侧 Agent 只读摘要卡，输出用占位符。
- **质量评审 Agent**：两档都检查输出中有没有机密级内容；严格档另查有没有真名和超出摘要卡的客户事实。

## 六、部署架构

2 台服务器，不采购 GPU；顾问工作台和知识运营台只在公司网络和 VPN 内可访问。标准档顾问在客户办公区经访客网络或手机热点连公司 VPN 实时使用平台；严格档在现场使用不联网的轻量工具，离场后同步。

| 数据服务器 | PostgreSQL（知识区、项目区分库）、MinIO、Redis | 8 核 / 32 GB 内存 / 1 TB SSD（加密），另配备份存储 |

**现场笔记本**：普通办公配置，不需要独立显卡；公司统一镜像，预装 VPN 客户端和严格档现场工具；安全基线见第七节；数量按同时在客户现场的顾问人数配置，另备 1～2 台周转。

- **备份**：每日全量备份，异地或离线副本；RPO 24 小时、RTO 4 小时，每季度演练一次。备份保留期不超过合同约定的最短保留期，项目区销毁时记录相关备份的过期日期。
- **环境隔离**：开发、测试、生产分开；测试只用虚拟客户数据。
- **扩容**：知识条目超过数万条时引入 OpenSearch；用户明显增加时再做应用层双机。

## 七、安全与合规架构

**服务器按等保第三级定级和建设（按最佳实践确定）。** 标准档项目会把可识别的客户资料（制度、组织架构、系统清单、访谈纪要、现状问题）存进项目区，服务器的保护要求要和这些资料的敏感度匹配。

**定级理由**

1. 项目区集中存放多家客户的安全现状和问题，其中可能包括城商行、股份行等关键行业客户；一旦泄露，影响的不只是客户权益，还可能波及社会秩序和公共利益，对应第三级。
2. 客户在供应商安全审查中，通常要求处理其资料的系统具备对等的保护水平。
3. 参照会计师事务所和金融行业外包服务的通行做法，集中存放多家客户资料的平台按第三级建设，客户做供应商安全审查时也更容易通过。

**程序**：公司自主定级 → 专家评审 → 向公安机关备案 → 由有资质的测评机构测评，三级系统每年至少测评一次。公司没有测评资质，不能自测。最终级别由公司安全部门确定。

**密码**：《商用密码管理条例》第四十一条要求网络运营者按等保制度要求使用商用密码，具体要求由密码管理部门按保护等级确定。三级系统一般需要做密码应用设计并开展密评，以安全部门和当地密码管理部门的意见为准。

**服务器主要控制项**（同时对标《会计师事务所数据安全管理暂行办法》中访问日志、分级隔离、账户管理的要求）

| 领域 | 做法 |
| --- | --- |
| 身份与访问 | SSO + 第二因素；RBAC；系统、安全、审计三类管理员分离；管理员看不到项目资料内容 |
| 远程接入 | 只允许公司 VPN 接入，VPN 需第二因素；按设备证书限定只有公司笔记本能连 |
| 项目隔离 | 项目区按成员授权；竞争客户的项目组之间设信息隔离墙；知识侧 Agent 读不到项目区 |
| 上传与出网检查 | 上传时拦截机密级；模型私有化部署，资料不出公司 |
| 数据保护 | 数据库和对象存储加密；导出文件加水印；严格档文档不上传 |
| 保留与删除 | 验收后保留 6 个月；到期提醒，人工确认后删除文件和索引，留删除记录 |
| 安全审计 | 上传、读取、Agent 调用、导出、删除全程留痕；日志至少保留 1 年，防篡改 |
| 运维 | 所有运维经堡垒机；不设不受监控的超级账户；管理员账号不交第三方 |
| 开发安全 | 代码、依赖和镜像扫描进 CI；上线前做渗透测试 |
| Agent 安全 | 资料内容一律作为数据传入，不作为指令；工具按 Agent 白名单授权；对照 OWASP 大模型应用十大风险做设计评审 |

**现场笔记本安全基线**

| 领域 | 基线 |
| --- | --- |
| 设备 | 公司配发、专人专用、资产登记；统一镜像 |
| 加密 | 全盘加密；严格档资料和标为严格的文档放在单独的加密容器 |
| 网络 | 只连客户的访客网络或手机热点，再走公司 VPN；永远不接客户生产网络 |
| 外设与外传 | USB 存储默认禁用，按客户要求开放指定介质；禁用个人网盘和即时通讯传输客户资料 |
| 应用 | 只装公司批准的软件 |
| 显示 | 屏幕水印（顾问、项目代号、时间）；离开自动锁屏 |
| 丢失 | 建议 2 小时内上报；吊销设备证书；按合同通知客户 |
| 结项 | 本地项目资料与项目区同步清理，人工确认后删除 |

**模型服务**：白名单大模型为公司私有化部署。《AI 辅助与数据处理说明》《数据处理计划》向客户写明“部署在公司内部、资料不出公司、不用于训练”。

## 九、复审补充与研发里程碑

对照业界做法复审后的关键补充如下，第 1～5 条是数据保护方案的核心。

| # | 方面 | 做法 |
| --- | --- | --- |
| 1 | 按项目定档 | 标准档便利，严格档严格；单个文档可临时升级 |
| 2 | 客户同意 | 标准档附《AI 辅助与数据处理说明》；严格档签《数据处理计划》 |
| 3 | 机密级不收 | 上传识别拦截；顾问只记问题，不记细节 |
| 4 | 模型私有化 | 资料不出公司、不用于训练；网关保留假名化能力，默认关闭 |
| 5 | 保留与删除 | 验收后 6 个月，人工确认删除，留记录 |
| 6 | 合同与知识产权 | 存量项目材料入库前核对知识产权约定 |
| 7 | 个人信息 | 访谈只记角色，不记姓名 |
| 8 | 信息隔离墙 | 竞争客户的项目组之间隔离 |
| 9 | 现场联网 | 访客网络或热点 + VPN，永不接客户生产网络 |
| 10 | 模型稳定性 | 记录模型版本；升级前跑评测集 |
| 11 | 结论可复现 | 交付物记录引用条目和版本 |
| 12 | Agent 安全 | 对照 OWASP 大模型应用十大风险做设计评审 |
| 13 | 可观测性 | Langfuse 记录每次 Agent 运行 |
| 14 | 开发安全 | 代码、依赖、镜像扫描；上线前渗透测试 |
| 15 | 环境隔离 | 测试只用虚拟客户数据 |
| 16 | 生成式 AI 合规 | 平台只对内使用，按《生成式人工智能服务管理暂行办法》第二条，企业应用生成式 AI 但不向境内公众提供服务的，不适用该办法 |

**研发里程碑（线性开发顺序）**

先做底座和知识服务，再做标准档交付链（覆盖大多数项目），严格档的现场工具放在最后。

| 里程碑 | 内容 | 验收标准 |
| --- | --- | --- |
| M1 平台底座 | SSO 与第二因素、VPN 接入（设备证书 + 双因素）、RBAC、三权分立；知识区与项目区隔离；审计日志；模型网关（拦截、路由、用量） | 机密级上传被拦截；模型调用不出公司网络；审计日志可查 |
| M2 知识服务 | 投料到发布全流程；知识库建设与脱敏审查 Agent；知识运营台；资料包导出 | 业界知识约 300 条入库；依据查询评测准确率 ≥ 90% |
| M3 标准档交付链 | 项目区与数据档位；纪要录入与资料上传；交付侧 Agent；确认卡；顾问工作台；文档生成 | 用虚拟客户在一天内从纪要生成 D4 现状评估初稿 |
| M4 删除与严格档 | 删除管理（到期提醒、人工确认、删除记录）；严格档摘要卡、规则检查、占位符回填 | 删除抽检通过；严格档“填卡 → 上传 → 起草 → 回填”闭环跑通 |
| M5 安全加固与上线 | 三级控制项落地；渗透测试；等保定级备案与测评；客户告知模板定稿 | 测评通过 |
