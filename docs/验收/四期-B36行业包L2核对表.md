# 四期 B36 · 四格行业包 L2 达标核对表与缺口清单

开发线 2，#507，2026-11-27。四格 = SOC、IRE × 银行、电力。L2 口径取 `docs/4A架构设计.md` §2.4：**判断规则与黄金样例**（L1 依据、题、术语见 `docs/验收/三期-B14行业包L1核对表.md`，已达标）。
数据来源：资料仓 Consult_Knowledge `drafts/ind/`（本单新增 8 份）；代码仓 `industries/*.yaml`、`knowledge/eval/agents/industry.yaml`。全部为公开方法版 v0，判断规则与黄金样例是“公司做法 / 黄金样例”知识类型，**必须由作者以外的知识专家确认才进检索**（B35 守卫），所以 L2 在专家确认前只能算“草稿就绪”。

## 一、L2 核对项

| # | 核对项 | 达标线 | 校验方式 |
|---|---|---|---|
| 1 | 判断规则 | 每格 ≥1 份条目、≥6 条“当……时，……，因为……”规则，覆盖影响判断、方案取舍、措辞边界 | 资料仓条目 `ind-*-mtd-*-judgment-rules` |
| 2 | 黄金样例 | 每格 ≥1 份 GLD 条目，虚拟客户，带证据编号、只用“符合性初判”，附“好在哪” | 资料仓条目 `ind-*-gld-*`；`parse_entry` 解析通过 |
| 3 | 评测题 | 每格 ≥1 道 golden 题，每个行业 ≥1 道红线题、≥1 道埋雷题，评测门通过 | `python -m app.cli agent-eval-lint ../knowledge/eval/agents` |
| 4 | 行业包引用 | 行业包 `instructions.gap` 指到判断规则条目 | `industries/*.yaml` |
| 5 | 章节槽位 | 条目挂 D4 差距章节槽位，就绪度能计入 | SOC 有槽位 `SOC.D4.ch2`；IRE 无槽位配置 |
| 6 | 专家确认 | 判断规则、黄金样例经行业负责专家确认并发布，行业包 `level` 改 L2 | 专家 12-08 到位后（E14） |
| 7 | 评测实跑 | 四格 golden 与埋雷题实跑通过（每题 3 轮） | 测试机攒批 agent-eval（统筹派） |

## 二、四格结果

| 核对项 | SOC × 银行 | IRE × 银行 | SOC × 电力 | IRE × 电力 |
|---|---|---|---|---|
| 1 判断规则 | 9 条 ✓ `ind-bank-mtd-soc-judgment-rules` | 8 条 ✓ `ind-bank-mtd-ire-judgment-rules` | 8 条 ✓ `ind-power-mtd-soc-judgment-rules` | 8 条 ✓ `ind-power-mtd-ire-judgment-rules` |
| 2 黄金样例 | ✓ `ind-bank-gld-soc-d4-regulatory`（监管要求对照） | ✓ `ind-bank-gld-ire-d4-reporting`（事件报告机制） | ✓ `ind-power-gld-soc-d4-zoning`（安全分区现状） | ✓ `ind-power-gld-ire-d4-linkage`（预案联动） |
| 3 评测题 | IND-BANK-SOC-G01、IND-BANK-R01、IND-BANK-M01 ✓ | IND-BANK-IRE-G01 ✓ | IND-POWER-SOC-G01、IND-POWER-R01 ✓ | IND-POWER-IRE-G01、IND-POWER-M01 ✓ |
| 4 行业包引用 | ✓ | ✓ | ✓ | ✓ |
| 5 槽位 | ✓ SOC.D4.ch2 | ✗ 缺口 G-3 | ✓ SOC.D4.ch2 | ✗ 缺口 G-3 |
| 6 专家确认 | 待（pending） | 待 | 待 | 待 |

**结论**：四格 1～4 项草稿就绪；第 5 项 IRE 缺槽位；第 6、7 项待专家与测试机。四格行业包 `level` 保持 L1，第 6、7 项通过后改 L2。每格只有 1 份黄金样例，覆盖 D4 差距一章；L2 验收前建议每格再补 D6（制度 / 预案）一份（缺口 G-5）。

## 三、缺口清单（登记进缺口池）

| 编号 | 缺口 | 补法 | 归谁 |
|---|---|---|---|
| G-1 | 银行外包、业务连续性两份监管文件条款号未核（L1 遗留，影响判断规则 IRE×银行第 4 条、黄金样例外包一行） | 采集机抓原文入库后核条款，条目去掉【依据待核实】 | 采集机 + 线2 |
| G-2 | 电力企业向行业主管部门报告网络安全事件的时限与渠道未入库（IRE×电力判断规则第 3 条、黄金样例“依据说明”） | 采集机按公开来源补（国家能源局相关应急预案、报告规定） | 采集机 |
| G-3 | IRE 产品配置没有章节槽位，IRE 两格的判断规则与黄金样例无法计入章节就绪度 | IRE 的 D4 槽位规格 v0（同 SOC #461 写法） | 线2 起草，C10 同口径 |
| G-4 | 条目文件导入（`kb-import`）只收公开资料，也不读 `knowledge_kind`、`slot` 字段；公司做法 / 黄金样例只能在知识页面逐条建 | 本批 8 份由知识管理员在页面建条目并填槽位；是否给文件导入加这两个字段（走专家确认队列）由线1 评估 | 线1 评估 |
| G-5 | 每格黄金样例只覆盖 D4 差距一章，缺 D6（SOC 制度、IRE 预案）样例 | 专家萃取访谈后起草，或从首个真实项目回流 | 专家（萃取）+ 线2 |
| G-6 | 判断规则中的默认值（影响“至少高”、值守三方案、工控监测最低建议）缺行业基准支撑 | 萃取访谈每格 2 次时逐条确认（规则末尾“待专家确认”列了问题） | 专家（E14） |
