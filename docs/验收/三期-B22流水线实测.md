# 三期 B22 · SOC × 银行知识流水线首跑与实测

状态：**v0 测量方案与报告骨架**（开发线 2，#406，2026-11-24）。数字一栏待测试机首跑后回填；本机没有 Docker 与网关模型，未实测。
范围：只用公开资料和虚拟数据（虚拟客户 BANK-A），不涉及任何真实客户材料。

## 一、跑什么

流水线六段：采集 → 提炼 → 挂载 → 审核 → 候选 → 发布（`docs/三期开发计划.md` 第一节第 8 条）。

| 段 | 输入 | 命令（测试机，backend 容器内） |
|---|---|---|
| 采集 | 银行监管公开资料（下发包，采集机白名单） | `python -m app.cli kb-acquire-dispatch …` → 采集机 → `kb-acquire-import …`（批次哈希核对） |
| 提炼 | 依据原文 | `kb-source-split` → `kb-source-publish`（SRC 程序核验，B10） |
| 挂载 | SRC、REF 与控制项检查点 | C12 公开依据预填（挂 `knowledge/controls/v0.yaml` 检查点）、C11 |
| 审核 | 公开资料 REF / MAP / MTD | 程序规则 + `kb-reviewer`（经网关），全部通过自动发布，存疑进人工队列 |
| 候选 | SOC 公司做法、黄金样例（drafts/soc） | `kb-import --submit`；`kb-candidate-promote`（专家确认） |
| 发布 | — | 审核通过；抽检按决策记录 2026-11-15 ③④ |
| 就绪度 | C10 槽位、A24 评测集 | `kb-assembly-eval /srv/knowledge/eval/assembly/soc-d4-d5-v0.yaml --as <用户> --out b22-base.json` |
| 编造条款号 | 发布条目与 D4、D5 草稿 | `kb-ref-check`、`kb-basis-check` |

## 二、指标口径

| 指标 | 口径 | 目标 | 首跑 |
|---|---|---|---|
| 自动发布率 | 自动发布条数 ÷ 进入审核条数（按 SRC、Agent 审核两类分列） | 记基线，校准四期 | 待测 |
| 抽检不通过率 | 抽检不通过 ÷ 抽检数（SRC 随机 5%、Agent 审核随机 20%） | ≤5%（>10% 停该类自动发布） | 待测 |
| 人工分钟 / 百条 | 人工队列 + 抽检 + 专家确认的计时合计 ÷ 发布条数 × 100 | 记基线 | 待测 |
| 专家分钟 / 条（按类型） | 公司做法链路 TPL / MTD / CAS / PIT / POL / OBJ / BMK 分列 | 记基线，校准四期 | 待测 |
| 编造条款号 | 发布条目和 D4、D5 草稿中引用对不上原文的条款号个数 | **必须为 0** | 待测 |
| 就绪度（总体） | A24 评测集应命中知识里已发布、未停用的比例 | ≥70% | 待测 |
| 就绪度（依据类槽位） | SOC-D4-03 与 SRC / REF 类槽位 | ≥95% | 待测 |
| 命中率（baseline） | A24 baseline 策略的应命中被装配比例；A12 须高于它 | 记基线 | 待测 |

计时按人工操作的开始、提交时间差（审核队列、确认卡、抽检记录），只计人，不计等待；报告只含计数与比例，不含条目正文与查询原文。
