# 生产部署手册（M5 ⑧）

适用于一期生产环境：内网单机部署（应用服务器 1 台；备份落到公司备份系统）。测试机部署见 CLAUDE.md“常用命令”。
本手册只写平台怎么装、怎么配；涉及公司网络、终端安全、日志平台的事项写明“部署方负责”，由公司运维按制度执行。

> 平台只做差距分析、符合性初判、整改建议，不出具测评、密评或认证结论；部署配置不改变这一点。

## 一、部署前准备

### 1.1 服务器

| 项 | 要求 |
|---|---|
| 操作系统 | Ubuntu 22.04 / 24.04 LTS（或公司标准 Linux），打齐安全补丁 |
| 配置 | 8 核 / 32 GB 内存 / 500 GB SSD 起（向量、重排模型在 CPU 上运行；压测方案和结论见 `docs/压测方案.md`） |
| 软件 | Docker Engine 24+、Docker Compose 2.24+（生产覆盖文件用到 `!reset`）、git、gpg、curl |
| 磁盘 | 数据目录（Docker 数据卷，默认 `/var/lib/docker`）所在分区做全盘加密（LUKS 等），**部署方负责**（等保自查 8.1.4.8 b） |
| 防病毒 | 安装公司终端安全软件，排除 Docker 数据卷目录的实时扫描以免影响数据库，**部署方负责** |
| 时间 | 开启 NTP 时间同步（审计时间、动态码都依赖准确时间） |

### 1.2 网络与防火墙（部署方负责）

| 方向 | 放行 | 说明 |
|---|---|---|
| 入站 | 443/TCP（`WEB_TLS_PORT`），80/TCP 只做跳转（可不开） | 来源限定为公司办公网段；**管理功能和业务同一入口**，系统管理员、审计员只从堡垒机或运维网段访问（等保 8.1.4.6 c） |
| 入站 | 22/TCP | 只允许堡垒机 |
| 出站 | 公司模型平台地址（`LLM_BASE_URL`，如单独部署 embedding / 重排也一并放行） | 平台运行时只访问模型平台；**其他一律拒绝** |
| 出站 | 公司备份系统 | 备份文件同步 |
| 出站 | 公司日志平台（如接入 syslog 等） | 日志集中留存 |

构建镜像要下载依赖（PyPI、npm、Hugging Face 模型、PostgreSQL 扩展源码、MinIO 源码）。生产机建议**不联网构建**：在构建机（可联网或经公司制品库）构建、`docker save` 导出、传到生产机 `docker load`；或者 `.env` 里把 `PIP_INDEX_URL`、`NPM_REGISTRY`、`HF_ENDPOINT`、`GOPROXY`、`SCWS_URL`、`ZHPARSER_URL`、`MINIO_SRC_URL` 指向公司内部镜像源，构建完成后撤销出站放行。

数据库、Redis、MinIO、embed、rerank、监控组件都不映射端口，只在 compose 内部网络可达；内部服务不出主机，所以内部连接不加 TLS（以后跨主机部署时要加，等保自查 8.1.2.2 b）。

### 1.3 需要准备的材料

- 公司 CA 签发的服务器证书和私钥（`server.crt` 依次放服务器证书和中间证书）。
- 公司模型平台的接口地址、各档模型名、API 密钥（只填 `.env`）。
- Word 导出模板（可选，`EXPORT_TEMPLATE`）。
- 首个系统管理员、安全审计员的人选。

## 二、安装

### 2.1 取代码

```bash
sudo mkdir -p /srv/consult-platform && sudo chown "$USER" /srv/consult-platform
git clone <公司代码仓地址> /srv/consult-platform && cd /srv/consult-platform
git checkout v1.0
```

### 2.2 配置 `.env`

```bash
cp .env.example .env && chmod 600 .env
cp deploy/prod/docker-compose.override.yml docker-compose.override.yml   # 去掉后端调试端口
```

逐项修改（`.env.example` 有每项的说明和生成方法；**口令和密钥不要贴到聊天、工单、PR 里**）：

| 变量 | 生产取值 |
|---|---|
| `APP_ENV` | `prod`（打开所有生产检查，见 2.5） |
| `COOKIE_SECURE` | `true` |
| `WEB_PORT` / `WEB_TLS_PORT` | `80` / `443` |
| `TLS_DIR` | 证书目录，例如 `/etc/consult-platform/tls`（`server.crt`、`server.key`，私钥 600） |
| `POSTGRES_PASSWORD` | 数据库超级用户口令（只用于本机运维） |
| `APP_POSTGRES_PASSWORD` | 主库应用账号 `consult_app` 口令（后端用它连库） |
| `KB_POSTGRES_PASSWORD` | 知识区账号 `consult_kb` 口令 |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` / `MINIO_KMS_SECRET_KEY` | 按 `.env.example` 生成；**KMS 主密钥丢失则对象存储无法解密，单独离线保存** |
| `TOTP_KEYS` | 按 `.env.example` 生成；**同样单独离线保存** |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL_*` | 公司模型平台 |
| `LLM_EXTERNAL` | `false`（生产开启即拒绝启动） |
| `SEED_DEMO_DATA` | `false` |
| `TEST_ACCOUNT_*` | **删除**（生产配置了即拒绝启动） |
| `BOOTSTRAP_ADMIN_*` | 首个管理员，见 2.4；建好后删除 |
| `EXPORT_TEMPLATE` | 可选，公司 Word 模板路径（配了但打不开导出返回 503） |
| `LOG_MAX_SIZE` / `LOG_MAX_FILE` | 本机日志轮转，默认即可 |

三个数据库口令都写进连接串，不要用 `@ : / ? # %`，至少 20 位。`.env` 和 `TLS_DIR` 只放部署机，不进代码仓。

### 2.3 启动

```bash
docker compose build          # 或 docker load 构建机导出的镜像
docker compose up -d
docker compose ps             # 各服务 healthy
curl -fsS https://<域名>/api/health
```

postgres 首次初始化数据卷时自动执行：`app-init.sh`（主库应用账号 `consult_app`，非超级用户）、`kb-init.sh`（知识区库 `consult_kb` 和账号）。后端启动时两条迁移链各自升级到最新。

### 2.4 首个管理员与审计员

二选一：

- 命令行（推荐，口令交互输入、不落文件）：
  ```bash
  docker compose exec backend python -m app.cli create-user --username <名字> --display-name <姓名>
  docker compose exec backend python -m app.cli grant-role --username <名字> --role sys_admin
  ```
- `.env` 的 `BOOTSTRAP_ADMIN_*`：库里没有用户时启动建一次。**建好后立即从 `.env` 删除这三项并 `docker compose up -d backend`**（等保自查 8.1.4.2 b）。

安全审计员只能用命令行授予：`grant-role --role security_auditor`。系统管理员、审计员与业务角色互斥。之后的用户在网页“用户与角色”页由系统管理员维护；项目用 `create-project` 立项（见运维手册）。

每人首次登录要扫码绑定动态码；`reset-totp`、`unlock` 用于应急。

### 2.5 启动检查（`APP_ENV=prod` 时不满足即拒绝启动）

会话存 Redis、`COOKIE_SECURE`、没有测试账号、对象存储已配置且密钥足够长、`TOTP_KEYS` 已配置、知识区单独建库且账号与主库不同、不用外部模型、**数据库账号不是超级用户**（主库 `consult_app`、知识区 `consult_kb`）、前端有证书。拒绝启动时看 `docker compose logs backend` 或 `frontend` 的第一条错误。

### 2.6 验证

```bash
bash scripts/smoke_test.sh https://<域名>       # 生产没有测试账号：登录后的项报“未配置测试账号”属预期，只看匿名部分；完整冒烟在测试机做
docker compose exec backend python -m app.cli selfcheck
docker compose exec backend python -m app.cli verify-audit
```

再用管理员账号登录，确认：用户页、审计页可用；业务账号能看到自己的项目；HTTP 自动跳到 HTTPS；`http://<主机>:8000` 不通（调试端口已去掉）。

## 三、从测试版本（v0.x）升级到 v1.0

已有数据卷时，postgres 初始化脚本不会再执行，要手工补两步：

```bash
git fetch && git checkout v1.0
echo "APP_POSTGRES_PASSWORD=<自己生成>" >> .env           # 口令不要贴到聊天和 PR 里
docker compose build postgres backend
docker compose up -d postgres                            # 重建 postgres 容器，带上新环境变量和脚本
docker compose exec postgres app-init.sh                  # 建 consult_app，把主库和库内对象转给它（可重复执行）
# 还没分库的：按 docs/知识区分库.md 执行 kb-init.sh、kb-split
docker compose up -d --build
```

升级前先做一次备份（运维手册“备份”）。`app-init.sh` 只改属主和权限，不动数据。

## 四、日志集中留存（部署方负责）

本机容器日志按 `LOG_MAX_SIZE` × `LOG_MAX_FILE` 轮转，只留近期。《网络安全法》要求网络日志留存不少于 6 个月：在 `docker-compose.override.yml` 里把各服务的 `logging` 改为公司日志平台支持的驱动（syslog、fluentd、gelf 等，文件里有示例），在日志平台留存 6 个月以上。审计记录在数据库里，不删除，随备份保存。日志和审计都不含客户原文。

## 五、备份与容灾

- 每日备份：`scripts/backup.sh`，加密口令文件放 `/etc/consult-platform/backup.pass`（600），用 cron 定时，见 `docs/备份与恢复.md`。
- 异地：把备份目录同步到公司备份系统（rsync / 备份代理），保留期按公司制度且不少于 6 个月；`BACKUP_KEEP_DAYS` 只管本机。**部署方负责**。
- 离线保存（与备份分开）：`backup.pass`、`.env` 里的 `MINIO_KMS_SECRET_KEY`、`TOTP_KEYS`。丢了备份无法恢复。
- 一期单机部署，不做热冗余；故障按运维手册恢复（等保自查 8.1.4.9 c）。

## 六、监控

自建 Prometheus / Grafana（内网，不映射公网端口，不联网），启用和告警接收见 `docs/监控.md`。Grafana 只经 SSH 隧道或堡垒机访问。

## 七、上线前检查清单

| # | 项 | 怎么确认 |
|---|---|---|
| 1 | `APP_ENV=prod`，后端、前端都正常启动 | `docker compose ps` |
| 2 | HTTPS 证书为公司 CA 签发，HTTP 跳转 | 浏览器无告警，`curl -I http://…` 返回 301 |
| 3 | 调试端口已去掉 | `docker compose port backend 8000` 报错 |
| 4 | 数据库账号不是超级用户 | 后端能启动即已通过；`docker compose exec postgres psql -U consult -Atc "select rolname, rolsuper from pg_roles where rolname like 'consult_%'"` |
| 5 | `.env` 无 `TEST_ACCOUNT_*`、`BOOTSTRAP_ADMIN_*`；权限 600 | `grep`、`ls -l` |
| 6 | 防火墙：入站只有 443（80）和堡垒机 22；出站只有模型平台、备份、日志 | 公司网络策略 |
| 7 | 磁盘加密、防病毒、NTP | 公司终端安全 |
| 8 | 备份 cron 已配置，第一次备份成功，**做过一次恢复演练** | `docs/备份与恢复.md` |
| 9 | KMS 主密钥、TOTP 密钥、备份口令已离线保存 | 负责人确认 |
| 10 | 审计链校验通过 | `verify-audit` |
| 11 | 监控告警能收到 | `docs/监控.md` |
| 12 | 公司上线前渗透检查完成 | 公司安全部门 |
| 13 | 接入公司模型后，用虚拟数据在严格档测一轮真实模型输出（占位符检查拦截率） | 开发计划 S5 |
