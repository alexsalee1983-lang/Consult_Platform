# 安全咨询 Agent 平台 · 4A + 运营架构规划

更新 2026-11-18 · 目标架构 2026-11 至 2027-12 · 版本 v4.0

## 一、规划概述

安全咨询 Agent 平台是公司安全咨询方法的运行时：把专家的方法和判断变成可执行、可核对、会进化的资产。顾问用它交付，专家用它沉淀，负责人用它管质量和专家。本文是 2026-11 至 2027-12 的目标架构与实施规划，按业务、应用、数据、技术四个架构加运营架构组织；现行实现见 `docs/架构设计.md`，工作项编号沿用 `docs/二期开发计划.md`。

### 1.1 背景与判断

| 判断 | 含义 | 对平台的要求 |
| --- | --- | --- |
| 竞争焦点是“AI 里装的是谁的方法” | 通用大模型人人可用，差距来自可核对的依据库、公司判断数据、去标识基准 | 方法即代码，判断即资产 |
| 合规从一次性项目走向持续服务 | 法规频繁修订、检查常态化；个保合规审计、网络安全事件报告已有法定要求 | 发现可追踪，依据变更可传导 |
| 可信是生死线 | 一个编造的条款号就能毁掉信誉 | 原文只取官方原件，模型只写解读，引用机器核对 |
| 公司是设备公司 | 咨询要规模化、可复制、带动设备 | 带货只作为选课题的输入，咨询方案保持中立 |

### 1.2 目标

**竞争力公式**：咨询核心竞争力 = 方法资产 × 依据可信 × 判断数据 × 交付效率 × 客户信任，任一项为零整体为零。

| 维度 | 北极星 / 目标值 | 2027-04（五期完成） | 2027-12 |
| --- | --- | --- | --- |
| 北极星 | 每月合格交付件数（已签署 + 门禁一次通过 + 引用零差错 + 客户评审 ≤ 2 轮） | 开始统计 | 按趋势定 |
| 效率 | 证据齐到 D1～D8 初稿齐的顾问人工时 | 比纯人工减 40% | 减 60% |
| 可信 | 交付件引用核对率 / 编造条款号 | ≥ 95% / 0 | ≥ 98% / 0 |
| 质量 | 门禁一次通过率 / 客户评审轮次 | ≥ 70% / ≤ 3 | ≥ 80% / ≤ 2 |
| 资产 | 打穿四格的行业包等级 / 公司实践条目 | L2 / 每格 ≥ 50 | L3 / 每格 ≥ 100 |
| 产品化 | 新产品从立项到可交付 | ≤ 3 周 | ≤ 2 周、≤ 3 专家人天 |

### 1.4 架构原则

| # | 原则 | 含义 |
| --- | --- | --- |
| 1 | 客户决定给什么 | 不取客户不给的，客户要删的照办；数据保护分标准档与严格档 |
| 2 | 机密级不收、不直连 | 口令、密钥、漏洞细节、完整拓扑与 IP、业务数据和个人信息样本不进平台；不连客户生产系统 |
| 3 | 项目与知识分离 | 项目内容只经去标识和第三级审核回流 |
| 4 | 依据可核对 | 原文只取官方原件、机械切分；模型只写解读；引用逐条机器核对 |
| 5 | 资质边界 | 只做差距分析、符合性初判、整改建议，不出具测评、认证结论 |
| 6 | 平台编排、Agent 出文字 | 能用确定流程的不用自主 Agent；读写只经工具层，模型只经网关 |
| 7 | 生成与评审分离 | 写的不评自己；评审用不同家族的模型 |
| 8 | 自动化优先 | 默认自动，人只处理例外；自主度逐级升，对客签字留给人 |
| 9 | 方法即代码 | 产品、行业包、题库、门禁、评分锚定、Agent 都版本化，评测不退化才发布 |
| 10 | 一切可追溯、不存原文 | 每次运行记生效配置、Agent、模型、提示词版本；度量和判断数据只存特征 |
| 11 | 结构化在后台、面对面在前台 | 事实交给题库和程序，洞察和关系留给顾问 |
| 12 | 先打穿再扩展 | 2 个产品 × 2 个行业做深并有真实项目验证后，再横向扩展 |

## 二、业务架构（BA）

业务架构按“产品骨架 × 行业包 × 深度档 × 法域包 × 模块”组织：产品统一一套、不分国内外，差异放在可叠加的包里，立项时组合并冻结为快照。

### 2.1 价值链与业务模式

立项定档 → 结构化调研 → 差距分析 → 方案设计 → 汇报签署 → 验收交付 → 经验回流 → 知识运营 → 下一个项目。当前做“项目交付”一种模式；持续服务（整改跟踪、复评、依据变更推送）和能力产品（行业基准、自评工具）是 2027 下半年的延伸。

### 2.2 业务能力地图

| 一级能力 | 二级能力 | 当前 | 目标态 |
| --- | --- | --- | --- |
| 项目治理 | 立项定档、范围与变更、阶段确认、保留与删除 | 已有 | 加客户评审轮次度量 |
| 调研 | 题库、选题预填、客户自评、现场访谈、事实确认、证据编号 | 访谈提纲、资料清单 | 结构化调研 + 调研助手 |
| 分析 | 依据查询、差距分析、符合性/成熟度初判、风险矩阵 | 已有 | 加发现记录、行业基准 |
| 设计 | 目标方案、路线图、制度起草与裁剪 | SOC 已有 | 5 个核心产品 |
| 质量 | 硬规则、门禁、质量评审、客户角色挑战、签署 | 已有 | 异构评审、抽检转规则 |
| 交付输出 | Word、PPT、证据与依据附录 | Word、PPT | 可验证交付件 |
| 知识运营 | 原文入库、解读、三级审核、抽检、复审、依据变更、知识获取 | 已有 | Agent 对知识充足度负责 |
| 能力进化 | 经验回流、判断数据、萃取、评测集、Agent 迭代 | 部分 | 飞轮自动运转 |
| 运营管理 | 指标、质量事件、专家管理、配置治理 | 部分 | 运营看板 + 专家管理看板 |

### 2.3 产品矩阵与打穿策略

| 序 | 产品 | 缩写 | 带动的设备品类（只用于选课题） | 定位 |
| --- | --- | --- | --- | --- |
| 1 | SOC 运营体系设计 | SOC | 态势感知/SIEM、SOAR、XDR、日志平台 | **打穿** |
| 2 | 事件后 E2E 评估与整改 | IRE | EDR、威胁检测、加固、备份恢复 | **打穿**（与 SOC 共用证据和事件知识，成交快） |
| 3 | 数据安全管理体系（含个保合规审计） | DSM | 分类分级、数据库审计、脱敏、DLP | 配置就绪，五期扩展 |
| 4 | 等保 / 关基整改与体系建设 | 模块 | 全线基础产品 | 模块，叠加在产品上 |
| 5 | 网络安全治理规划 | NSG | 规划期内建设项目 | 配置就绪，公司实践待补 |
| 6 | ISO 27001 认证咨询 | ISO | 弱 | 配置就绪 |
| 7 | AI 安全治理与合规 | AIG | AI 安全网关、大模型防火墙 | 五期新增 |
| 8 | 攻防演练支撑 | 模块 | 蜜罐、监测 | 低优先 |

**打穿四格**：「SOC、IRE」×「银行、电力」。打穿的标准是行业包达到 L2（有判断规则和黄金样例）、每格至少一个真实项目走完交付链、该产品的评测集和题库成型。其余产品保持“配置就绪、公开方法版”，五期按产品工厂流程扩展。供应链、密评不做。

### 2.4 行业包

行业是与产品、模块并列的配置维度（`industries/*.yaml`），原“行业监管专项”模块和产品配置中的行业依据并入行业包。

| 内容 | 银行例 | 电力例 | 用在哪 |
| --- | --- | --- | --- |
| 行业依据 | 金融监管办法、JR/T 标准 | 电力监控系统安全防护规定 | 检索加权、差距分析 |
| 行业题与追问 | 监管检查要点 | 三区四层要求 | 调研选题 |
| 术语与系统名 | 核心、网银、柜面 | 调度、SCADA、生产控制区 | 题目改写、报告措辞 |
| 组织惯例 | 信息科技部、风险合规部 | 调控中心、信通 | 受访角色、场次 |
| 威胁画像 | 金融欺诈、数据窃取 | 工控攻击、供应链 | SOC、事件评估 |
| 门禁规则 | — | 生产控制区提示严格档 | 立项、签署 |
| 判断规则、黄金样例、行业基准 | 行业特有做法 | 行业特有做法 | 生成、评审、汇报 |

建设等级：L0 行业依据 → L1 题与术语 → L2 判断规则与黄金样例 → L3 行业基准。每个行业由一位知识专家兼任行业负责专家。

### 2.7 人机分工

人只做五类事：对客签字担责、客户数据决定、只有人知道的事（访谈、关系、取舍）、公司经验认可、规则变更。顾问的时间从写初稿转向访谈、确认卡取舍和改稿；专家从逐条审知识转向审存疑项、抽检、拍板和萃取访谈。

### 3.2 交付链 D1～D8 与自主度

| 步 | 交付件 | 负责 Agent | 人的动作 | 目标自主度 |
| --- | --- | --- | --- | --- |
| 1 | D1 项目启动材料 | 咨询协调 | 确认范围 | L3 |
| 2 | D2 调研计划与访谈提纲 | 调研访谈 | 审阅签名调研包 | L3 |
| 3 | D3 事实清单 | 调研访谈 | 现场访谈、事实确认 | L2 |
| 4 | D4 差距分析与初判 | 依据与差距分析 | 确认分数和发现 | L2 → L3 |
| 5 | D5 目标方案 | 方案与制度设计 | 确认卡取舍 | L2 |
| 6 | D6 制度文件 | 方案与制度设计 | 改稿 | L3 |
| 7 | D7 建设路线图（只写能力层面） | 方案与制度设计 | 确认优先级 | L2 |
| 8 | D8 汇报报告与 PPT | 报告与汇报 | 签署 | L3 |

自主度：L0 建议 → L1 起草、人逐段审 → L2 人只看标出的问题 → L3 自动到待签署 → L4 自动发布加抽检。对客交付件封顶 L3，公司实践知识封顶 L2，公开知识可到 L4。升级由负责人按月度复盘决定，退化自动降级。每步内固定为“生成 → 评审 → 单轮修订 → 门禁”，关键数字判断用三方仲裁。

### 3.3 设计原则：Agent 按环节分工、按包拼装

运行时的 Agent = 公共规范 + 角色骨架 + 产品模块段落 + 行业包段落 + 模块追加 + 项目卡 + 判断规则。Agent 数量不随产品和行业增加；领域差异全部放在配置和知识里。

### 3.4 Agent 体系（8 个）

收敛规则：同一上下文、同一模型档、同一类产出的合并为一个；生成与评审不合并；安全检查不做 Agent、做工具。现有 13 个收敛为 8 个，脱敏审查降为工具层检测，售前和带教作为 2027 下半年的储备。

| # | Agent | 合并自 | 负责 | 不负责 | 模型 | 给飞轮的信号 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 咨询协调 | 咨询师 + 项目交付管理 | 对话问答与转交、D1、周报、变更、结项回流单预填 | 分析与设计 | 标准 | 高频问题、回流单 |
| 2 | 调研访谈 | — | 预填、题目改写、补充题建议、开放题整理、D2、D3、事实确认单 | 选题、打分 | 标准 | 确认单修改 |
| 3 | 依据与差距分析 | — | D4、符合性/成熟度初判、风险、发现记录 | 设计方案 | 推理 | 分数和发现被改 |
| 4 | 方案与制度设计 | 方案设计 + 制度起草 | D5、D6、D7；建设项只写能力层面 | 推荐品牌 | 推理 | 确认卡取舍、改稿 |
| 5 | 报告与汇报 | — | D8、PPT、对客措辞 | 新增结论 | 标准 | 客户评审意见 |
| 6 | 质量评审与异议应答 | — | 评审、四类客户角色挑战、异议应答 | 改稿、放行决定 | 推理，与生成不同家族 | 驳回、新异议 |
| 7 | 知识审核 | — | 七项清单审知识条目、存疑标记 | 发布决定 | 标准，与起草不同家族 | 抽检结论 |
| 8 | 知识建设与萃取 | 知识库建设 + 经验萃取 | 缺口与获取计划、公开资料解读与映射、专家任务包、萃取访谈、从判断数据提候选、题库问题题标记 | 发布、碰项目区 | 标准 | 知识充足度 |

质量责任：正确归 3 和 7，完整归 6 和门禁，适用归 4 和项目经理签署，表达归 5。评审只挑问题（位置、类型、严重度、依据、建议），生成方按意见改一轮，放行由平台规则决定。不训练模型；岗位能力靠 md 岗位说明书、动态注入的判断规则和黄金样例、评测（评审 Agent 做埋雷测试）和版本迭代。

### 3.5 调研架构

调研包在平台定义，调研助手执行；事实交给题库和程序，现场只谈矛盾、痛点和证据。界面稿：[调研助手与调研编排 v0.1](https://claude.ai/artifact/NMYGdusbQcYvCGhcreqyHA)。

| 阶段 | 环节 | 在哪 | 要点 |
| --- | --- | --- | --- |
| 场前 | 画像 → 收资 → 预填 → 选题 → 顾问签名发布 | 平台 | 题库每题挂控制项；规则选题可复现；Agent 补充题标“新增”、采纳前不评分；评分锚定不进包 |
| 场前 | 客户自评 | 客户电脑 | 加密离线问卷，口令另行告知，回传后导入；Excel 兜底；客户不配合由顾问现场代填 |
| 现场 | 题卡访谈 → 事实确认单 | 调研助手 | 本地优先、两档通用、本机加密、可远程吊销；选项锚定可观察状态；跨角色矛盾实时提示；确认单只记确认人角色 |
| 离场 | 同步 → D3 → 补证 → 题库改进 | 调研助手 + 平台 | 标准档同步、严格档只出摘要卡；封闭题程序直转事实；“不清楚”率高的题自动标出 |

客户系统数据（如 SIEM）只收统计与配置摘要（告警量趋势、数据源类别、检测用例清单、处置时长），由客户按模板自行导出；原始日志、IP 清单、漏洞明细只现场看不带走。

### 3.6 顾问对话

定位为副驾驶：查条款依据、局部改稿、访谈准备、异议应答、临时任务、转交专业 Agent。输入框占位“问条款、查依据、改某一节、准备访谈或应对客户质疑…”，首次使用显示 6 张示例卡。答案来源分三色显示：知识库、项目区、模型推断；条款类问题约 100% 来自知识库，查不到标“依据待核实”。对话里的 Agent 可自主调用检索类工具，最多 4 轮。

### 3.7 知识管理与专家支持

| 工作台 | 给谁 | 主要功能 |
| --- | --- | --- |
| 专家工作台 | 知识专家 | 派单任务（裁决、抽检、拍板，附任务包）；萃取准备包（主题、去标识样例、相关条目、提纲）；萃取会话（Agent 主持、当场出规则候选）；起草辅助（模糊词、缺适用条件、冲突提示）；个人月报 |
| 专家管理看板 | 项目负责人 | 计划与实际人天、派单与逾期、预审通过率、被推翻率、有效引用数、各格知识健康度、分歧裁决队列、按月导出 |
| 知识运营台 | 知识管理员 | 缺口与获取计划、求助任务、入库流水线、抽检与复审、依据变更 |

### 3.8 能力飞轮

> 图：能力飞轮 · 六个环节一个方向（图示见 Docs 版）

飞轮六个环节只有第三级审核需要人。回流机制：使用反馈标待复查、依据变更传导、结项回流预填、手改萃取、取舍成偏好、挑战成异议、抽检成规则。所有候选走第三级审核，只存做法不存数据。

### 3.9 集成

公司 SSO（OIDC/LDAP，保留本地账号应急）；公司模型平台（OpenAI 兼容接口，只经网关）；官方法规站点只经隔离采集机；OA 和档案系统只同步元数据；客户 GRC 工具通过 OSCAL 导出（2027 下半年）。

### 4.1 数据域

### 4.3 知识图谱

> 图：咨询知识图谱 · 三个本体与一条回流路径（图示见 Docs 版）

| 本体 | 核心对象 | 关系 |
| --- | --- | --- |
| 控制本体 | 公司控制项（能力域 × 控制目标）、标准条款 SRC、映射 MAP | 所有标准映射到控制项，不再两两映射；对外对齐 NIST OSCAL 字段 |
| 方法本体 | 题库、评分锚定、判断规则、设计模式、建议模板、异议应答、黄金样例 | 每个方法对象挂到控制项 |
| 交付本体 | 项目、证据、发现、风险、建议、整改、章节 | 发现挂控制项，可反查各标准条款 |

控制本体的结构（2026-11-22 统筹自审，随 B19 k0013 建表）：

- 层次：能力域 → 控制项 → 检查点。检查点是可判定的具体要求，参照 NIST SP 800-53A 的评估目标；题库、评分锚定、发现初判都挂到检查点。
- 映射：每条映射带关系类型（等价、子集、超集、交集）、强度和理由，依据 NIST IR 8477、SCF 的 STRM；不能写成“满足一项即满足各标准”。
- 版本：条款、映射、控制项都带版本；标准换版时自动列出受影响的映射、模板和在办项目。
- 适用性：按行业、等保级别、辖区、部署形态写成规则（参照 SP 800-53B 基线、OSCAL Profile），立项时按客户画像裁剪控制项清单。
- 组织定义参数：如“日志保留 ＿ 个月”，值由法规或客户填，不为每个行业复制控制项。
- 国内标准（等保、密评、行业规范）到国际框架没有公开的权威映射，由专家拍板，这是公司的差异化积累；国际框架之间优先导入 OLIR、CTID 的权威映射。

四期候选（三期 B19 跑通 SOC 试点后再定）：控制项之间的支撑与依赖关系（整改路线按依赖排序）、控制项到 ATT&CK 和事件类型的连接（CTID 映射、D3FEND）、检查点的期望证据类型（查阅、访谈、测试）、术语对照 GLS 与别名表合并为控制项的首选名与同义词（参照 SKOS）。试点后看效果：Agent 起草映射、专家只确认存疑；按判断数据回流修订控制项。

发现记录（F-xx）字段：控制项、证据编号、依据条款与版本、初判（已/部分/未满足，现状与目标分）、风险、建议四要素（优先级、责任部门、周期、验收标准）、状态（初判 → 确认 → 签署 → 整改中 → 已复核）、责任方（客户自担、继承自云厂商、共担）；字段对齐 OSCAL 评估结果与 POA&M（只对齐字段，不引入 OSCAL 格式）。它是整改跟踪、行业基准和可验证交付件的基础。

### 4.4 分级与流动

机密级两档都不收；敏感级标准档进项目区、严格档只收同意后的摘要卡。项目区到知识区只有一条路：去标识（规则 → 工具层检测 → 知识管理员确认）→ 第三级审核。分包商数据按组织边界隔离。客户不同意回流的项目不产生任何候选。

### 4.5 判断数据

顾问和专家的每个决定都是公司方法的标注样本，只存结构化特征，不存客户原文。

| 事件 | 留存 | 用途 |
| --- | --- | --- |
| 顾问改稿 | 章节类型、改动类别与幅度、Agent 与提示词版本 | 自主度复盘、手改萃取、版本对比 |
| 确认卡取舍 | 选项、行业、规模区间 | 判断规则候选、方案默认值 |
| 阻断驳回 | 阻断类型、是否驳回 | 评审 Agent 误报率 |
| 知识抽检 | 类别、结论、不通过的清单项 | 审核 Agent 校准、停发判定 |
| 客户挑战 | 异议类型、控制项、是否应答成功 | 异议应答库 |
| 事实确认单修改 | 题目、修改类型 | 题库改进、调研准确度 |
| 建议落地 | 建议类型、是否完成、用时 | “哪种建议能落地”（2027 下半年） |

### 4.6 成熟度参考模型

| 产品 | 参考模型 | 输出 |
| --- | --- | --- |
| SOC | SOC-CMM（5 个域，成熟度 0～5，技术和服务另评能力） | 0～5 |
| 事件后评估 | NIST SP 800-61 Rev.3 生命周期，对齐 CSF 2.0 | 分环节差距 |
| 治理规划 | NIST CSF 2.0 现状/目标画像 + Tiers 1～4 | 现状 → 目标 |

### 4.7 知识充足度与知识获取

“够不够”看三个信号：结构覆盖（产品依据集合 × 能力域 × 控制项的需求清单逐项有现行条目）、可检索（评测题按控制项自动生成）、实际使用（待核实率、零命中、被推翻）。知识建设与萃取 Agent 对“够”负责：每周算缺口 → 出获取计划 → 知会知识管理员 → 隔离采集机按官方白名单下载并算 sha256 → 第一级核验发布 → 评测关闭缺口；拿不到的派求助任务。生产平台不联网。

### 5.1 分层与技术栈

| 入口 | 工作台、调研助手（PWA）、命令行、内部 API | React；只在公司网络和 VPN 内 |

| Agent 运行面 | 统一调用层 `call.py`：按快照拼装、六层上下文、结构化输出、引用核对、三种多模型模式 | 自建 |
| 工具层 | `invoke()` 白名单、区域硬规则、成员与组织检查、机密级与脱敏检测 | 自建；对内提供 MCP 接口（2027） |

| 观测与审计 | 指标、审计哈希链、运行记录（不记原文） | Prometheus + 自建 |

### 5.2 私有模型与知识库的配合

私有化模型不联网、有训练截止日期：会变的、要核对的一律以知识库为准，模型只负责理解、推理和组织语言。每次调用按固定顺序组装：① 规范（立项快照）→ ② 判断规则 → ③ 项目输入（带编号）→ ④ 知识与依据原文（编号、版本、时效）→ ⑤ 黄金样例 → ⑥ 任务与格式。输出后程序核对编号，不带编号的句子标“推断”，引用已废止条款拦下。不变的①②层放前面以利用前缀缓存；各层有字数预算。

### 5.3 模型规划

| 角色 | 首选 | 备选（按序） | 约束 |
| --- | --- | --- | --- |
| 生成（推理 / 标准 / 轻量三档） | DeepSeek | GLM、Kimi、MiniMax | — |
| 评审、知识审核 | GLM | Kimi、MiniMax、DeepSeek | 与生成不同家族，平台强制校验 |
| 仲裁 | Kimi | MiniMax、GLM | 与 A、B 都不同 |
| 向量 | 公司平台 embedding 或 bge-m3（按评测定） | Qwen3-Embedding | 换模型需重新向量化 |
| 重排 | 2026：bge-reranker-v2-m3 int8（CPU） | 2027：本地 Qwen3-Reranker（0.6B/4B 按评测） | 换模型自动重校门槛 |

三种模式：单模型（起草）、异构评审（评审、审核）、多模型仲裁（成熟度分、符合性初判、知识存疑）。首选不可用自动取下一个已通过评测的；只有一个家族时降级为同家族并提高抽检。生产只用公司私有化模型，外部模型只限测试环境和虚拟数据。

### 5.4 检索

现状正式评测 93 题 91.4%。目标态四项：切片上下文（入库时前缀文件/章/节/适用对象）、控制项扩展检索、法域与行业过滤、引用级核对。目标准确率 ≥ 95%，引用核对率 ≥ 98%。

### 5.5 可信工程与安全

| 闸 | 拦什么 |
| --- | --- |
| 入库闸 | 非官方原件、sha256 不符、条文不一致 |
| 生成闸 | 引用库外条款 |
| 核对闸 | 条款号核不上、已废止、已替代 |
| 评测闸 | 准确率 < 90% 或有编造时停自动发布 |
| 挑战闸 | 四类客户角色挑战答不上的章节 |

Agent 安全对照 OWASP 大模型应用风险：提示注入（资料只作数据、写入工具不进对话）、知识投毒（白名单、逐字重解析、抽检、按批次下线）、工具越权（白名单 + 硬规则）、过度自主（自主度封顶）、数据外泄（网关唯一出口、审计不记原文）。平台本身按等保三级建设，三权分立，审计哈希链；调研助手、分包账号、采集机、多模型接入每增一项更新威胁模型；五期前做第二次渗透测试。

## 六、运营架构

运营架构贯穿四层，回答三件事：质量怎么衡量和把关、出了问题怎么处置、专家怎么管。业务量小的阶段以精简指标和定性复盘为主。

### 6.1 质量模型与把关

交付件质量四维：正确（事实与依据）、完整（覆盖与要素）、适用（贴合客户、可落地）、表达。门禁一次通过率只是过程指标。洞察和建议过三道关：机器关（质量评审 Agent 查四要素、追溯、客户约束、泛化）→ 人工关（项目经理签署；关基、认证类、严格档项目加独立复核）→ 结果关（客户评审、建议采纳、整改落地）。

### 6.2 指标体系（精简版）

| 类 | 指标 | 口径 | 红线 / 看法 |
| --- | --- | --- | --- |
| 北极星 | 每月合格交付件数 | 已签署 + 门禁一次通过 + 引用零差错 + 客户评审 ≤ 2 轮 | 趋势 |
| 正确 | 编造条款号次数 | 抽检加评测 | **红线 0** |
| 正确 | 依据查询评测准确率 | 正式评测题 | **红线 ≥ 90%** |
| 完整 | 门禁一次通过率 | 首次提交签署即通过 | 趋势 |
| 适用 | 建议类章节改稿幅度 | Agent 稿到顾问稿 | 趋势 |
| 客户 | 客户评审轮次 | 每份对客交付件 | 趋势 |
| 效率 | 初稿人工时 | 证据齐到初稿齐 | 趋势 |
| 调研 | 事实确认单修改率 | 修改加待补占比 | 趋势 |
| 知识 | 有效引用数 | 被引用且未被推翻 | 趋势 |
| 专家 | 派单按时完成率 | 按专家导出 | 趋势 |

每月定性复盘 30 分钟：被推翻最多的 3 条知识、改稿最多的 3 个章节、确认单修改最多的 3 道题。自主度、判断事件量、多模型一致率、洞察抽评、引用覆盖率 2027 下半年再纳入。

### 6.3 AI 质量事件处置

事件：AI 产出已签署、已发客户或被采用到对客内容中，并存在编造或错引条款、引用已废止依据、事实与证据不符、资质边界用语、客户信息跨项目泄露、明显不当建议。

| 级别 | 情形 | 遏制时限 |
| --- | --- | --- |
| P1 | 已对客且可能影响合规决策或法律风险；客户数据泄露 | 4 小时 |
| P2 | 已对客影响有限；签署前发现的跨项目系统性问题 | 1 个工作日 |
| P3 | 单点、未对客 | 常规修复 |

八步：登记（任何人或程序）→ 分级（项目经理 → 项目负责人）→ 遏制（冻结导出、下线条目、回滚 Agent 版本、降自主度）→ 影响评估（按引用关系反查）→ 更正与沟通（是否通知客户由项目负责人定）→ 根因（知识、检索、md、模型、门禁、人工签署）→ 纠正预防（新增评测题或门禁）→ 复盘。数据泄露类同时走公司安全事件流程。降级模式：模型平台不可用时交付链暂停、对话只检索、调研助手不受影响。

### 6.5 评测与发布

评测四层：检索（正式评测题，每批入库、换模型、调门槛必跑）、Agent（黄金样例对照、红线用例、评审 Agent 埋雷测试）、端到端（虚拟客户 D1～D8）、线上（定性复盘）。发布流程：PR → 评测不退化 → 测试机影子运行 → 新立项生效 → 退化即回滚。线上发现的问题自动成为新评测题。
