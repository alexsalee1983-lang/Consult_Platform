# 安全咨询知识库建设方案

版本：v2.0（2026-11-15）。v1（2026-11-07）写于平台开发之前，载体、审核和排期已被后续决策和平台实现取代；v1 全文见 git 历史。排期以《知识库建设总体计划》和《二期开发计划》为准，已拍板的事项以决策记录为准。

## 一、定位与目标

- **首要用户**：交付顾问，以及交付链上的 Agent（Agent 只能引用库里的依据，查不到标“【依据待核实】”）。售前、新人带教放到二期之后。
- **范围**：管理与运营类咨询知识为主，技术类作为配套。二期覆盖 5 个核心产品：SOC 运营体系设计、ISO 27001 认证咨询、数据安全管理体系、事件后 E2E 评估与整改、网络安全治理规划，和 3 个模块（等保 2.0 整改与体系建设、行业监管专项、实战攻防演练支撑）。
- **目标顺序**：先统一交付质量，再提升交付效率。
- **知识库的作用**：给 Agent 和顾问**可核对的依据和公司做法**，不是教模型。大模型对新法规、条款号和原文、版本效力、行业要求都靠不住，所以依据原文只取官方原件、机械切分入库，模型只写解读，且只能引用已入库的条款。
- **12-31 口径**：平台和公开知识就绪；公司实践（项目沉淀、专家经验、黄金样例）在 2027 年 1～2 月经结项沉淀和经验回流续补。

## 二、现状与约束

| 项目 | 现状 |
|---|---|
| 交付模式 | 4～5 人团队、3～6 个月；帮助客户建立体系（文档、流程），并指导落地 |
| 主要客户 | 国内大行（含海外业务）、电力、制造、政府、零售、少量运营商 |
| 存量资产 | 约 10G，分散在专家个人电脑中；用于公司实践部分，入库前要法务三问的书面结论 |
| 母版与映射 | 有公司内部制度框架，但不是为咨询设计的；控制映射矩阵二期起建（B3，首份 ISO 27001 ↔ 等保 2.0 管理要求 v0） |
| 客户保密协议 | 大部分允许脱敏后复用；项目沉淀一律先去标识 |
| 人力 | 知识库专人每月约 10 人天；每个产品一名专家负责人；专家时间主要用在“只有人能判断”的地方（见第六节） |
| 平台 | **自建平台的知识服务**（一期 M2 已建成）：知识区单独一个库；全文 + 向量检索、重排；Agent 经工具 `kb.search`、`basis.lookup`、`kb.mapping` 查询；模型只经网关，接公司私有化部署的白名单模型 |
| 资质 | 不具备测评类资质；知识和 Agent 输出只写差距分析、符合性初判、整改建议，不写测评、密评、认证结论 |
| 新人成长 | 约 2 年才能独立交付，卡在知识体系不足、专家形象立不起来 |

**顾问主要痛点**：最耗时的是客户侧反复沟通，其次是写制度、写报告；常见的坑是客户不配合访谈、制度写完落不了地、评审被客户挑战。

## 三、交付质量差异的七个根源

| # | 常见问题 | 客户侧表现 | 知识库对策 |
|---|---|---|---|
| 1 | 调研没有目标 | 客户觉得“问了一堆没用的”，不配合 | 按角色的访谈提纲，每个问题标明“为什么问、对应哪个控制项” |
| 2 | 结论缺证据链 | 被挑战“你凭什么这么说” | 统一“发现—证据—依据—风险—建议”的写作规范 |
| 3 | 差距分析只对标准，不对业务 | 客户觉得“对我没用” | 结合行业监管要求和业务场景的分析模板 |
| 4 | 建议泛化 | 方案落不了地 | 整改建议必须带优先级、责任部门、周期和验收标准 |
| 5 | 制度照抄 | 制度束之高阁 | 制度母版 + 裁剪指引，配套流程、表单、RACI 和度量 |
| 6 | 依据储备不足 | 专家形象立不起来 | 依据库 + 客户异议应答库 |
| 7 | 不管理预期 | 反复沟通、返工 | 启动会模板、范围确认单、阶段签字确认机制 |

“反复沟通”这个最大耗时项，根源主要在第 1、4、7 条。

## 四、知识库结构（沿用）

```
L1 通用交付方法论（所有项目共用）
   ├─ 项目阶段与质量门禁（启动 / 调研 / 分析 / 设计 / 落地辅导 / 验收）
   ├─ 写作规范（发现—证据—依据—风险—建议）
   └─ 客户管理工具（启动会、范围确认单、周报、阶段确认单）

L2 服务产品交付包（顾问检索入口，按 6 个一级目录组织）
   ├─ 安全战略与治理
   ├─ 合规与认证
   ├─ 数据安全与隐私
   ├─ 安全运营
   ├─ 应急与韧性
   └─ 安全架构与新兴技术

L3 领域知识（按 管理 / 运营 / 技术支撑 标签归类，被各交付包引用，只写一次）

L4 依据库（法规标准条款解读、控制映射矩阵、行业监管要求）

L5 经验库（脱敏案例、客户异议应答库、踩坑记录）
```

**一级目录面向外部，三个维度面向内部**：一级目录用于售前和客户沟通；“管理、运营、技术支撑”作为知识库内部标签。

### 每个服务产品交付包的标准内容

1. 服务说明：解决什么问题、适用客户、范围边界（将来可直接开放给售前）
2. 工作分解与排期模板（4～5 人、3～6 个月）
3. 交付物清单：每个阶段产出什么，附质量检查清单
4. 模板：访谈提纲、调研问卷、报告与汇报材料
5. 黄金样例：每类交付物一份最好的脱敏样例
6. 常见挑战与应答

交付物类型（doc_type）：TPL 模板、GLD 黄金样例、POL 制度母版、MTD 方法、REF 依据解读、MAP 控制映射、CAS 案例、OBJ 异议应答、PIT 踩坑记录、SRC 依据原文（B7 新增，法规条文、NIST 控制项；国家标准只有条款目录）。元数据取值以公共规范第 7 节和 `backend/app/kb/meta.py` 为准。

## 五、知识来源与三级审核

决策依据：2026-11-13 两人原则、2026-11-15 自动化优先原则和公开知识三级审核，以及“公开资料由知识审核 Agent 替代两人审核”（决策记录同日）。

| 级别 | 来源和内容 | 怎么审 | 抽检 |
|---|---|---|---|
| 一 | **依据原文 SRC**：官方网站下载的法规、NIST 等原件，按条机械切分；国标只建条款目录 | 平台程序核验后自动发布：来源网址在官方网站白名单里，原件 sha256 与清单一致，重新解析后条文逐字一致、条号连续，状态和文号与清单一致（B10） | 随机 5% |
| 二 | **公开资料加工**：解读 REF、映射 MAP、方法 MTD，以及只含公开资料的案例 CAS、异议应答 OBJ | 程序规则（引用都已核对、无结论用语、无机密级、元数据齐全）+ 知识审核 Agent 按七项清单逐项判断（B11）。全部通过的自动发布，标“Agent 审核”；任何一项存疑进人工队列，按两人原则审，人只看标出的问题和原文对照 | 随机 20%；问题率超过 5% 翻倍 |
| 三 | **项目沉淀、专家经验、内部制度改造**（L2、L5 公司实践） | 去标识由知识管理员确认（不能是上传者）；知识审核 Agent 先审、列出问题；一位知识专家拍板（不能是作者）（B12） | 不抽检，逐条人审 |

- **停止自动发布**：某一类自动发布内容最近 20 次抽检的不通过率超过 10%，这一类全部回到人工审，修好后恢复；管理员也可以用开关（`KB_SRC_AUTO_PUBLISH`、`KB_AGENT_AUTO_PUBLISH`）随时停掉。
- **审核员资格**：内容审核为知识专家、所审领域 3 年以上咨询实践；合规审核为知识管理员；抽检为知识专家，不能抽检自己导入或编写的版本。人工审核、抽检和知识审核 Agent 用同一份七项清单（`agents/roles/kb-reviewer.md`、《专家指导书》）。
- **不变的**：作者永远不能审自己的版本；去标识确认人不能是上传者；非公开来源不走自动发布；每次自动决定都进审计（规则结果、Agent 和提示词版本，不记原文）。
- `KB_SINGLE_REVIEWER_PUBLIC`（作者自审 + 补复审）被第二级取代，生产保持关闭。

## 六、入库流程

```
下载清单（官方网址、sha256、文号、版本、状态）
  → kb-source-split 切条（SRC）→ 平台核验 → 自动发布 / 抽检
  → kb-draft 起草解读、映射、方法、异议应答（经网关，只能引用已入库条款）
  → 引用校验（B8）：找不到原文的引用列“待核”，不能提交
  → 提交审核 → 程序规则 + 知识审核 Agent（B11）→ 自动发布 / 人工队列
  → 每批入库后跑有无知识库对比评测（B1），不达标这一批暂不发布
  → 发布后：依据换版、废止按 B5 登记，B9 在交付件签署前拦下过期引用；条目更新后经 B4 提醒引用它的项目顾问复核
```

项目沉淀走另一条：结项沉淀 / 经验回流 → 去标识（规则词库 → 脱敏审查 Agent → 知识管理员确认，确认后原件删除）→ 第三级审核。

## 七、依据准确应用

1. **原文和解读分开**：条款号和原文只取官方原件；模型只起草解读、映射、案例和异议应答。
2. **版权分档**：法律法规原文可逐条入库；美国政府出版物（NIST、CISA）可原文入库；MITRE ATT&CK 可入库、保留版权声明；国家标准（GB/T、JR/T、GM/T）只收条款号、条款标题、解读和映射，不收全文，原件只放下载目录供对照。
3. **宁缺勿错**：检索达不到门槛的不给，Agent 标“【依据待核实】”或发“证据不足”卡；引用已废止或已被替代的条款在签署前拦下（B9，平台规则阻断，不能驳回）。
4. **按产品、按行业**：检索先查本项目产品和模块，再查通用（B2）；金融、电力项目优先行业依据（B2 补充）。
5. **不做外部自动订阅**：依据变更靠季度官网核对清单和人工登记（B5）。

## 八、内容生产顺序（二期）

| 顺序 | 内容 | 用在哪里 |
|---|---|---|
| 1 | 近两年新发布或修订的法规（SRC + 解读） | 所有产品的依据查询 |
| 2 | 金融、电力的行业监管文件 | 行业监管专项模块、B2 行业加权 |
| 3 | 等保、数据安全、密评的条款目录、解读和映射 | 等保 2.0 整改模块、B3 映射矩阵、数据安全产品 |
| 4 | NIST、ATT&CK（ATT&CK 和 Sigma 规则加工成检测用例和处置剧本） | SOC、事件后 E2E |
| 5 | 监管处罚案例加工成异议应答（只记问题类型、依据和金额，不记当事单位） | 所有产品的异议应答 |
| 6 | 各产品交付包（服务说明、工作分解、交付物清单与默认大纲、模板） | 产品配置（D 线），先按公开方法起草、专家补公司实践 |

M2 验收（12-04）约 300 条以 1～3 为主；ISO 27001、数据安全各约 50 条在 12-18 前；事件后 E2E、治理规划在 12-31 前，治理规划的公司方法靠专家萃取工作坊。

## 九、质量衡量

| 指标 | 怎么量 | 目标 |
|---|---|---|
| 依据查询准确率 | 正式评测题（50～100 道，按条号查询、跨依据映射、行业要求三类） | ≥ 90%（M2 验收） |
| 有无知识库对比 | 同一批题目不用 / 用知识库作答，比准确率和编造条号次数（B1 补充） | 用知识库明显更好、编造条号为 0 |
| 自动发布质量 | 各类抽检不通过率 | ≤ 10%，超过即停自动发布 |
| 交付使用 | 交付件引用的条目数、被顾问改掉或推翻的条目（标“待复查”） | 试点后定基线 |
| 健康度 | 过期内容占比、缺口 TOP、贡献统计（B6 知识地图） | 每季度看 |
| 业务结果 | 交付物首次评审通过率、客户返工次数、报告与制度编写耗时、新人独立交付所需时间（现状约 2 年） | 试点拿到基线后定 |

## 十、风险与应对

1. **专家时间不够**：公开知识靠程序和 Agent 审、人抽检，专家时间留给存疑项、第三级审核和萃取；每周看进度，落后一周把治理规划降为“平台已配置、公司实践待补”版。
2. **Agent 审核放过错误**：抽检兜底、问题率超标自动停；每批跑对比评测；依据原文不经模型。
3. **内部制度和客户资料授权**：法务三问书面结论之前，公司实践部分不入库；公开知识不受影响。
4. **语料质量**：原始资料不直接入库，只入核验或审核过的条目。
5. **资质边界**：等保测评、密评、认证须由有资质机构开展，知识只写差距分析、符合性初判、整改建议；程序规则和七项清单都查结论用语。

## 十一、后续阶段

- **2027 年 1～2 月**：试点复盘（原一期交付日 2027-01-15 改为检查点）；结项沉淀和经验回流补公司实践；关基保护、数据分类分级与风险评估、事件报告与应急机制、漏洞管理与威胁情报 4 个模块按试点反馈排。
- **之后**：售前入口、新人带教；按市场需求启用储备产品，优先观察个保合规审计、数据出境、AI 安全与合规。
