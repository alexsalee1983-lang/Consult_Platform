# 安全咨询知识库建设方案

更新日期：2026-11-07

## 一、定位与目标

- **首要用户**：交付顾问。后续开放给售前，角色颗粒度与权限在第一期定义好字段，暂不开放。
- **范围**：优先建设管理与运营类咨询知识，技术类作为配套，支撑端到端的安全规划。
- **目标顺序**：先统一交付质量，再提升交付效率。
- **第一期期限**：2 个月内交付第一个可用版本。
- **第一期定位**：不是“资料库”，而是“统一交付标准 + 两个服务产品交付包”。

## 二、现状与约束

| 项目 | 现状 |
|---|---|
| 交付模式 | 4～5 人团队、3～6 个月；帮助客户建立体系（文档、流程），并指导落地 |
| 主要客户 | 国内大行（含海外业务）、电力、制造、政府、零售、少量运营商 |
| 存量资产 | 约 10G，分散在专家个人电脑中，没有平台 |
| 母版与映射 | 有公司内部制度框架，但不是为咨询设计的；没有咨询母版体系，没有控制项映射 |
| 客户保密协议 | 大部分允许脱敏后复用 |
| 人力 | 指定专人，每月约 10 人天 |
| 平台 | 公司内部智能体（白名单商用大模型），RAG 无限制，需部署在公司内部 |
| 资质 | 暂不具备测评类资质（等保测评、密评等） |
| 新人成长 | 约 2 年才能独立交付，卡在知识体系不足、专家形象立不起来 |

**顾问主要痛点**：最耗时的是客户侧反复沟通，其次是写制度、写报告；常见的坑是客户不配合访谈、制度写完落不了地、评审被客户挑战。

## 三、交付质量差异的七个根源

| # | 常见问题 | 客户侧表现 | 知识库对策 |
|---|---|---|---|
| 1 | 调研没有目标 | 客户觉得“问了一堆没用的”，不配合 | 按角色的访谈提纲，每个问题标明“为什么问、对应哪个控制项” |
| 2 | 结论缺证据链 | 被挑战“你凭什么这么说” | 统一“发现—证据—依据—风险—建议”的写作规范 |
| 3 | 差距分析只对标准，不对业务 | 客户觉得“对我没用” | 结合行业监管要求和业务场景的分析模板 |
| 4 | 建议泛化 | 方案落不了地 | 整改建议必须带优先级、责任部门、周期和验收标准 |
| 5 | 制度照抄 | 制度束之高阁 | 制度母版 + 裁剪指引，配套流程、表单、RACI 和度量 |
| 6 | 依据储备不足 | 专家形象立不起来 | 依据库 + 客户异议应答库 |
| 7 | 不管理预期 | 反复沟通、返工 | 启动会模板、范围确认单、阶段签字确认机制 |

“反复沟通”这个最大耗时项，根源主要在第 1、4、7 条。

## 四、知识库结构

```
L1 通用交付方法论（所有项目共用）
   ├─ 项目阶段与质量门禁（启动 / 调研 / 分析 / 设计 / 落地辅导 / 验收）
   ├─ 写作规范（发现—证据—依据—风险—建议）
   └─ 客户管理工具（启动会、范围确认单、周报、阶段确认单）

L2 服务产品交付包（顾问检索入口，按 6 个一级目录组织）
   ├─ 安全战略与治理
   ├─ 合规与认证
   ├─ 数据安全与隐私
   ├─ 安全运营
   ├─ 应急与韧性
   └─ 安全架构与新兴技术

L3 领域知识（按 管理 / 运营 / 技术支撑 标签归类，被各交付包引用，只写一次）

L4 依据库（法规标准条款解读、控制映射矩阵、行业监管要求）

L5 经验库（脱敏案例、客户异议应答库、踩坑记录）
```

**一级目录面向外部，三个维度面向内部**：一级目录用于售前和客户沟通；“管理、运营、技术支撑”作为知识库内部标签。

### 每个服务产品交付包的标准内容

1. 服务说明：解决什么问题、适用客户、范围边界（将来可直接开放给售前）
2. 工作分解与排期模板（4～5 人、3～6 个月）
3. 交付物清单：每个阶段产出什么，附质量检查清单
4. 模板：访谈提纲、调研问卷、报告与汇报材料
5. 黄金样例：每类交付物一份最好的脱敏样例
6. 常见挑战与应答

## 五、第一期范围

> **2026-11-07 调整**：网络安全治理规划一期不做，第一期只有 SOC 运营体系设计（见决策记录）。本节和下文按两个产品安排的交付件、工作坊和人力待规划侧调整，调整前以决策记录为准。

**两个产品**：SOC 运营体系设计、网络安全治理规划（一运营、一管理）。

| 交付件 | 说明 |
|---|---|
| 通用交付规范 v1 | 阶段划分、质量门禁、写作规范、客户管理工具 |
| SOC 运营体系设计交付包 v1 | 聚焦本地数据中心和网络环境，不含云安全运营 |
| 网络安全治理规划交付包 v1 | 需先做专家萃取，再标准化 |
| 制度母版体系 v1 | 四级文件框架（方针 / 管理办法 / 流程规程 / 记录表单）+ 裁剪指引，先覆盖治理架构与运营制度 |
| 客户异议应答库 v1 | 收集 30～50 条高频挑战及标准应答 |
| 平台上线 | 内部智能体 + RAG，实现可检索、可问答 |

**说明**：治理规划依赖资深专家判断，标准化难度高于 ISO 27001，第一期需要安排足够的专家萃取工作坊。

## 六、两个月推进计划

| 周 | 工作 | 关键动作 |
|---|---|---|
| 第 1 周 | 定标准 | 元数据字段、命名规范、密级、角色权限（售前权限字段先定义）；指定两个交付包的专家负责人 |
| 第 2～3 周 | 盘点筛选 | 专家从 10G 资料中各自挑出“最好的 20%”，按产品和阶段归档 |
| 第 3～5 周 | 萃取加工 | 脱敏；把内部制度改造成咨询母版；组织 2～3 次专家萃取工作坊（访谈提纲、常见挑战、踩坑、治理规划方法） |
| 第 5～6 周 | 平台入库 | 导入内部智能体 RAG；配置 3 个高频场景：制度起草、条款与依据查询、异议应答 |
| 第 7 周 | 试点验证 | 选一个在建项目试用，收集顾问反馈 |
| 第 8 周 | 发布与机制 | 发布 v1；把“结项沉淀”写进项目流程 |

## 七、风险与应对

1. **人力不够**：专人每月 10 天只够组织协调和平台工作，内容需由专家来写。建议两个产品的专家负责人各投入 5～8 天，并纳入绩效。
2. **内部制度对外使用授权**：改造成咨询母版前，需法务或保密部门确认；去除企业特有的组织名称、系统名称和流程编号。
3. **RAG 效果取决于语料质量**：不要把 10G 原始资料直接灌入，第一期只入库几百份精选文档。
4. **资质边界**：等保测评、密评须由有资质机构开展，咨询方只做差距分析、方案和整改辅导，合同中写明边界。

## 八、后续阶段

- **第二期**：补齐 ISO 27001 认证咨询、事件后 E2E 评估、数据安全管理体系；“合规与认证”整体启动；完成 ISO 27001 与等保 2.0 管理要求映射 v0；以模块方式挂接法规驱动产品；开放服务说明和案例摘要给售前。
- **后续**：按市场需求启用储备产品，优先观察个保合规审计、数据出境、AI 安全与合规。

**衡量指标**：资产复用率、报告编写耗时、检索命中率与满意度、新人独立交付所需时间、过期内容占比。
