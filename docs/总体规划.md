## 一、结论

1. 路线不变：二期 11-30（v2.0）→ 三期 12-31（v3.0）→ 四期 2027-01-31（v4.0）→ 五期 2027-04-30（v5.0）→ 六期 2027 下半年。
2. 三期仍是重心，要打好四个地基：知识数据结构、知识采集与建设流水线、评审严格度、写稿助手 v1。**本版新增第五个：知识就绪度。** 三期的知识链路原本几乎都是公开来源自动化；交付链最缺的公司做法类知识（模板、方法、常见坑、案例、黄金样例）没有工作项，也没有专家时间。12-31 装配机制会上线，但槽位多半是空的。
3. 就绪度的做法分三步：
   - 先定靶子：SOC 关键章节的槽位规格和章节级评测集；
   - 再由 Agent 起草、专家确认；
   - 最后用就绪度验收。v3.0 第 9 条从“缺知识发卡”改为“SOC 8 个关键章节就绪度 ≥ 70%”。
4. 采集机补“公开的依据”，人补“公司的做法”，槽位规格把两者对到同一个章节上。专家只做判断和公司经验，起草、排版、找出处交给 Agent。
5. zj1、zj2 12-08 才到位，三期专家时间是全计划最紧的资源。专家入场积压清单（积压 E1～E14，见 `docs/专家入场工作清单.md`）要和三期工作合并排期，能合的合并做（第六节）。

## 三、设计要点（影响分期开发的部分）

### 1. Agent：9 个

| # | Agent | 所在区 | 主要模式 | 由谁审 | 上线 |
|---|---|---|---|---|---|
| 1 | 咨询协调 | 项目区 | 对话、派活、D1 表单成稿 | 人 | 三期 |
| 2 | 调研访谈 | 项目区 | D2、访谈纪要整理 | 质量评审 | 已有 |
| 3 | 依据与差距分析 | 项目区 | D3、差距分析、查依据 | 质量评审 | 已有 |
| 4 | 方案与制度设计 | 项目区 | D5、D6、补齐建议四要素 | 质量评审 | 三期合并 |
| 5 | 报告与客户沟通 | 项目区 | D4、D7、D8、对客口吻、异议应答 | 质量评审 | 三期 |
| 6 | 质量评审 | 项目区 | 门禁评审（封闭五类阻断）、对照黄金样例打分 | 人（驳回） | 三期 |
| 7 | 知识采集 | 采集机 | 来源发现、巡检、初筛 | 知识审核 | 三期 |
| 8 | 知识建设与萃取（kb-builder） | 知识区 | 提炼、挂载、知识源清单、反向提炼、缺槽访谈、合成、保鲜 | 知识审核 | 三期合并；合成五期 |
| 9 | 知识审核（kb-reviewer） | 知识区 | 审核、起草预审、异构挑战 | 人（抽检） | 已有 |

脱敏审查降为工具层；售前、带教暂作储备。生成类用 DeepSeek，审核类用 GLM，分歧由 Kimi 仲裁，采集初筛用小模型。两条硬边界不变：知识侧 Agent 不能访问项目区，交付侧 Agent 不能写知识区。因此改稿特征、补库任务、知识更新草稿都由平台程序生成。

### 2. 知识：以控制项为主轴，按槽位装配，以就绪度验收

- 产品、行业、控制项都是多值标签；知识编号只做序号（`KB-000123`）；控制项中枢以公开框架起草，法务确认后以 SCF 为起点。
- 交付链每个章节声明所需的知识槽位：依据、模板、方法、案例、常见坑、经验数值，以及每槽所需条数和挂哪些控制项。按“产品 × 行业 × 控制项”装配；缺槽在动笔前提示，不硬写。
- **就绪度**：槽位内已发布（不含候选）、类型匹配且未被标“不对 / 过时”的条目达到规格条数，这个槽就算就绪；章节就绪度 = 就绪槽位 ÷ 槽位总数。
- 截断按知识类型分配额度，模板、案例不再截成 300 字。

### 3. 知识流水线

发现 → 获取 → 解析 → 提炼 → 挂载 → 合成 → 审核 → 评测 → 保鲜。

- 平台不联网，采集在隔离采集机上，结果经单向通道导入。
- 获取由缺口驱动，缺口有五类触发源：定时巡检、外部变化、使用信号、业务需求（含“章节缺槽”）、生命周期。
- 公开来源 ≥ 90% 自动发布，先进候选影子期；公司做法和黄金样例必须由专家拍板。

### 4. 知识来源分工

| 知识 | 谁来产出 |
|---|---|
| 标准、法规原文 | 采集机，自动核验后发布 |
| 条文解读、标准间映射 | 采集机和 Agent 起草，知识审核 Agent 审，专家抽检 |
| 公开基准数据、行业报告 | 采集机，只作参考，标出处 |
| 交付模板、方法论、案例、常见坑、黄金样例、公司经验数值 | **只能靠人**（Agent 起草、专家确认） |
| 章节槽位规格（每章需要什么知识） | **只能靠人**（规划会话起草、专家确认） |

### 5. 严格度

- 阻断只有封闭五类：编造或用错依据、资质用语、机密与客户信息、对客结论无证据、与已确认事项矛盾。
- 按交付件分评审档案，增量评审。
- 对机器严、对人松：Agent 产出的引用必须能解析、条文必须一致；专家输入只拦三类（引用不存在或错误、资质用语、机密与客户信息），其余给建议，格式问题自动修。

### 6. 专家怎样快速产出知识：Agent 起草、专家确认

不让专家对着空白页写，Agent 先拿出约八成的草稿，专家只做判断和补充。

| 方式 | Agent 做什么 | 专家做什么 | 适合 | 对应工作项 |
|---|---|---|---|---|
| 1. 从旧交付物反向提炼 | 读脱敏后的历史报告，抽结构、模板、方法、写法，每条标出处段落 | 勾选、补公司口径 | 模板、方法、黄金样例 | C20 |
| 2. 口述转写 | 专家讲 10～15 分钟，Agent 整理成知识卡片 | 看一遍、改错 | 常见坑、案例、经验数值 | C13 最小版 |
| 3. 公开依据预填 | 用采集机拿到的原文先搭框架和依据部分 | 只补“公司怎么做” | 制度模板、方法论 | C12、C20 |
| 4. 候选列表勾选 | 先列 10～15 个候选 | 勾 3～5 个 | 槽位规格、评测集 | C10、A24 |
| 5. 从改稿里挖 | 对比初稿和专家改后稿，归纳反复改的地方 | 确认是否普遍规律 | 常见坑、评审清单、术语 | F4 最小版 |
| 6. 结构化追问 | 带区间和选项追问 | 选或给数加适用条件 | 经验数值、判断规则 | C13 最小版 |

交互要点：

- 卡片式确认：采纳 / 修改 / 驳回，可批量；卡上写出处、依据、把握程度、还缺什么。
- 填空不写作文：专家可以直接贴零散文字。
- 首页只显示“今天 30 分钟能做完的事”，按章节就绪度从低到高排。
- 每确认一条，就绪度随之上涨。
- 每条知识记贡献人。

B17 先做确认队列，其余交互放四期 B23。

三条红线：

1. 机器草稿只进候选，公司做法类必须专家确认才进检索。
2. 防止“顺手点采纳”：定期抽查已采纳条目；修改率长期接近 0 时提醒。
3. 历史交付物先在平台外脱敏、替换成虚拟客户才能进来，过 `guard` 和起草预审。

### 7. 经验萃取只由事件触发

信号 → 先查后问三道过滤 → 打分 → 每人每周 ≤ 3 题 → 超时与跳过收尾。三期只做“缺槽专题访谈”最小版（由章节缺槽触发）；四期开前 3 类信号（知识不足卡、改稿聚类、评审驳回）；五期开其余 5 类。

### 8. 人机交互

- 知识专家不碰命令行，只用一个“我的任务”，每天约 25 分钟。
- 顾问在写稿页侧栏问和改，插入时保留来源。写稿助手分三期上线：三期侧栏问答，四期选中即改与 @ 引用，五期评审意见挂原文。
- D1、D2 在四期表单化。
- 项目驾驶舱与交付件页在四期改版（2026-11-25）：五导航、按产品配置生成的全景、调研四渠道与答案池、自动化分工，见 `docs/驾驶舱改版方案.md`。
