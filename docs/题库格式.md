# 题库格式 v1（三期 E1）

对应 `docs/4A架构设计.md` 3.5 调研架构：题库每题挂控制项，规则选题可复现，评分锚定不进调研包与自评包。平台读取题库的代码属四期（调研助手）；v1 先定格式、出内容，格式自检见 `backend/tests/test_question_bank.py`。

## 目录与文件

- `question_bank/<产品代码小写>.yaml`，一个产品一个文件：`soc.yaml`、`ire.yaml`。产品必须存在于 `products/<产品>.yaml`。
- 内容为公开方法版草稿（`status: draft`、`expert_review: pending`），待产品专家复核；不含客户信息，不写测评、认证结论。

## 文件头字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| product | 是 | 产品代码，如 SOC、IRE |
| version | 是 | 题库版本，如 v1 |
| status / expert_review | 是 | draft / pending；复核后改 ready / done |
| domains | 是 | 控制域，须与产品配置 `baseline.domains` 一致 |
| controls | 是 | 控制项列表：`id`、`name`、`domain` |

控制项 id 形如 `SOC.ORG.01`，符合知识库 `control_ids` 的写法（大写字母、数字和 `. _ -`，至多 32 位，见 `backend/app/kb/items.py` 的 `check_control_ids`），以便知识条目、题目和差距分析按同一编号对齐。控制项目录归公司控制项库统一维护，v1 暂随题库文件定义。

## 题目字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 是 | `<产品>-<域缩写>-<三位序号>`，全库唯一，发布后不复用 |
| product | 是 | 同文件头 |
| domain | 是 | 属于 `domains` 之一，且等于所挂控制项的域 |
| control_ids | 是 | 控制项 id 列表（至少 1 个），须在 `controls` 中定义 |
| kind | 是 | `closed`（封闭题，选项锚定可观察状态，程序可直转事实）或 `open`（开放题，由调研助手整理） |
| stem | 是 | 题干，面向受访者，用“请说明、目前”等口吻，不用审计或评判口吻；对客只说“提前了解情况” |
| options | 封闭题 | 由弱到强的可观察状态，`key`（A～D）、`level`（1～4）、`text`；末位固定 `X` “不清楚”（`level: null`），用于统计“不清楚”率 |
| anchors | 是 | 评分锚点：`level` 加 `state`（可观察状态）。封闭题与 `options` 的 level 对应；开放题至少 3 档。仅内部使用，不进调研包与自评包 |
| followups | 是（可空列表） | 追问，只在受访者回答后由访谈者或调研助手使用 |
| depth | 是 | 适用深度档，取值 `quick`（快检）、`full`（全面）、`deep`（深度）；与 4A 2.5 对应，档位是包含关系由选题规则决定，题目只声明自己适用哪些档 |
| respondent_roles | 是 | 建议受访角色：安全负责人、运营值班、安全分析、IT运维、业务负责人、合规风控、管理层 |
| prefill | 是（可空列表） | 预填来源 `source`：asset_list、org_chart、policy_docs、siem_stats、ticket_export、runbooks、prior_report、incident_record、self_assessment、none。有预填来源的题，现场只确认和追问矛盾 |
| industry_variants | 否 | 行业变体：`industry`（行业包代码，如 BANK、POWER，对应 `industries/*.yaml`）、`stem`、`followups`。命中行业时替换题干与追问，术语以行业包 `terms` 为准；控制项、选项与锚点不变 |
| problem | 是 | “问题题”标记，v1 一律 `false`。运行时由判断数据（事实确认单修改、“不清楚”率高等）自动置位，内容作者不手工标记；置位后调研助手提示改写或复核 |
| source | 否（v1 不用） | 补充题（Agent 建议）标 `added`，采纳前不评分；v1 全为人工编写 |

## 写作规则

1. 对客口径：题干不出现“审计、不合格、通过测评、认证”等评判措辞；不出具等保测评、密评、认证结论。
2. 只问状态与类别，不索取口令、密钥、可利用的漏洞细节、完整网络拓扑和 IP 规划、业务数据与个人信息样本（机密级，两档都不收）；系统数据只要统计与配置摘要。
3. 选项写“可观察的状态”（有无书面、是否执行、是否有记录），不写“好、较好”等主观档。
4. 虚拟示例才可出现客户名，只用 BANK-A、GRID-B、MFG-C 一类代号。
5. 题目增删改走 PR；改题不改 id，语义变化则新增 id、旧题标 `deprecated: true`（v1 暂无）。

## 与其他部件的衔接（四期接入点）

- 选题：按产品、深度档、控制域、行业、受访角色筛选，规则可复现（同一画像得到同一题单）。
- 预填：按 `prefill` 与收到的资料匹配，命中的题标“已预填，待确认”。
- 事实转换：封闭题的选项直转 D3 事实，证据编号指向调研记录；开放题由调研助手整理。
- 判断数据：事实确认单修改（题目、修改类型）记在题 id 上，驱动 `problem` 置位。
