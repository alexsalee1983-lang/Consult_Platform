# 渗透测试报告（M5 ⑦，平台自测）

本报告是开发阶段的自测记录，不是第三方渗透测试结论；上线前公司另做渗透检查（决策记录 2026-11-13）。全部使用虚拟数据（BANK-A、GRID-B、MFG-C 和测试临时项目）。

- 时间：2026-11-13
- 范围：后端全部 103 个接口、Agent 工具层、机密级检测、文件上传与解析、Word 导出、前端与现场工具的输出转义、nginx 安全响应头、登录与会话
- 方法：代码审阅 + 自动化测试（`backend/tests/test_pentest_fuzz.py` 进 CI，以后每次提交都跑）+ 定向探测；测试机上的 ZAP 基线扫描见第 4 节

## 1. 发现与修复

| 编号 | 问题 | 等级 | 状态 |
|---|---|---|---|
| P-01 | 机密级检测可被绕过：全角数字和字母（中文输入法常见）、零宽字符、分段写法的手机号（138-1234-5678）和银行卡号（4 位一组）都检测不到；正常写文档也会漏判，关系红线 3 | 高 | 已修复 |
| P-02 | 写入类工具可经调试接口 `POST /api/agents/{agent}/tools/{tool}` 直接调用：业务用户能冒用 Agent 身份写交付件章节（`doc.generate`）、发确认卡（`confirm.create`）。审计记的是真人，但界面上显示为 Agent 所写 | 中 | 已修复 |
| P-03 | 交付件正文、标题能存进控制字符（如 \x00、\x0b），此后这份交付件导出 Word 一直返回 500；PostgreSQL 写入 \x00 也会报错 | 中 | 已修复 |
| P-04 | 路径里的编号填超出数据库整数范围的值（如 25 位数字），会话、交付链运行、删除申请、知识版本、后台任务等 10 多个接口返回 500 | 低 | 已修复 |

修复方式：

- P-01：`services/guard.py` 检测前先规范化：全角转半角，去掉 Unicode Cf 类格式字符（零宽空格等）。命中位置换回原文位置。新增手机号、银行卡号的分段写法规则。回归用例在 `tests/test_guard.py`，含不误拦日期、标准条款号、普通数字的用例。
- P-02：调试接口只允许读取类工具（`tools.access = read`）；写入类返回 403，并记审计 `tool.call` blocked（reason=write_via_api）。写入类工具只由平台运行时调用（Agent 对话、交付链）。
- P-03：全局依赖 `core/errors.reject_control_chars` 检查 JSON 请求体和查询参数，含控制字符（保留制表、换行、回车）、孤立代理项、U+FFFE/U+FFFF 时返回 422，不回显输入。导出时另外过滤一遍，兜底库里已有的旧数据。
- P-04：`OverflowError`（SQLite）和 `DataError`（PostgreSQL：数值越界、字符串超长）统一按 422 返回，不回显输入。

## 2. 已检查、未发现问题

| 项目 | 结论 |
|---|---|
| 未登录访问 | 公开接口只有 health 和 login，其余 401（`test_auth.py` 的 PROTECTED 列表覆盖全部接口） |
| CSRF | 修改类请求都要带 `X-CSRF-Token`；Cookie 设置了 HttpOnly 和 SameSite=Strict，生产环境加 Secure |
| 越权访问（IDOR） | 所有按编号取对象的接口都核对了所属项目、发起人或可见范围：会话、确认卡、评审、运行、同意记录、摘要卡、证据、投料、知识版本、删除申请。非成员 404（`test_permissions.py` 矩阵） |
| 提示词注入 | Agent 调用工具时，项目代号由平台给出、不取模型输出；工具层按 Agent × 工具授权、区域硬规则和真人用户的项目成员身份判断。所以证据里夹带的指令最多影响本项目草稿内容，草稿要经人工审阅、质量门禁和签署 |
| SQL 注入 | 全部经 ORM 或绑定参数；检索里动态拼接的只有固定的条件片段 |
| XSS | 前端没有 `dangerouslySetInnerHTML`；现场工具的 innerHTML 插值都经 `esc()`，页面 CSP 禁止一切网络请求和内联脚本 |
| 上传与解析 | 文件类型按文件头判断，20MB 上限；docx 检查解压后总大小（防压缩炸弹）；PDF 有页数上限，加密 PDF 拒收；python-docx 不解析外部实体；对象存储的键不用原文件名 |
| Word 导出 | 脚注、正文都通过 lxml 赋值写入，不拼接 XML；下载文件名只用项目代号和交付件编号 |
| 登录 | 口令 argon2 校验，用户不存在时也做一次比对（响应时间一致）；TOTP 有防重放（`totp_last_step`）；连续失败锁定；登录后服务端生成新会话 |
| 安全响应头 | CSP、X-Frame-Options DENY、nosniff、Referrer-Policy、Permissions-Policy、COOP；HTTPS 时加 HSTS；`server_tokens off` |
| 模糊测试 | 全部接口 × 3 类角色（业务、系统管理员、审计员）× 异常路径参数（路径穿越、SQL 片段、超长、超大整数、空字节）× 异常请求体（按接口模式生成极值、超长字符串、畸形 JSON）：修复后没有 500 |

## 3. 低风险观察（不修，记录在案）

| 编号 | 观察 | 处理 |
|---|---|---|
| O-01 | 账号锁定期间，登录提示“已锁定”，和普通失败提示不同，能据此判断账号存在。但要先对这个账号连续输错若干次才会出现 | 接受：内网系统，锁定提示便于用户自助判断 |
| O-02 | 任何人连续输错可锁定他人账号（锁定类拒绝服务） | 接受：锁定有时限，审计和告警（⑤）能发现；生产经堡垒机或限制来源网段访问 |
| O-03 | 登录失败计数和 TOTP 防重放没加行锁，并发请求可能多试一两次，或同一验证码并发换出两个会话（仍要口令正确） | 接受：口令 argon2 校验本身慢，影响很小 |
| O-04 | 后端调试端口映射到本机 127.0.0.1:8000，绕过 nginx 时可以自带 X-Real-IP 头，伪造审计里的来源地址 | 生产部署手册（⑧）写明去掉调试端口映射 |
| O-05 | 系统管理员可在网页上重置另一名系统管理员的口令 | 接受：三权分立只要求管理员与审计员互斥；操作写审计，审计员可查 |
