## 一、目标与验收

主题：生产上线、SOC 试点，打好五个地基——知识数据结构、知识采集与建设流水线、评审严格度、写稿助手 v1、知识就绪度。
采集和建设同期上线：只采不建会堆积原料，只建不采则无料可加工。
知识就绪度是 v6.0 新增的地基：交付链最缺公司做法类知识（模板、方法、常见坑、案例、黄金样例），先定槽位规格和章节级评测集，再由 Agent 起草、专家确认，最后用就绪度验收。
为腾出人力，D1/D2 表单（A14）、统一配置登记（G3）、AI 质量事件台账（F3）在四期；B28 多语言与海外法规整体移到四期，含最小版（负责人 2026-11-22 定）。

v3.0 验收标准（12 条）：

1. 生产环境运行（退路：测试机验收，上线顺延，不阻塞四期）
2. SOC 试点项目走完交付链（没有真实项目时用虚拟客户并标明）
3. 四格（SOC、IRE × 银行、电力）行业包达到 L1
4. 9 个 Agent 全部上线，评测不退化（对照二期 Z4 的 37 题真模型基线，每题 3 轮多数判定）
5. 异构评审生效，平台强制校验
6. 指标精简版出数
7. 知识数据结构迁移完成，旧编号仍可引用，已签署交付件不受影响
8. SOC × 银行知识流水线跑通：采集 → 提炼 → 挂载 → 审核 → 候选 → 发布，实测自动发布率和人工分钟 / 百条，编造条款号为 0
9. SOC 8 个关键章节就绪度 ≥ 70%（依据类槽位 ≥ 95%），章节级装配命中率高于固定查询基线，缺槽发卡
10. 阻断只有封闭五类，增量评审生效
11. 写稿助手 v1 可用（侧栏问答、插入保留来源，插入内容照样过签署门禁）
12. 知识持续获取五步在测试环境用虚拟缺口跑通；下发包只有网址与规则

## 二、设计要点（影响三期开发的部分）

- **Agent 9 个**：咨询协调、调研访谈、依据与差距分析、方案与制度设计、报告与客户沟通（含异议应答）、质量评审（只做评审）、知识采集（采集机区，新拆出）、知识建设与萃取、知识审核。脱敏审查降为工具层。生成类用 DeepSeek，审核类用 GLM，分歧由 Kimi 仲裁，采集初筛用小模型。
- **知识以控制项为主轴**：产品、行业、控制项为多值标签；知识编号只做序号（`KB-000123`）；控制项中枢以公开框架起草，法务确认后以 SCF 为起点。
- **槽位与就绪度**：交付链每个章节声明所需的知识槽位（依据、模板、方法、案例、常见坑、经验数值），以及每槽所需条数和挂哪些控制项；按“产品 × 行业 × 控制项”装配，缺槽在动笔前提示，不硬写。
- **就绪度口径**：槽位内已发布（不含候选）、类型匹配且未被标“不对 / 过时”的条目达到规格条数，这个槽就算就绪；章节就绪度 = 就绪槽位 ÷ 槽位总数。
- **截断按知识类型分配额度**：模板、案例不再截成 300 字。
- **流水线**：发现 → 获取 → 解析 → 提炼 → 挂载 → 合成 → 审核 → 评测 → 保鲜。平台不联网，采集在隔离采集机上，经单向通道导入。公开来源 ≥ 90% 自动发布，先进候选影子期；公司做法和黄金样例必须由专家拍板。
- **来源分工**：标准、法规原文由采集机取、自动核验后发布；条文解读和标准间映射由采集机和 Agent 起草、知识审核 Agent 审、专家抽检；公开基准数据只作参考并标出处；交付模板、方法论、案例、常见坑、黄金样例、公司经验数值和章节槽位规格**只能靠人**（Agent 或规划会话起草、专家确认）。
- **严格度**：阻断只有封闭五类（编造或用错依据、资质用语、机密与客户信息、对客结论无证据、与已确认事项矛盾）；按交付件分评审档案；增量评审。
- **对机器严、对人松**：Agent 产出的引用必须能解析、条文必须一致；专家输入只拦三类（引用不存在或错误、资质用语、机密与客户信息），其余给建议，格式问题自动修。
- **Agent 起草、专家确认的六种方式**：从旧交付物反向提炼（C20）、口述转写（C13 最小版）、公开依据预填（C12、C20）、候选列表勾选（C10、A24）、从改稿里挖（F4 最小版）、结构化追问（C13 最小版）。
- **专家交互**：卡片式确认（采纳 / 修改 / 驳回，可批量，卡上写出处、依据、把握程度、还缺什么）；填空不写作文；首页只显示“今天 30 分钟能做完的事”，按章节就绪度从低到高排；每条知识记贡献人。三期 B17 先做确认队列，其余交互放四期 B23。
- **三条红线**：① 机器草稿只进候选，公司做法类必须专家确认才进检索；② 定期抽查已采纳条目，修改率长期接近 0 时提醒，防止“顺手点采纳”；③ 历史交付物先在平台外脱敏、替换成虚拟客户才能进来，过 `guard` 和起草预审。
- **经验萃取只由事件触发**：三期只做“缺槽专题访谈”最小版（由章节缺槽触发），四期开前 3 类信号，五期开其余 5 类。
- **两条硬边界不变**：知识侧 Agent 不能访问项目区，交付侧 Agent 不能写知识区。“生成补库任务”“改稿生成知识更新草稿”“改稿特征表”由平台程序完成。

### 获取触发模型（B25 的发起逻辑）

负责人 2026-11-22 要求系统考虑什么驱动知识库建设 Agent 发起获取，按以下四点做。

**1. 五类触发源**

| 触发源 | 信号 | 验收 |
|---|---|---|
| 定时巡检（每周） | 知识地图健康度：覆盖空白、过期条目比例、单一来源条目；各领域条目数与目标差距 | 每周任务自动跑，结果进缺口池；无缺口时只记一条运行记录 |
| 外部变化 | 已收法规 / 标准的修订、废止、征求意见稿、新发布（采集机按白名单定期比对官网目录和哈希）；执法通报新增；临近生效日、过渡期截止日提前提醒（建议提前 90 天、30 天两档） | 虚拟官网目录变更能在一个巡检周期内进缺口池；临近日期提醒按档触发 |
| 使用信号 | 对话答不上来或依据“待核实”；顾问标“过时 / 不对”（B29）；检索零命中；评测失败题 | 四种信号都能落到缺口池并能回溯到来源事件（只记编号、长度、摘要哈希，不记原文） |
| 业务需求 | 新立项涉及的地区 / 行业 / 标准库里没有；新产品或模块配置引用但库里缺失；售前机会涉及新地区；章节缺槽（A24 报出的槽位未就绪） | 立项与配置保存时自动比对，缺口进池；不阻塞立项 |
| 生命周期 | 条目到复核期；来源失效（网址失效、被替代） | 到期条目与失效来源每周进池；被替代的同时触发 B26 |

**2. 统一进“缺口池”**

- 去重合并：同一来源、同一依据的多个信号合为一个缺口，保留信号次数与来源事件列表。
- 打分排序：影响面（引用该缺口的在办项目与交付件数）、紧急度（生效日 / 截止日临近）、权威等级（B27）、信号次数，加权得分，权重可配。
- 每类触发源设阈值，未达阈值只累积不发起。
- 验收：同一来源的重复信号合并后只剩一个缺口；排序测试覆盖四个因子；未达阈值的缺口不生成清单。

**3. 出口**

- 高于阈值的缺口由知识库建设 Agent 生成知识源清单，进知识审批队列“来源确认”类。
- 法规修订且来源已在白名单（B16 正式状态）的，属已批准来源，直接下发采集机自动采集，只在入库审核把关（自动化优先，人只处理例外）。
- 新来源、新网站必须人确认，未确认的不下发。
- 验收：白名单内修订不进“来源确认”队列、直接出采集任务；白名单外来源一律停在队列；两条路径都有审计记录。

**4. 节流与闭环**

- 节流：每周生成清单与采集任务设批量上限（可配），采集机单并发。
- 每个缺口记录关闭条件：入库后对应评测题通过或检索命中；满足即自动关闭，超期未关闭的升到“我的任务”（B17）。
- 关闭率、平均关闭时长进知识地图健康看板（F2）。
- 验收：超出周上限的缺口顺延到下周且不丢；关闭条件由程序判定；看板出两项指标。

### 生产内网下的单向通道（负责人 2026-11-22 定）

生产平台不联网（第八节第 5 条），清单下发（平台 → 采集机）与结果回传（采集机 → 平台）需要单向通道。决定：三期生产用③人工介质：采集结果按批导出、附哈希清单，每周一次拷入内网，平台核对哈希后入库；同时向公司网络或安全部门问有无现成的内外网文件交换系统，有则四期改为②边界中转点；①经资料仓中转排除（生产不能联网）；测试环境沿用资料仓中转。三个选项的优缺点保留如下。

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| ① 经资料仓中转 | 平台把确认过的网址与规则推到私有资料仓，采集机拉取；采集结果推资料仓，平台侧导入机拉取并核对哈希清单 | 与测试环境现做法一致，改动最小；全程有版本记录 | 生产内网要能访问外部代码托管，等于开一条出网路径，需公司网络与安全部门批准 |
| ② 内网边界中转点 | 在公司网络边界（DMZ）设中转目录，只允许采集机写入结果、平台读取；下发方向另设只读目录 | 不依赖外部托管；可自动化；方向可由网络策略强制 | 要公司网络部门建设和运维中转点；需安全评审 |
| ③ 人工介质摆渡 | 知识管理员定期用加密介质双向拷贝，导入时核对哈希清单 | 无需开网络路径，隔离最强 | 有人工环节，违反自动化优先，频率受限（更新延迟以周计）；介质管理有丢失风险 |
