## 一、目标与验收

主题：生产上线、打穿起步，同时打好四个地基——知识数据结构、知识采集与建设流水线、评审严格度、写稿助手 v1。采集和建设同期上线：只采不建会堆积原料，只建不采则无料可加工。为腾出人力，D1/D2 表单（C3）、统一配置登记（G3）、AI 质量事件台账（F3）移到四期。

v3.0 验收标准（11 条）：

1. 生产环境运行（退路：测试机验收，上线顺延，不阻塞四期）
2. SOC 试点项目走完交付链（没有真实项目时用虚拟客户并标明）
3. 四格（SOC、IRE × 银行、电力）行业包达到 L1
4. 9 个 Agent 全部上线，评测不退化（对照二期 Z4 的 37 题真模型基线）
5. 异构评审生效，平台强制校验
6. 指标精简版出数
7. 知识数据结构迁移完成，旧编号仍可引用，已签署交付件不受影响
8. SOC × 银行知识流水线跑通：采集 → 提炼 → 挂载 → 审核 → 候选 → 发布，实测自动发布率和人工分钟 / 百条，编造条款号为 0
9. SOC 产品按知识清单装配跑通，缺知识发卡
10. 阻断只有封闭五类，增量评审生效
11. 写稿助手 v1 可用（侧栏问答、插入保留来源）

## 二、设计要点（影响三期开发的部分）

- **Agent 9 个**：咨询协调、调研访谈、依据与差距分析、方案与制度设计、报告与客户沟通（含异议应答）、质量评审（只做评审）、知识采集（采集机区，新拆出）、知识建设与萃取、知识审核。脱敏审查降为工具层。生成类用 DeepSeek，审核类用 GLM，分歧由 Kimi 仲裁，采集初筛用小模型。
- **知识以控制项为主轴**：产品、行业、控制项为多值标签；doc_id 只做序号；控制项中枢以 SCF 为起点（许可待法务）。交付链每步声明知识槽位，按“产品 × 行业 × 控制项”装配，缺知识发卡，不硬写。
- **流水线**：发现 → 获取 → 解析 → 提炼 → 挂载 → 合成 → 审核 → 评测 → 保鲜。平台不联网，采集在隔离采集机上，经资料仓单向导入。公开来源 ≥ 90% 自动发布，公司做法和黄金样例由专家拍板。
- **严格度**：阻断只有封闭五类（编造或用错依据、资质用语、机密与客户信息、对客结论无证据、与已确认事项矛盾）；按交付件分评审档案；增量评审。
- **两条硬边界不变**：知识侧 Agent 不能访问项目区，交付侧 Agent 不能写知识区。“生成补库任务”“改稿生成知识更新草稿”“改稿特征表”由平台程序完成。

## 六、已定决策（负责人 2026-11-21“同意”，v5.0 第十节）

1. 采纳 v5.0 分期方案（本文件即其三期部分）；四、五期计划另建
2. Agent 由 8 个改为 9 个：拆出知识采集、质量评审只做评审、异议应答并入报告与客户沟通（C6、C9、C11）

5. 阻断改为封闭五类、按交付件评审档案（改 qa-reviewer md）；公开来源合规审核程序化（A13、C9、B20）
6. 编辑器换代与写稿助手分期：v1 三期、v2 四期、v3 五期（A15）
7. 法务三问：判断数据采集、SCF 许可、国标全文入库（F1、B19、B21）

说明：改进清单第十一节把 W3、W4（选中即改、@ 引用）、C3（D1/D2 表单）、P6（访谈模式）列为三期，v5.0 为腾人力已移到四期（A16、A14、C13），本计划以 v5.0 为准。
