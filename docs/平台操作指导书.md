# 平台操作指导书

版本 1.1（2026-11-16）。写给平台的全部使用者：顾问、项目经理、咨询业务负责人、知识专家、知识管理员、系统管理员和安全审计员。按“谁、在哪个页面、做什么”写，读者不需要懂代码。

- 知识侧的完整做法见《知识管理指导书》。
- 用一个虚拟项目从立项走到删除的示范见《专家交付指导书》。
- 各角色只做哪些事见《人工职责清单》。

本书反映二期 11-16 已合并的功能。还没上线的功能列在第十节，不要按它们操作。

## 一、先记住的五条

1. **不收机密级内容。** 口令、密钥、可利用的漏洞细节、完整网络拓扑与 IP 规划、业务数据和个人信息样本，两档项目都不收。被拦截后删掉这些内容再传，**不要换个写法绕过**。
2. **只写客户代号。** 平台里只写 BANK-A 这类代号，不写客户真实名称。访谈纪要只写受访者角色，不写姓名。
3. **不出结论性用语。** 不写“通过等保测评”“符合密评要求”“可获得认证”，统一用“差距分析、符合性初判、整改建议”。质量评审会把这类用语判为阻断。
4. **Agent 写初稿，人签字负责。** 平台能自动做的都自动做；人负责投料、拍板、审核和签署。
5. **两人原则。** 去标识确认、知识发布审核、删除确认都要由两个不同的人完成。系统会把你不能处理的事项置灰。

## 二、登录与账号

| 事 | 怎么做 |
|---|---|
| 首次登录 | 用系统管理员给的账号和初始口令登录，按提示绑定手机动态码（TOTP），再改口令。改口令前只能访问“修改口令”页 |
| 日常登录 | 账号 + 口令 + 动态码。30 分钟不操作自动退出 |
| 忘记口令、换手机、账号锁定 | 找系统管理员 |
| 长期不用 | 超过规定天数没登录的账号会被平台自动停用，找系统管理员启用 |

## 三、角色与页面

左侧导航按你持有的角色显示，没有的页面看不到。

| 角色 | 能看到的页面 |
|---|---|
| 顾问（consultant） | 我的任务、我的项目、项目驾驶舱、交付件审阅、顾问对话、知识检索、投料箱 |
| 项目经理（项目内的 manager） | 同顾问；另外在自己管理的项目里能调整成员、签署、退回、驳回评审意见、登记验收和客户书面文件 |
| 咨询业务负责人（project_lead） | 另有“项目总览”“资料删除”，能在“我的项目”新建项目 |
| 知识专家（knowledge_expert） | 知识检索、投料箱、审批队列、知识地图与健康 |
| 知识管理员（knowledge_admin） | 同知识专家；负责去标识确认、合规审核 |
| 系统管理员 | 用户与角色、模型配置状态。看不到任何业务数据 |
| 安全审计员 | 审计日志。看不到业务数据；只能由运维用命令行授予 |

系统管理员、安全审计员与其他角色互斥。非项目成员看不到项目，地址也打不开。

## 四、每天的习惯：先看我的任务

我的任务把你身上各角色的待办汇总在一处（原“工作台”已并入，负责人 2026-11-25），按影响 × 不确定度排好，超出每日额度的折叠。
顶部筛选条按类型计数，点一类只看该类，再点一次取消：

1. 确认卡
2. 待签署
3. 知识内容审核（点“去处理”进专家工作台对应的问答卡）
4. 知识合规审核
5. 待复审
6. 去标识确认
7. 资料删除确认

按规则你不能处理的（你是作者、上传者或发起人，要另一个人来做）放在底部“须由别人处理”折叠区，每项写明须谁处理。
目标是每天清空自己的待办。

## 五、交付侧：一个项目从立项到删除

### 1. 立项（咨询业务负责人，“我的项目”→“新建项目”）

1. 填客户代号（如 BANK-A，不写真名）和行业。
2. **定档**：
   - **标准档**：客户资料可以进入平台。
   - **严格档**：资料不出客户现场，平台只收客户书面同意后的去标识摘要卡。

   依据合同和客户的数据要求（《客户数据告知模板与合同条款》）定档，拿不准时按严格档。
3. **选服务产品、勾模块**：
   - 平台记下当时的配置版本（快照），以后配置改了也不影响这个项目。
   - 产品配置还在草稿状态的，界面会标出来。
4. 指定首位项目经理。平台自动建好交付件 D1～D8。

### 2. 组建团队（项目经理，项目驾驶舱“项目成员”）

加减成员、指定其他项目经理。只有成员能看到项目。

### 3. 上传证据（顾问，项目驾驶舱“项目证据”）

| 证据 | 编号 | 要点 |
|---|---|---|
| 客户资料 | D-xx | 支持 Word、PDF（文字版）、Markdown、文本；扫描件不收（不做 OCR），请客户提供文字版 |
| 访谈纪要 | I-xx | 只写受访者角色；记事实和原话要点，矛盾和拿不到证据的地方如实记下。可以从 .docx / .md / .txt 文件导入正文，文件本身不保存 |
| 现场观察 | O-xx | 写看到的现象，不写 IP、账号 |

- 编号一经分配不变、不复用。
- **改名、删除**：录入人或项目经理可以改名、删除传错的证据。删除后编号保留、内容清空，不可撤销；已签署交付件引用的不能删。
- **仅现场使用**：客户书面通知某份资料只能留在现场时，项目经理标“仅现场使用”，填文号（不写客户名）。不可撤销，平台立即删除原件和解析结果，以后不能引用。

### 4. 交付链（平台自动发起，也可手动）

- **自动发起**：项目还没跑过交付链、交付件还没有正文、证据齐了（资料都已解析），而且最近 2 小时没有新证据，平台会自动发起。
- **手动发起**：在项目驾驶舱“交付链 · Agent 组”点“运行交付链”。同一项目同时只能有一次运行。
- 步骤按产品配置走，例如 SOC：事实清单（D3）→ 差距分析 → 目标运营模型 → 制度（D6）→ 报告和汇报材料（D4、D5、D7、D8）。
- 每一步 Agent 只经平台工具读证据、查知识库，写进对应交付件的章节；每次写入都是新版本，旧版本保留。

### 5. 处理确认卡（顾问，我的任务或项目驾驶舱）

- Agent 遇到方案取舍、来源冲突、证据不足、范围确认，会发确认卡并停下来等人。
- 处理方式：选一个选项，或者写意见。**处理后不能改**，想清楚再点。
- 等待的卡处理完，交付链自动继续，你的处理结果会交给后续步骤，本次运行不再问同一问题。
- “证据不足”卡的正确做法是**补证据**，不是让 Agent 推测。
- 推荐理由不成立时，不要照着推荐选，写明你的意见。

### 6. 顾问对话（顾问对话页）

- **统一从咨询师 Agent 进入**：点“＋ 新对话”就是和咨询师 Agent 对话。它了解项目情况，回答问题，必要时建议转交给专业 Agent。
- **转交**：回复末尾出现“转交给 XX Agent”按钮时，点它，平台新建一个与该 Agent 的对话，并把交接说明作为草稿放进输入框。你确认或修改后再发送，不会自动发给模型。
- 熟悉的顾问也可以展开“直接找专业 Agent…”自己选，一般不需要。
- 对话只有你自己能看到；离开项目后也看不到。

### 7. 审改交付件（交付件审阅页）

逐章读 Agent 初稿，重点看：

- **来源标注**：每条结论后面要有 `[I-01]` `[D-12]` `[O-05]`（严格档 `[S-02]`）、知识条目或 `[推断]`。核对不上的编号在质量评审里判阻断；整章只有推断的判重要。
- **【依据待核实】**：知识库里查不到依据时 Agent 会这样标。对照原文核实后改成正式引用，并告诉知识专家补库。
- **锋利度**：把放之四海而皆准的通用话，改成针对本客户事实的结论。
- **知识更新提醒**：章节引用的知识条目出了新版本或下线时，交付件概览会提示。改写该章后提醒消失。

### 8. 质量评审与签署

1. **评审自动发起**：
   - Agent 写完后立即评审；
   - 顾问修改后，24 小时没再改也会自动评审；
   - 也可以手动点“质量评审”。
2. 评审由平台规则和质量评审 Agent 一起做，结论是通过、修改后通过或不通过。
3. **驳回阻断**：项目经理可以驳回 Agent 提出的阻断，理由至少 10 个字，要具体（例：“已核对原文第 8.1.3 条，Agent 误判”）。平台规则判出的阻断（缺正文、机密级、结论用语、来源核对不上、引用已下线或已废止的依据）**不能驳回**，只能改正文。
4. **提交签署**：D1、D2、D6、D8 门禁通过后平台自动提交签署（提交人记“平台”）；D3、D4、D5、D7（事实清单、差距分析、目标方案、路线图）门禁通过后停在起草中，由顾问看过评审标出的问题后手动提交（决策记录 2026-11-18）。任何交付件都可由成员手动提交。待签署期间改正文会自动退回起草。
5. **签署或退回**：项目经理签署，或写理由退回。**签署后只读，不能撤销**，签前请通读全文。签署门禁会再实时查一次依据有没有下线或废止。
6. **导出 Word**：未签署的每页页眉标“草稿”，**不要把草稿发给客户**。来源标注会转成 Word 脚注。

### 9. 验收与保留期（项目经理）

在项目驾驶舱“验收与保留期”登记验收日和保留月数（默认 6 个月，按合同调整，0～24）。平台算出到期日，项目列表显示保留状态：保留中、30 天内到期、已到期。可以更正，每次都进审计。

### 10. 删除

- **到期删除**：平台每小时扫描，自动发起到期项目的删除申请。
- **客户要求提前删除**：项目经理凭客户书面要求发起，填文号（不写客户名），10 个工作日内完成。
- **确认**：由咨询业务负责人在“资料删除”页确认，不能是发起人。确认时必选经验回流情况：已回流（填投料编号）、无可回流、客户不同意回流。回流要在确认前做完。
- 删除后项目代号不复用，删除记录（编号、日期、计数、确认人、回流情况）可以直接交给客户。

## 六、严格档额外要做的

严格档相关功能二期放低优先级（决策记录 2026-11-16），现有功能可用：

1. 项目经理登记客户书面同意（文号 + 签署日期）。没有有效同意，不能上传摘要卡，也不能运行交付链。
2. 在客户现场用离线现场工具 `field-tool/field-tool.html` 整理摘要卡：机构、人员、系统一律用占位符（【客户】【人员1】【系统A】），不写真名、IP、域名、产品名和版本号，不引原话。对照表只存在加密工作文件里，**只留现场**。
3. 摘要卡经客户审阅后整批上传，任何一张不过检查整批拒收。
4. Agent 输出一律用占位符；出现真名、网络标识、系统名、原话判阻断。
5. 客户书面撤回同意时，项目经理登记撤回，平台清空摘要卡和据此写成的未签署内容；已签署的保留。

## 七、咨询业务负责人

- **项目总览**：看全部项目的元数据（档位、阶段、交付件进度、保留期）。不是成员的看不到项目内容，需要进入时请项目经理把你加为成员。
- **立项**：见第五节第 1 步。
- **删除确认**：见第五节第 10 步。

## 八、知识侧速览

详细做法见《知识管理指导书》。日常页面：

| 页面 | 谁用 | 做什么 |
|---|---|---|
| 知识检索 | 所有业务角色 | 按关键词、标准号或条号查已发布知识 |
| 投料箱 | 顾问、知识专家 | 上传项目沉淀、专家经验等原料，填来源和授权编号；看去标识报告 |
| 审批队列 | 知识专家、知识管理员 | 内容审核、合规审核、抽检、待复查、复审到期 |
| 知识地图与健康 | 知识专家、知识管理员 | 覆盖矩阵、缺口 TOP、问题率、自动发布占比、贡献统计 |

顾问能为知识库做的最有价值的事：项目结束时把做得好的部分去标识后投料，并在删除确认时记下回流。

## 九、管理与运维

| 角色 | 在哪里 | 做什么 |
|---|---|---|
| 系统管理员 | 用户与角色 | 建账号、授予或收回角色、启用停用、重置口令和动态码 |
| 系统管理员 | 模型配置状态 | 看大模型、向量、重排的地址、模型名、是否外部和连通状态（只读，不显示密钥） |
| 安全审计员 | 审计日志 | 查谁在什么时候做了什么。审计只记编号、计数和结论，不记客户原文 |
| 运维 | 部署机命令行 | 首个管理员、审计员授予、立项应急、备份恢复、知识批量入库，见 CLAUDE.md“常用命令”和《运维手册》 |

平台每天自检、每小时扫描到期删除和知识复审；自检失败、删除逾期、备份超过 26 小时会告警（《监控》）。

## 十一、出了问题找谁

| 情况 | 找谁 |
|---|---|
| 账号锁定、忘记口令、动态码失效 | 系统管理员 |
| 被机密级检测误拦截 | 先自查口令、IP 等内容；确属误拦截，告诉系统管理员是哪一类，**不要转发原文** |
| 交付链停住不动 | 先看我的任务有没有待处理的确认卡；再看是否缺证据或资料还在解析 |
| Agent 输出明显错误、反复犯同一个错 | 记下项目代号、交付件、章节和版本号，交给咨询业务负责人 |
| 客户提出删除、撤回同意、仅现场使用 | 项目经理按第五、六节操作，书面文件存档在平台以外 |
| 怀疑有客户信息泄露 | 立即报咨询业务负责人和安全审计员 |
