| 核心产品（新增） | 网络安全治理规划 | 完整交付包 + 交付链 |

## 三、核心设计：从 SOC 写死到按服务产品配置

| 配置项 | 产品配置写什么 | 模块能追加什么 |
|---|---|---|
| 交付件清单 | 编号、名称、阶段、是否对客、默认大纲 | 在某个交付件里追加章节 |
| 交付链步骤 | 步骤、负责 Agent、输入和输出的交付件、提示词模板 | 一般不加步骤 |
| 评估基线与维度 | 能力域（事实清单分组）、对标框架、依据集合 | 追加依据和对标项 |
| 质量门禁 | 产品特有的硬规则（如 ISO 27001 的 SoA 覆盖附录 A 全部 93 项） | 追加规则 |
| 知识检索 | 按“服务产品”元数据过滤，先查本产品、再查通用 | 追加标签 |
| 严格档 | 摘要卡评估项、严格档提示规则（第十节修订 ②） | 追加评估项 |

设计原则：

1. **配置放在仓库里**（`products/*.yaml`、`modules/*.yaml`），和 Agent md 一样版本化，改配置走 PR、负责人审批；二期不做网页编辑。
2. **立项即冻结**：项目记下产品和模块的配置版本（内容哈希），之后配置改版不影响进行中的项目。
3. **Agent 不按产品增加**：按交付环节分工；各 Agent md 改为“通用骨架 + 产品模块”，运行时只拼入本项目产品和模块的段落。
4. **SOC 是第一份配置**：先把现有写死的 SOC 搬成配置，现有项目迁移为“产品 = SOC”，M3、M4 验收用例全部重跑通过，再加新产品。

## 四、工作分解

A、B 线的代码和 C2 归开发线 1（平台代码）；B1 的内容、C1 / C3 / C4 的 md 与评测题、D 线的配置草稿和知识归开发线 2（内容与评测）；专家审改贯穿 B1、C3、D 线。

### A 线 · 产品配置与交付链

| # | 任务 | 说明 |
|---|---|---|
| A1 | 产品与模块配置格式 | `products/*.yaml` `modules/*.yaml` 的结构和校验（CI 校验测试）；写进 `docs/接口约定.md`。知识元数据“服务产品”取值（`app/kb/meta.py`）同步扩充，改取值要同步公共规范第 7 节、经负责人同意 |
| A2 | SOC 搬成配置 | 交付件名称、交付链步骤、提示词和检索词里的 SOC 维度移到 `products/soc.yaml`；现有项目迁移为产品 = SOC；单独一个 PR，只搬不改；M3、M4 验收用例全部重跑 |
| A3 | 立项快照与网页立项 | 立项选产品、勾模块，记下配置版本；网页立项；项目驾驶舱、交付件页的交付件清单按项目快照显示（不再默认 D1～D8 固定） |
| A4 | 交付链引擎读配置 | 步骤常量改为读项目快照；提示词模板化 |
| A5 | 交付链补全 D5～D8 | 第 5 步方案设计（D5、D7）、第 6 步制度起草（D6）、第 7 步汇报（D8）；方案取舍发确认卡暂停 |
| A6 | 门禁规则按产品 | 平台硬规则分“通用 + 产品 + 模块”三层；测评 / 认证结论用语规则留在通用层 |
| A7 | Agent 自主调用工具 | 对话改用 function calling，取代“提问前检索注入”。**有条件**：公司模型支持工具调用才做，排在 12 月第 3 周；不支持就二期不做 |
| A8 | 严格档按产品 | 摘要卡评估项、`STRICT_RULES`、占位符检查、现场工具模板随产品配置；改了规则照旧跑 `update_field_tool_checks.py` 两边核对 |

### B 线 · 知识服务与运营

| # | 任务 | 说明 |
|---|---|---|
| B1 | M2 收尾 | 约 300 条业界知识、正式评测题（11-27 前出初稿）、门槛校准，打 v0.2 |

### C 线 · Agent 组

| # | 任务 | 说明 |
|---|---|---|
| C1 | Agent md 改为“通用骨架 + 产品模块” | 先改一个 Agent 做样板，负责人确认结构后其余一次性审批；运行时只拼入本项目产品和模块的段落 |
| C2 | 对话中由咨询师 Agent 转交专业 Agent | 调研访谈、报告与汇报、项目交付管理一期已是独立 Agent（迁移 0006，交付链在用）；未做的是对话里咨询师 Agent 仍“按模式自己完成”。二期改为转交，补授权与权限矩阵测试（第十节修订 ①） |

### D 线 · 产品接入

每个新产品走同一套：① 产品配置 → ② 交付件默认大纲和 Word 章节 → ③ Agent 模块 → ④ 公开资料知识入库 → ⑤ 虚拟客户素材和端到端验收。

顺序：D1 ISO 27001（标准最清楚，验证配置格式，顺带启动映射矩阵）→ D2 数据安全（与 ISO 27001 共用制度母版）→ D3 事件后 E2E（与 SOC 共用证据和事件知识）→ D4 治理规划（最依赖专家，萃取工作坊 11 月底前开始）→ D5 三个模块跟在对应产品后面。
