## 三、环境

### 测试机
- Windows 上的 WSL `Ubuntu-24.04`，仓库在 `~/consult_platform_m1`；在 Ubuntu 终端里、这个目录下执行命令。
- 端口：网页 `18080`（`WEB_PORT`），后端调试 `127.0.0.1:18000`（`BACKEND_DEBUG_PORT`）。8080/8000 被同机的 SecAssess 占用。浏览器在测试机本机开 `http://localhost:18080`；别的电脑暂时访问不了（WSL 端口没转发到局域网）。
- 代理：`http://172.26.192.1:2081`。Docker 守护进程已配这个代理拉镜像；**构建时**用 `docker compose build --build-arg HTTP_PROXY=... --build-arg HTTPS_PROXY=...`，**不要**在 Dockerfile 里声明这几个 ARG，也不要改 `~/.docker/config.json` 的 proxies。拉基础镜像超时就先 `docker pull` 再构建；日常构建不要加 `--no-cache`（会全量重下依赖，很慢）。
- 测试机 `~/.docker/config.json` 会把代理注入容器；compose 里已给 backend、worker 显式设 `NO_PROXY`（内部服务一律直连），新增内部服务时要加进去。
- 模型：**当前接 DeepSeek 官方 API**（`LLM_EXTERNAL=true`），只用虚拟数据和公开资料；严格档项目（GRID-B）对话会被拒绝，属正常。切回模拟模型：`.env` 里 `LLM_BASE_URL=http://mock-llm:8000/v1`、`LLM_EXTERNAL=false`、删掉 `LLM_API_KEY`，再 `docker compose --profile mock-llm up -d --force-recreate backend worker`。**密钥由负责人自己填在测试机 `.env`，不经任何聊天。**
- 向量服务：`embed` 容器（`BAAI/bge-small-zh-v1.5`，512 维，CPU），模型在镜像里，运行时不联网。
- 重排服务：`rerank` 容器（`BAAI/bge-reranker-v2-m3-int8`，CPU，镜像约 0.6 GB 模型），同样运行时不联网；启动要加载模型几十秒，期间健康检查里 `rerank` 显示 down。开发电脑（4 核）上 20 个候选约 3 秒一次，测试机耗时待测。

## 四、流程约定（对话里定下的做法）

- 开发助手：开分支 → 写代码和测试 → 推送 → CI 全绿 → 开 PR，PR 描述写清“怎么测”（按测试机没有浏览器写成 curl / 命令行）。
- 给测试助手的说明要能直接转发：写明分支、是否先备份、构建命令、重点步骤、“测完发评论，不要合并，不要删分支”。
- **合并由负责人说了才做**（“合并 #N”）。用普通合并，不用 squash。
- **叠加的 PR（目标分支是另一个 PR 的分支）**：合并下层 PR 后，**先**把上层 PR 的目标分支改成 `main`，**再**删除下层分支；先删分支会把上层 PR 自动关掉（发生过一次）。
- 迁移链：同时开着的 PR 如果都加迁移，后开的要接在先开的后面（`down_revision`），并把目标分支设成先开的那个 PR 的分支，避免迁移分叉成两个头。
- CI 的 gitleaks 扫**全部分支**的历史：某个分支上的误报会让 `main` 和其他 PR 一起变红。误报处理见 `docs/安全扫描.md`；`.gitleaks.toml` 只为 `knowledge/**/*.md` 里整行 `key: 标识` 放行。
- 测试助手登录：**每个账号只登录一次、各用一份 cookie 文件（/tmp/cp_<账号>.txt）全程复用**；同一 30 秒内同一账号重复登录会被防重放拒绝并计入失败次数，5 次锁 15 分钟（曾因此空等两小时）。失败不自动重试，被锁用 `python -m app.cli unlock --username <账号>`。
- 接口调用（curl / 脚本）：修改类请求要带 `X-CSRF-Token` 头，值在登录响应或 `/api/auth/me` 的 `csrf_token` 字段里，不在 cookie 里（`CLAUDE.md` 登录约定）。
- 测试数据只用虚拟客户（BANK-A、GRID-B、MFG-C）和公开资料；口令、密钥、动态码密钥不进评论、不进聊天、不打印。

## 五、踩过的坑（避免重犯）

| 现象 | 原因 | 处理 |
|---|---|---|
| 测试机构建拉镜像每秒几 KB | 代理节点临时故障 | 重试一次；仍慢再测速定位 |
| 后端访问 embed 被绕到外部代理 | 宿主机代理注入容器，`NO_PROXY` 不含新服务 | compose 显式设 `NO_PROXY` |
| 镜像历史里出现代理地址 | Dockerfile 显式声明了 `ARG HTTP_PROXY` | 不声明（预定义参数不进历史） |
| 冒烟测试“普通文件上传”偶发 422“银行卡号” | 用纳秒时间戳去重，19 位数字偶尔通过 Luhn 校验 | 改用 UUID |
| 依据查询永远返回一条弱相关结果 | 向量检索没有相似度下限 | 加下限，依据查询更严 |
| 页面“项目不存在” | 登录账号不是该项目成员（权限隔离正常） | 用项目成员账号，或让项目经理在驾驶舱加成员 |
| `.env` 某项不生效 | 写成了 `KEY==value` | 只用一个等号，不加引号和空格 |
| 宿主机 `export` 的变量容器里没有 | compose 用 `env_file: .env`，不读宿主机环境 | 写进 `.env` 后重建容器；临时试值用 `docker compose run --rm -e KEY=值` |
| 依据查询门槛 0.55 误杀正例 | 向量化文本加前缀后整体分数下移，正例最低降到 0.50 | 定门槛：先列正例最低分、负例最高分，看是否交叉；不交叉就在空隙里取离两边都有余量的值（0.5 离正例只差 0.002，所以取 0.48），别凭经验值 |
| 误判“门槛无解、要加关键词加分” | 把 search 模式的负例分数（0.542）当成了 basis 的 | basis 和 search 的正负例分数分开统计，各定各的门槛 |
| 测试中途 backend、worker 被停启，网页 502 | 测试机上 SecAssess 靶场的 `boot-start.sh` 按容器名匹配执行 `docker compose start`，把本平台的容器也停启了 | 测试前确认它没在运行；出现 502 先等它跑完（约 110 秒）、全部服务 healthy 后再测，期间结果作废 |
| 工具通道全部返回 422“kind 只能是…”之类，看着像参数编码不对 | `POST /api/agents/{agent}/tools/{tool}` 的请求体是 `{"project_code": …, "args": {…}}`，工具参数必须放在 `args` 里；平铺在顶层时 `args` 是空的 | 参数一律包在 `args` 里（#39 测试时踩到） |
| 测试机调 DeepSeek 超时，代理端口能连但不转发 | 宿主机代理 `172.26.192.1:2081` 卡住 | 请负责人重启代理；临时办法是在 `/tmp` 下用 compose override 把 `api.deepseek.com` 加进 `NO_PROXY` 直连，不改仓库文件（#38 测试时踩到） |
| 重排服务刚启动时被判 unhealthy | int8 模型加载超过 60 秒的健康检查宽限 | 宽限放到 180 秒（#34） |
| 对话输出时输入框抖动 | 每段字触发一次平滑滚动、整页随内容变长 | 对话区固定高度、内部滚动（#26） |
