## 一、为什么改

负责人 11-28：“整个 D1～D8 输出链条太过死板，人输入和机器输出都没有明确清楚。”具体是三个问题：

1. **输入散**：输入挂在单个交付件下（D1 表单、D2 表单），合同只在 D1 抽几个字段后即删，客户做什么、输入什么没有写清。
2. **输出窄**：交付件 = 一份 Word；Agent 只输出成段文字，上游一变只能整章重写，定制化只能靠改稿。
3. **驾驶舱乱**：五个导航页按数据流分，全景按阶段 × 角色分，交付件两处都出现，相互关系看不出来。

## 二、总原则

1. **人提供信息和决定，机器负责成文**；人仍参与审稿与改稿，改稿助手让人改得快、改一次管全项目。
2. **确定的用程序，判断与表达用模型**。D1、D2 内容相对确定，走程序模板，不调模型；D3～D8 由 Agent 经网关起草，但先输出结构化数据，程序校验后再渲染。
3. **先有数据，再有文档**：结构化数据是唯一真源，Word / PPT / Excel 都是它的视图，改一处三处同步。
4. **黄金样例定基线，定制项定差异**：每份输出附“相对基线的差异说明”。
5. **输入按来源组织**：合同、客户、顾问 / 项目经理、选填材料；每张输入卡 = 结构化字段 + 参考样例 + “其他信息 / 要求”。
6. **驾驶舱每页只放一类东西**：全景 = 时间线；输入 = 输入物；需求 = 定制项与决定；分析 = 事实与发现；输出 = 产出。

## 三、五层结构

| 层 | 内容 | 谁 |
|---|---|---|
| ① 输入层 | 合同要点卡、客户输入物、顾问 / 项目经理输入卡、选填材料、对话补充 | 人（客户经顾问带入） |
| ② 需求层 | 项目定制项（长期生效）、修订指令（一次性）、决定记录（范围、取舍、确认卡结果） | 平台归类，人确认生效 |
| ③ 基线层 | 产品大纲与槽位规格、输出包组件清单、黄金样例、公司做法、行业包、法规依据 | 公司（知识中心） |
| ④ 生成层 | 输出规格 = 基线组件 ± 定制项；程序 / Agent 按第六节分工生成结构化数据 | 平台 + Agent |
| ⑤ 输出层 | 每个交付件一个**输出包**：数据表 + 文稿 + 汇报 + 客户用表单，附变化摘要、差异说明、待处理卡 | 平台 |

之后是质量门禁（程序规则 + 评审 Agent + 定制项逐条核对）→ 人审稿、改稿、签署 → 客户确认。

**“其他信息 / 要求”栏**：自由文本由 Agent 拆成三类，回显给填写人确认后才生效：事实 → 事实库；决定 → 决定记录；要求 → 定制项或修订指令。

**定制项优先级**（11-27 已定，不变）：红线与资质 ＞ 客户书面 ＞ 项目定制项 ＞ 行业 ＞ 公司做法与黄金样例 ＞ 默认大纲；越线标“不可接受”。结构类（增删章节、增删组件）须项目经理确认。

## 四、输入：四个来源

### 4.1 合同要点卡（立项时，项目基础数据）

合同导入从 D1 表单前移到**立项**（A28② 的抽取能力复用）：Agent 抽成结构化要点卡，项目经理核对后保存，全程保留；合同原文照旧抽取后删除。严格档不上传合同，项目经理手填要点卡。

| 要点 | 驱动 |
|---|---|
| 目标、范围、不包含项 | D1 范围确认单、调研范围、全程范围检查（输出越出范围提示） |
| 交付件清单与验收标准 | 输出包组件、质量门禁、验收阶段逐条对照 |
| 周期、里程碑、付款节点 | 关口日期、进度预测 |
| 数据处理档位、保留期、是否参与经验积累 | 立项设置、删除计划、结项复盘入口 |
| 授权与同意（见 4.6） | 关口 1 进入条件、资料导入许可、结项沉淀许可 |
| 客户书面要求、保密条款 | 项目定制项 |
| 双方角色与对接人 | 成员、调研受访角色 |

**字段状态**：每个要点标“已核对 / 合同未写明 / 待与客户澄清 / 合同外新增”。

**要点卡体检**（程序规则为主，核对时提示，不阻断，资质边界一条除外）：
- 资质边界：出现“等保测评结论、密评结论、认证结论”等字样，标“不可接受”，须改为差距分析、符合性初判口径后才能保存；
- 验收标准能否逐条对照（不可量化的提示改写）；
- 付款节点是否与验收节点绑定；
- 周期是否短于同产品黄金样例的工期；
- 交付件清单与产品默认组件是否一致；
- 档位信号：客户属国有大行、电力生产控制区、政府涉密或敏感单位，合同却写标准档；
- 保留期、返还与销毁条款是否与已签保密协议冲突。

**合同不明确时怎么成稿**：“未写明 / 待澄清”字段自动生成**需求澄清清单**，每题附 2～3 个推荐选项（取自同产品黄金样例）和售前材料里的痛点，项目经理拿去开启动会或沟通会引导客户选择；会议纪要导入后由 Agent 拆成事实 / 决定 / 要求，回显确认；结论写进 D1 范围确认单，客户签字后固定。成稿不依赖合同写全。

**要点卡规则检查只显示例外**：检查通过的项不显示（只留一行“其余自动检查已通过”）；资质边界字样命中即阻断保存；其余提示项需要客户回答的转成澄清题，只需项目经理知道的（如工期偏紧）进“待我处理”。

**澄清题怎么生成**（客户不登录平台，澄清只能“出题 → 开会 → 导入纪要”；人只做会上问、会后确认冲突两件事）：

| 步骤 | 谁做 | 内容 |
|---|---|---|
| 输入 | — | 要点卡中“合同未写明 / 待澄清”字段；规则检查提示项；售前材料中的客户原话与痛点；同产品黄金样例；产品默认组件（交付件、份数、工期） |
| 找缺口 | 程序规则 | 逐字段比对，列出要问的点；规则查过没问题的不出题 |
| 出题 | 交付项目经理 Agent | 每个缺口一道单选题，2～3 个选项取自黄金样例，标推荐与理由（引样例条数、售前原话）；写明影响哪个交付件、哪个关口；按影响排序、合并重复 |
| 检查 | 程序规则 | 机密级检测；资质边界用语 |
| 输出 | — | 澄清清单（Word 一页，可直接作会议议程）；全景“待我处理”出现一条 |
| 回收 | 项目经理 | 导入会议纪要，或会上直接勾选 |
| 对题抽答案 | 交付项目经理 Agent | 答案明确且不冲突的自动回填；含糊或与合同、售前材料矛盾的出确认卡；没答到的留在清单，到关口仍没有则按推荐项起草并标“按默认写法”；客户新提且超出合同的起草变更单 |
| 固定 | 客户 | 结论写进 D1 范围确认单，客户签字后固定；进“需求”页成为定制项或决定；要点卡不改 |

**在哪里调整**：
- 合同要点卡只反映合同本身，只有补充协议才出新版本（旧版保留，下游标“需更新”）；
- 客户需求的细化与变化进“需求”页（定制项、决定记录），每条标来源：客户书面 / 会议纪要 / 对话；
- 超出合同范围的临时需求标“合同外”，生成**变更单**（影响哪些交付件、工期、组件），项目经理确认；涉及商务的提示走补充协议，补充协议签后才转为定制项。

### 4.2 客户：做什么、输入什么

客户不登录平台，平台不对外发信；客户输入由顾问经文件导入、加密自评包、现场工具或代录带入，全部过 `guard`。

| 阶段 | 客户做什么 | 输入物 |
|---|---|---|
| 启动 | 签合同与数据处理附件；指定对接人；参加启动会 | 附件一 / 二、对接人与受访角色名单、范围确认 |
| 调研 · 场前 | 按资料需求清单交资料；填自评包；确认排期 | 资料、自评答卷、排期 |
| 调研 · 现场 | 受访；演示与现场查看；确认预填答案 | 口述、现场证据 |
| 调研 · 离场 | 补证 | 补充资料 |
| 分析 | 审阅 D4、听分析汇报 | 客户意见（自动拆条） |
| 设计 | 给约束；审阅 D5～D7 | 编制上限、预算区间、现有工具、制度格式规范、客户意见 |
| 验收 | 签收、验收 | 验收确认、满意度反馈 |
| 保留期 | 必要时 | 删除请求、撤回同意 |

### 4.3 顾问 / 项目经理：只给人才知道的信息和决定

D1 / D2 表单中合同没有的部分；现场访谈与矛盾定案；低置信事实与发现确认；方案取舍；客户约束的转述；对话中的定制要求；改稿；签署。

### 4.4 选填材料（有就导入，缺了不阻断）

售前材料（建议书、需求沟通纪要：痛点与期望）；监管检查意见、审计发现（差距分析最有力的依据）；上一期项目报告（续签）；客户现有制度清单（D6 判断新建 / 修订 / 保留）。

### 4.5 输入卡规范

- 三栏：必填（只留必须由人确认的）/ 选填 / 其他信息与要求。
- 每个字段旁给参考样例（取自同产品、同行业黄金样例），能预填的已预填并标来源。
- 输入不足不猜：必填缺失发“补资料卡”；选填缺失按黄金样例默认写法起草并标“按默认写法”。

### 4.6 授权与同意（授权台账）

我方是受托处理方、客户是处理者（《个人信息保护法》第 21 条委托处理）。对客户说明的口径是“AI 辅助起草，顾问逐份审核、签署并负责”，不逐页标注 AI；依据是附件一和附件三第 X.1 条。

合同要点卡内设“授权与同意”一节，即项目的授权台账，只记签署状态，不存附件正文：

| 授权 | 何时签 | 平台用途 |
|---|---|---|
| 附件三合同条款 | 随合同 | 关口 1 进入条件 |
| 附件一（标准档） | 随合同 | 关口 1 进入条件 |
| 附件二（严格档） | 启动会逐项确认、单独签字 | 未签不得导入任何资料或摘要卡 |
| 去标识经验积累同意（X.4） | 随合同勾选，可撤回 | 未同意或已撤回时，结项复盘不能提交沉淀候选 |
| 严格档摘要卡书面同意 | 每份摘要卡 | 沿用摘要卡约定 |
| 中途转严格处理通知 | 随时 | 对应文档标“仅现场使用” |
| 删除请求、撤回同意 | 保留期内随时 | 触发删除流程、出具删除证明 |

每条记：版本、签署日期、记录人；变更留历史，审计只记事件，不记原文。

待法务：附件一增加“受访员工的个人信息告知由客户以用人单位身份负责”，与“法务审核要点”第 2 条一并定；客户的个人信息保护影响评估（第 55 条），我方提供一份标准安全措施说明配合。附件文本改动须法务确认后另提。

### 4.7 先行启动（合同未签先启动交付）

客户常要求合同签订前先开工。立项页提供“合同未签，先行启动”选项：

- **立项依据**：至少上传一份依据（中标通知书、委托函、建议书、售前沟通纪要、客户确认范围的邮件），Agent 同样抽成要点卡，整卡标“先行启动 · 待合同确认”，每个字段标出处。
- **谁批**：项目经理勾选后，部门负责人一键确认（不签合同就投入人力是商务风险，须由人担责）；确认前项目只能做准备工作。
- **授权不先行**：附件一、附件三签署前，客户资料一律拒收，只能做不碰客户数据的准备（D1 草稿、调研包、排期与受访名单）；授权签署后可正常调研。这条与合同是否签订无关（数据保护红线）。
- **提醒**：全景顶部常驻“先行启动第 N 天 · 合同未签”；“待我处理”出现“催合同”；满 30 天未签自动升级提醒部门负责人（天数可配置）。
- **合同到达**：上传合同，Agent 将正式要点卡与临时卡逐字段比对——一致的自动转正；范围、验收标准有变化的出确认卡；超出合同的部分起草变更单；受影响的交付件标“需更新”（复用上游变更机制）。
- **不可越过**：合同未签不能出 D8 验收、不能结项；其他交付照常推进。


## 五、调研包怎么生成

D2 调研包由平台在**输出**页生成，是 D2 输出包的一部分；输入页只放回收物：已收资料、自评答卷、现场答卷。调研助手只用于现场，本身不出题，使用访谈提纲、现场议程和预填答案，把现场答案回传到答案池。

一个题池，每道题挂评估项、只走一个渠道：资料答过的不进自评，自评答清楚的现场只做快速确认，不重复问客户。

| 输入 | 来源 | 用途 |
|---|---|---|
| 范围、不包含项、评估基线框架 | 合同要点卡 / D1 | 决定评估域 |
| 评估项与题库、行业补充题 | 产品配置、行业包 | 候选题 |
| 受访角色与人员、时间窗 | D2 表单 | 按角色分题、排期 |
| 客户重点关注、不访谈范围 | D2 表单 / 定制项 | 加题、减题 |
| 已收客户资料 | 证据库 | 预填答案，资料能答的不当面问 |
| 同类项目调研提纲 | 黄金样例 | 题目写法与深度参考 |

输出：每角色调研包（每题标渠道：资料预填 / 客户自评 / 现场题卡 / 开放讨论）、客户自评包、资料需求清单；自评导入后生成现场议程。

| 渠道 | 产物 | 何时、给谁 | 回收到 |
|---|---|---|---|
| 资料预填 | 资料需求清单 | 场前，顾问发客户 | 输入页 · 客户资料 |
| 客户自评 | 客户自评包（加密离线网页 + Excel 兜底） | 场前，顾问用公司邮箱发 | 输入页 · 自评答卷 |
| 现场题卡 | 每角色访谈提纲；自评收回后生成现场议程（矛盾、不清楚、开放题） | 现场，调研助手按场次排题卡；D2 输出包可导出打印 | 调研助手回传 → 输入页 · 现场答卷 |
| 开放讨论 | 议程中的讨论题 | 现场 | 同上 |

四个渠道的答案按评估项合并进答案池 → D3 事实清单。

## 六、逐个交付件：人输入、机器输出、生成方式

| 交付件 | 人输入（谁） | 生成方式 | 输出包 |
|---|---|---|---|
| **D1 启动包** | 项目经理：核对合同要点；补客户痛点、已知风险；其他 | **程序模板**（固定段程序写入） | 范围确认单（客户签字版）、工作计划与里程碑（表 + 甘特）、启动会 PPT、定制项清单、资料需求初单、前提与风险清单 |

## 七、审稿与改稿（人参与改）

1. **先告诉人看哪里**：打开交付件先给按风险排序的审阅清单——低置信结论、无来源句子、与定制项不符、偏离黄金样例、门禁提醒；点一条跳到位置；第二轮起只高亮本轮变化。
2. **三种改法**：直接改字；选中一段用一句话提要求（给 2～3 种改法一键选用）；整章 / 整件用对话提要求。
3. **改动意图识别与扩散**：

| 人改的是 | 平台处理 |
|---|---|
| 事实错误 | 回写事实库，引用该事实的章节和交付件标“需更新” |
| 口径（称呼、视角、详略） | 问“全项目都这样改？”，确认后转定制项 |
| 措辞 | 只改这一处 |

4. **人工定稿不被覆盖**：人改过的段落标“人工定稿”，Agent 刷新时跳过；上游变化时只提示并给建议改法，由人决定。
5. **就地来源**：悬停看依据与证据，一键补来源（A16③）；修订痕迹逐条接受 / 回退。
6. **学习**：改稿记录进 F4 改稿特征表，下次起草减少同类修改；修改率按月看趋势。
7. **四条回路统一进“修订指令”队列**：签署人退回、客户意见、上游变更、顾问对话。签署后只能发起勘误，走同一条路。

## 八、驾驶舱结构

### 8.1 每页一类东西

**导航形态**（示意 11）：最左窄栏放全局入口（工作台、项目、知识、健康）；第二栏为项目栏——项目卡（名称、档位、进度环）、全景、“输入 → 需求 → 分析 → 输出”竖向交付链（已完成绿点、当前琥珀点、带待办数）、D1～D8 挂在“输出”下带状态点、调研助手、设置；新建项目在项目栏顶部。不用横向分页：四个环节是先后流程，竖排能看出走到哪；D1～D8 需要二级；切页时全景始终可见。

**全景三块**（首屏只回答“在哪个关口、还差什么、卡在谁”）：① 顶部一行：进度环、“第 N 周 · 某阶段”、过关口还差几件、按期 / 预警；先行启动时挂提示条。② 关口进度线：横向 5 个关口（按产品配置），已过段绿色、进行中段流动虚线、当前关口脉冲，点关口跳对应页。③ “过关口还差”卡片（每张进度条 + 卡在谁手里，含客户）与“待我处理”（一行一件事，带“只看我的”）。后台自动完成的事不上全景，只进健康看板；系统设置减少动画时动画关闭。

| 页 | 放什么 |
|---|---|
| 全景 | 见上“全景三块”；不做阶段 × 角色矩阵，卡住的事挂“卡在谁手里”（项目经理 / 顾问 / 签署人 / 客户） |
| 输入 | 全部输入物，按来源分组：合同要点卡（含授权台账）/ 客户（资料、自评答卷）/ 现场答卷 / 顾问输入卡 / 选填材料；调研包不在此页，在输出页 D2 |
| 需求 | 项目定制项、修订指令、决定记录、变更单；每条标来源与生效状态（新增页） |
| 分析 | 事实（带证据）、发现（事实 + 依据 → 差距、影响、优先级）、证据缺口、待定矛盾；界面统一叫法：客户侧“证据”，规范侧“依据” |
| 输出 | D1～D8 输出包、阶段包、结项复盘；“需更新”提示；阶段包一键导出 |
| 设置 | 成员与写签分工、档位、保留期、结项与删除 |
| 交付件页（挂在输出下） | D1～D8 与结项复盘每个都有，结构相同（示意只画 D1 代表程序模板类、D4 代表审稿改稿类）：审阅清单 / 正文（修订痕迹、人工定稿标记）/ 改稿助手 / 差异说明 / 版本 / 导出；四模式不变 |
| 调研助手（全屏，不进导航） | 现场：快速确认 → 议程 → 补问 → 回传；入口：输出页 D2、全景与“待我处理”的当天现场待办、我的项目中现场阶段的项目 |

**导出**：交付件页输出包区每个组件可下载 Word / PPT / Excel，输出页阶段包一键导出；未签署带“草稿”水印，签署后出正式版（沿用导出约定）。D3～D8 不是 Agent 直出：结构化数据 → 程序校验渲染 → 质量门禁 → 人审稿、改稿、签署后才能出正式版。

**顾问入口收敛**：
- 一个对话入口：顾问对话改为驾驶舱右侧抽屉，在哪页打开就带哪页上下文，同一项目同一会话（独立的顾问对话屏保留给不进项目的问答）；
- 一个待办入口：“待我处理”汇总确认卡、补资料卡、审阅清单、签署、变更单；
- 就地改稿保留：直接改字、选中一段提要求；
- 所有入口进来的要求进同一个修订指令 / 定制项队列，回显确认后生效。

### 8.2 主链与关口

| 关口 | 进入条件（输入到齐） | 退出条件 |
|---|---|---|
| 1 启动 | 合同要点卡已核对；授权台账：附件三与附件一（严格档附件二）已签 | D1 已签、客户确认范围 |
| 2 调研 | D1 范围、D2 角色、调研包已发布 | 答案池入齐、D3 已签 |
| 3 分析 | 事实已确认 | 发现表确认、D4 已签、客户意见处理完（v1.1） |
| 4 设计 | 发现已确认、方案取舍卡已答、客户约束已录 | D5～D7 已签、客户审阅完 |
| 5 验收 | D4 / D5 / D7 已签 | D8 已签、对照合同验收标准逐条通过、结项复盘已提交（或写理由跳过） |

依赖连线表示“上游变，下游标需更新”：合同要点卡 → 立项设置、D1、定制项；D1 + 产品评估项 + D2 + 客户资料 → 调研包 → 答案池 → 事实 → D3；事实 + 依据 → 发现 → D4；发现 + 取舍 + 约束 → D5 / D6 / D7；D4 / D5 / D7 → D8 → 验收 → 结项复盘 → 结项 → 保留期到期删除。定制项横贯全程。

### 8.3 结项（两步提交，与结项分开）

1. **预览去标识结果**：逐条看将交给知识中心的候选内容，可修改、取消勾选；经验积累同意未签或已撤回时，此步不可用，只能选“本项目无可沉淀”。
2. **提交知识中心**：预览后才可点；确认去标识由项目经理担责，记审计。
3. **本项目无可沉淀**：单独按钮，须写理由，计入跳过率。
4. **结项**：复盘提交（或跳过）后，在设置页“结项与删除”点结项；结项前给核对清单（D1～D8 签署、验收标准逐条、客户确认凭证、未处理修订指令）。

### 8.4 其他流程

| 情形 | 处理 |
|---|---|
| 客户意见 | 客户不登录；顾问导入客户批注过的 Word，按批注自动拆条、对到章节，进修订指令队列 |
| 客户签字凭证 | 范围确认单、验收单签字页回传只记“已签”状态、日期、页数和摘要哈希，不存正文；过 `guard` |
| 项目暂停 / 终止 / 提前结项 | 暂停冻结关口与提醒；终止或提前结项写原因，跳到结项复盘（可跳过），随即生成删除计划 |
| 人员变动 | 换人生成交接摘要（未完成待办、未签交付件）；重新校验写签分离 |
| 续签项目 | 上一期数据按保留期已删，只能导入客户提供的上期报告（选填材料），不回读平台旧数据 |
| 严格档输出包 | PPT / Excel 同样只用占位符；现场替换方式随“现场工具形态”待决定事项定 |
