# 运维手册（M5 ⑧）

面向平台运维人员（能在部署机上执行 `docker compose` 的账号）和系统管理员。命令都在仓库根目录（`/srv/consult-platform`）执行。
口令、密钥、动态码一律不贴到聊天、工单、PR 里；命令行工具都是交互输入口令。

## 一、日常巡检

| 频率 | 做什么 | 命令 / 位置 |
|---|---|---|
| 每日 | 服务状态、健康检查 | `docker compose ps`；`curl -fsS https://<域名>/api/health`（各项 ok） |
| 每日 | 备份是否成功 | 备份日志、`docs/备份与恢复.md` 的检查项 |
| 每日 | 告警 | Grafana / 告警接收渠道（`docs/监控.md`） |
| 每周 | 后台任务积压、失败 | `docker compose exec backend python -m app.cli jobs` |
| 每周 | 平台自检（配置、存储、模型、向量、重排） | `docker compose exec backend python -m app.cli selfcheck` |
| 每周 | 审计哈希链 | `docker compose exec backend python -m app.cli verify-audit`（有问题退出码 2，立即上报） |
| 每月 | 大模型用量 | `docker compose exec backend python -m app.cli usage-report --days 30` |
| 每月 | 保留期与删除申请 | `retention-report`、`deletion-report`（见第五节） |
| 每月 | 账户清理：长期未登录（用户页标注，默认 90 天）、离职人员 | 系统管理员在“用户与角色”页停用 |
| 每月 | 磁盘空间、数据库膨胀 | `df -h`；第六节 VACUUM |
| 每季度 | 恢复演练 | `docs/备份与恢复.md` |
| 每季度 | 镜像漏洞、依赖更新 | 拉取新版本按第八节升级；CI 的 trivy / pip-audit / npm audit 结果（`docs/安全扫描.md`） |

## 二、启停与日志

```bash
docker compose up -d                       # 启动 / 按配置重建有变化的服务
docker compose restart backend worker       # 改了 .env 后用 up -d（restart 不重新读 .env）
docker compose stop                         # 停止（数据卷保留）
docker compose logs --no-color --since 1h backend worker | tail -200
```

日志不含客户原文、口令和密钥；排错时把相关日志行发给开发前仍要先看一遍。**不要执行 `docker compose down -v`**（会删除数据卷）。

worker 可横向扩展：`docker compose up -d --scale worker=2`，任务不会重复执行。

## 三、用户与账号

日常在网页“用户与角色”页由系统管理员操作（新建、停用、改角色、重置口令）。命令行用于首个管理员、审计员任命和应急：

```bash
docker compose exec backend python -m app.cli list-users
docker compose exec backend python -m app.cli create-user --username <名字> --display-name <姓名>
docker compose exec backend python -m app.cli grant-role --username <名字> --role security_auditor   # 审计员只能这样授予
docker compose exec backend python -m app.cli revoke-role --username <名字> --role <角色>
docker compose exec backend python -m app.cli unlock --username <名字>        # 连续输错被锁
docker compose exec backend python -m app.cli reset-totp --username <名字>    # 换手机、丢失动态码
```

- 口令有效期默认 90 天（`PASSWORD_MAX_AGE_DAYS`），到期登录后先改口令。
- 安全参数（登录锁定次数、会话时长、口令规则和有效期等 `.env` 项）不设单独的安全管理员角色，改动按公司变更流程审批后由运维修改（决策记录 2026-11-14）。
- 系统管理员、安全审计员与业务角色互斥，看不到业务数据。
- 人员离职：当天停用账户；如是项目经理，先由其他项目经理或命令行 `add-member --role manager` 补位。

## 四、项目

```bash
# 立项（一期无网页立项）：必须定档 standard / strict，建 D1～D8，指定首位项目经理
docker compose exec backend python -m app.cli create-project --code <客户代号> --tier standard --manager <名字> [--industry 银行]
# 没有项目经理的项目补位、应急
docker compose exec backend python -m app.cli add-member --project <项目> --username <名字> --role manager
```

项目代号只用客户代号（例如 BANK-A），不用客户真名。严格档项目资料不出现场，平台只收客户书面同意后的去标识摘要卡。

## 五、保留期与删除（兑现对客户的承诺）

依据 `docs/客户数据告知模板与合同条款.md`、决策记录 2026-11-13。

```bash
docker compose exec backend python -m app.cli retention-report [--all]    # 已验收项目的保留期与到期状态
docker compose exec backend python -m app.cli deletion-scan               # 立即扫描到期项目发起删除申请（worker 每小时自动扫描）
docker compose exec backend python -m app.cli deletion-report [--all]     # 未完成的删除申请
```

- 到期删除由平台自动发起，项目负责人在“删除申请”页确认后执行。客户书面要求提前删除的，项目经理发起，**10 个工作日内**完成。
- 运维要做的：每月看 `deletion-report`，有待确认超过 5 个工作日的提醒项目负责人；有执行失败的（后台任务 `project.delete`）看 `jobs` 和日志，修复后任务会重试。
- 删除完成后，删除申请记录就是给客户的删除记录（编号、日期、计数、确认人、回流情况）。
- 备份里的旧数据随备份保留期自然过期，客户问到时按合同条款说明。

## 六、数据库

### 6.1 账号

| 账号 | 用途 |
|---|---|
| `consult`（超级用户） | 只用于本机运维：备份、恢复、建库建账号。不给后端用 |
| `consult_app` | 后端和 worker 连主库；主库和库内对象的属主 |
| `consult_kb` | 后端和 worker 连知识区库 `consult_kb`；连不上主库 |

`consult_app`、`consult_kb` 由 `deploy/postgres/app-init.sh`、`kb-init.sh` 维护（可重复执行），都不是超级用户。生产后端发现自己以超级用户连库会拒绝启动。

改口令：

```bash
# 改 .env 里的 APP_POSTGRES_PASSWORD（或 KB_POSTGRES_PASSWORD）后
docker compose up -d postgres                       # 让容器拿到新口令
docker compose exec postgres app-init.sh             # 或 kb-init.sh，按环境变量重设口令
docker compose up -d backend worker
```

### 6.2 VACUUM 与存储空间回收

项目删除、去标识确认后，数据库行已删除，但物理页要靠 VACUUM 回收（等保自查 8.1.4.11 b）。autovacuum 默认开启，日常无需操作；**每次执行项目删除后、以及每月一次**手工执行：

```bash
docker compose exec postgres vacuumdb -U consult --all --analyze
```

需要把空间还给操作系统时（大量删除后）在维护窗口执行 `vacuumdb -U consult --all --full`（锁表，期间服务不可写）。磁盘报废按公司制度处理。

### 6.3 迁移

后端启动时自动升级两条迁移链（主库 `alembic_version`、知识区 `alembic_version_kb`）。手工执行：`docker compose exec backend python -m app.core.migrate`。迁移失败时后端不启动，看日志第一条错误，不要手工改版本表，联系开发。

### 6.4 审计表

`audit_logs` 只追加，数据库触发器拒绝 UPDATE / DELETE / TRUNCATE。审计记录不删除（网络日志留存不少于 6 个月）。

## 七、知识库

```bash
docker compose exec backend python -m app.cli kb-import /srv/knowledge/<目录> --as <知识专家> [--submit]   # 批量入库（条目文件格式见 backend/app/kb/files.py）
docker compose exec backend python -m app.cli kb-eval /srv/knowledge/eval/samples.yaml --as <用户> [--out /tmp/report.json]
docker compose exec backend python -m app.cli kb-reembed           # 换了向量模型（维度相同）后重新向量化
```

换维度不同的向量模型要开发出迁移，不能只改配置。重排服务不可用时检索自动退回 RRF 排序，健康检查会显示。

## 八、升级

```bash
BACKUP_PASSPHRASE_FILE=/etc/consult-platform/backup.pass bash scripts/backup.sh /srv/backups/consult-platform   # 先备份
git fetch && git checkout <新版本标签>
# 看版本说明：有无新增 .env 项（对照 .env.example）、需要手工执行的脚本
docker compose build && docker compose up -d
docker compose ps && curl -fsS https://<域名>/api/health
docker compose exec backend python -m app.cli verify-audit
```

升级失败回退：`git checkout <旧标签>`、`docker compose up -d --build`；如果新版本已经迁移了数据库，按 `docs/备份与恢复.md` 恢复升级前的备份。

Agent 提示词（`agents/*.md`）随镜像发版，生产不挂载目录。

## 九、密钥与证书

| 项 | 位置 | 轮换 |
|---|---|---|
| TLS 证书 | `TLS_DIR` | 到期前替换，`docker compose restart frontend`（`deploy/tls/README.md`） |
| 动态码种子加密密钥 `TOTP_KEYS` | `.env` | 新密钥放第一位、旧的留后面 → `docker compose up -d backend worker` → `python -m app.cli totp-rekey` → 删掉旧密钥再 `up -d` |
| 对象存储 KMS 主密钥 | `.env` | 一期不轮换；离线保存，丢失则文件无法解密 |
| 模型平台 API 密钥 | `.env` | 按公司模型平台要求，改完 `up -d backend worker` |
| 数据库口令 | `.env` | 见 6.1 |
| 备份口令 | `/etc/consult-platform/backup.pass` | 换口令后旧备份仍用旧口令解密，旧口令保留到旧备份过期 |

## 十、故障处理

| 现象 | 先看 | 处理 |
|---|---|---|
| 网页打不开 | `docker compose ps`、`logs frontend` | 证书路径、端口占用；`APP_ENV=prod` 没证书前端拒绝启动 |
| 后端反复重启 | `logs backend` 第一条错误 | 启动检查（部署手册 2.5）、迁移失败、数据库口令不对 |
| 登录失败 | 审计页（审计员）`auth.login` 的原因 | 锁定 → `unlock`；动态码 → 核对服务器时间、`reset-totp` |
| 对话报“模型暂不可用” | `selfcheck`、健康检查 `llm` 项 | 模型平台地址、密钥、出站防火墙 |
| 解析、向量化、删除不动 | `jobs`、`logs worker` | worker 健康检查；失败任务修复后重试 |
| 检索结果变差 | 健康检查 `rerank`、`embedding` 项 | 重排、向量服务容器状态 |
| `verify-audit` 报错 | 立即上报安全审计员和负责人 | **不要动审计表**，保留现场、按安全事件处理 |
| 磁盘满 | `df -h`、`docker system df` | 清理旧镜像 `docker image prune`，检查日志轮转、备份保留期 |

疑似数据泄露、账号被盗、审计链异常：按公司安全事件流程上报，停用相关账户，保留日志和数据库现场，不自行删除任何数据。

## 十一、恢复

整机故障或数据损坏：新机按部署手册装好同版本 → `restore.sh` 恢复最近备份（清空并覆盖当前数据，要输入目录名确认）→ `verify-audit` 校验审计链与备份清单里的链头哈希一致。详见 `docs/备份与恢复.md`。
