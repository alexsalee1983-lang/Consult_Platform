# 工作项编号登记表

> 工作项编号以本文件为准。起新编号先在本文件登记、随 PR 合并，再在计划、提交和 PR 标题里使用。
> 规划会话在 claude.ai 上的文档只作讨论稿；与本文件不一致时以本文件为准。各期范围与关口见 `docs/总体规划.md`。
> 建立于 2026-11-22，起因是三期计划第九节与 v5.0 规划四期同时用了 B25～B29、C14（见第四节改号记录）。

## 一、规则

1. 前缀：A 交付链与应用、B 知识库、C 内容与 Agent、E 调研、F 运营与治理、G 平台与部署、Z 二期收尾。
2. 各前缀只往后续号，不复用、不回填空号；作废的编号留在表里标“作废”。
3. 一个工作项跨期时，用“最小版 / 完整版”区分，编号不变（先例：三期计划第九节 B27～B29）。
4. 改进项编号（K、S、P、C、Q、H、W、X，见《知识库自动化与人机协同：架构设计与改进清单》第十一节）是另一套，只写在计划表的“改进项”列。C 开头两套都有：引用改进项时写“改进项 C1”。
5. `docs/专家入场工作清单.md` 里的 E1～E14 是专家积压事项的编号，不是工作项；引用时写“积压 E1”，与工作项 E1（题库 v1）、E2（调研助手）区分。
6. 新编号由起草的会话登记；两条开发线、规划会话同时要新号时，以先合并的 PR 为准，后者顺延。
