# 专家交付指导书：用一个模拟项目走一遍

版本 1.0（2026-11-15）。本文用一个**虚拟项目**从立项走到删除，写清每一步顾问做什么、平台和 Agent 自动做什么、怎么判断做得对。一期操作细节见《专家指导书》v1.0，各角色职责见《人工职责清单》。

> 模拟项目：**BANK-A**（虚拟城商行），产品 **SOC 安全运营体系建设咨询**，勾选模块“行业监管 HYJG”，**标准档**，周期 8 周。
> 人员（虚拟）：项目负责人 lead01；项目经理 pm01；顾问 c01、c02；知识专家 ke01。文中所有客户信息都是虚构的。

## 每天的习惯

1. 登录后先看**工作台**。待办都在这里，包括确认卡、待签署、提醒。置灰的不是你能处理的。
2. 写任何东西前都记住：**不写**口令、密钥、可利用的漏洞细节、完整网络拓扑和 IP 规划、业务数据和个人信息样本。平台会拦截，被拦截了就改写成概括描述。
3. 不出具测评、认证结论，统一用“差距分析、符合性初判、整改建议”。

## 第 0 周 立项（项目负责人 lead01）

1. 打开“我的项目”，点“新建项目”。
2. 客户代号填 `BANK-A`，**不写客户全称**。行业选“银行”。
3. 产品选 SOC，模块勾选“行业监管”。
4. **定档**：先问清客户资料能不能带离现场。能，选标准档；不能，选严格档（严格档做法见本文附录）。档位立项后不能随便改。
5. 首位项目经理选 pm01。

平台会按 SOC 配置建好 D1～D8，并记下配置版本：

| 编号 | 交付件 |
|---|---|
| D1 | 启动包 |
| D2 | 调研包 |
| D3 | 事实清单 |
| D4 | 现状评估报告 |
| D5 | 设计方案 |
| D6 | 制度文件包 |
| D7 | 实施路线图 |
| D8 | 高层汇报 |

以后产品配置有更新，也不影响这个项目。lead01 在“项目总览”能看到该项目的元数据。

pm01 进入项目驾驶舱后：

- 在“成员”里加入 c01、c02；
- 合同里有回流限制的，在“经验回流”里标记“客户不同意回流”。

## 第 1 周 启动（D1）

D1 启动包和 D2 调研包**由顾问写**，交付链不写这两份。

- 在交付件审阅页打开 D1，先写大纲（项目目标、范围、组织、计划、沟通机制），再逐章写。
- 可以在顾问对话里请咨询师 Agent 起草：“按 SOC 产品给 BANK-A 写启动包大纲”。Agent 会给出带来源标注的草稿，复制后再改。
- 启动会纪要：在“项目证据”里点“录入纪要 / 观察”，选“访谈纪要”。受访者只写角色，如“信息科技部负责人”。保存后得到编号，如 I-01。

D1 写完后，平台会自动评审；门禁通过后自动提交签署，pm01 签署。签署流程同第 7 周。

## 第 2～3 周 调研（D2、D3）

**D2 调研包**：顾问按访谈计划写访谈提纲和资料清单，可以请 Agent 按评估域起草。

**交证据**：

| 证据类型 | 怎么交 | 例子 |
|---|---|---|
| 资料 D-xx | 点“上传客户资料”（docx、pdf、xlsx 等），平台在后台解析 | D-01 安全管理制度汇编、D-02 SOC 值班记录样表（去掉人名后再传） |
| 访谈 I-xx | 录入纪要，也可以“从文件导入”正文，文件本身不保存 | I-02 SOC 负责人访谈、I-03 安全分析岗访谈 |
| 观察 O-xx | 录入现场观察 | O-01 监控大屏告警处置流程观察 |

- 传错或录错了，在证据详情里删除。编号保留、不会复用；同一文件可以重新上传。
- 客户书面要求某份资料只能在现场看的，由 pm01 标“仅现场使用”。平台会立即删掉文件，Agent 读不到，交付件也不能引用。

**交链自动开始**：证据齐了（至少有一份访谈或资料），并且没有未结束的运行时，平台自动发起交付链。你也可以在驾驶舱手动“运行”或“取消”。第 3 步由调研访谈 Agent 整理 **D3 事实清单**：按评估域列事实，每条带证据编号，另起一章写“待补证据与矛盾点”。

**顾问审 D3**（这是最关键的一份，后面所有内容都建在它上面）：

- 每条事实后面都应有 `[I-02]`、`[D-01]` 这样的标注。没有标注的事实要删掉，或者补证据。
- 看“待补证据与矛盾点”。按它补访谈、补资料，补完平台会重跑相关步骤。
- 证据不够时，Agent 会发**“证据不足”卡**，交付链停在本步。补完证据后在卡上写“已补 I-04”，交付链继续。

## 第 3～4 周 分析（D4）

第 4 步由依据与差距分析 Agent 完成：

- 对照评估基线做差距分析，依据只取知识库，没有的标“【依据待核实】”；
- 产出差距分析表、业务影响 TOP 5、依据库缺口。

这些产出存在运行记录里，交给后续步骤，不直接成为交付件。

**处理确认卡**（工作台“确认卡”）。例子：

> **来源冲突**：D-01 制度写“7×24 值班”，I-03 访谈说“夜间无人值守、告警次日处理”。
> 选项：A 以访谈为准，判为差距；B 以制度为准；C 补现场观察后再定。推荐 A，理由：访谈与值班记录 D-02 一致。

你选 A，或者写“已安排夜间观察，见 O-02”。处理完交付链自动继续，处理结果作为“顾问已确认事项”交给后续步骤，同一问题本次运行不会再问。

第 7 步由报告撰写 Agent 起草 **D4 现状评估报告初稿**，平台随后**自动排一次质量评审**：

- **平台硬规则**：
  - 缺正文、机密级内容、测评或认证结论用语、来源核对不上 → 阻断；
  - 整章只有 `[推断]` → 重要；
  - 引用的依据已废止或已被替代 → 阻断，即将实施的 → 重要。
- **质量评审 Agent** 再按 `qa-reviewer` 规则给出意见。

**顾问审改 D4**，按这个顺序看：

1. 阻断项：必须改。只有评审 Agent 提的阻断，项目经理认为判错时，可以写理由驳回；平台规则判出的阻断只能改正文。
2. `unresolved`：核对不上的来源标注，改成正确编号，或者删掉这个说法。
3. `[推断]` 多的章节：补证据，或者改成“建议进一步核实”。
4. 依据：法规条号对不对，可以在对话里问“《××办法》第 X 条原文”。Agent 只会给库里的原文，查不到的会标待核实。
5. 对客户的口吻：D4 不能出现差距编号 G-xx、确认卡、“内部”“测试”等字样。

每次保存都会生成新版本，旧版本保留。改完平台自动重评。

## 第 4～6 周 设计（D5、D6、D7）

- 第 5 步由方案设计 Agent 设计**目标运营模型**。遇到两个以上可行路线时，发**“方案取舍”卡**，例如：

  > 自建 7×24 SOC / 与托管服务商共建 / 先日间自建、夜间托管。

  预算、规划期这类只有客户知道的信息，Agent 会发**“范围确认”卡**，不会自己假设。这些卡要和 pm01、客户商量后再选。
- 第 6 步由制度起草 Agent 起草 **D6 制度文件包**。部门名称只用证据里出现过的；不清楚的会发“范围确认”卡。
- 第 7 步由报告撰写 Agent 写 **D5 设计方案**和 **D7 实施路线图**。

顾问审改的重点：

- 方案取舍要和已确认的卡一致；
- 制度条款要可执行（谁、何时、做什么、留什么记录）；
- 路线图的资源和时间要符合客户约束；
- 行业监管模块的要求（如金融行业监管文件）有没有覆盖到。

## 第 7 周 汇报与签署（D8）

- 报告撰写 Agent 根据**已写好的 D4、D5、D7**起草 **D8 高层汇报**，每章一页要点，结论先行，不新增结论。
- **门禁**：每章都有正文、最近一次评审针对当前修订、未驳回的阻断为 0。门禁通过后，D1、D2、D6、D8 由平台**自动提交签署**，并在 pm01 的工作台出现“待签署”；D3、D4、D5、D7 停在起草中，由顾问看过标出的问题后在交付件审阅页点“提交签署”。
- **pm01 签署**：
  - 通读全文，确认对客户负责后签署。签署后只读。
  - 不同意就退回，写理由，交付件回到“起草中”。
  - 待签署期间有人改了正文，交付件会自动退回“起草中”。
- **导出 Word**：
  - 在交付件页点导出；
  - 未签署的版本每页页眉标“草稿”；
  - 来源标注会保留原样，并转成 Word 脚注；
  - 交给客户前，按公司模板做排版检查。

## 第 8 周 验收与沉淀

- pm01 在驾驶舱登记**验收日**和**保留月数**（按合同，默认 6 个月）。平台算出到期日，项目列表会显示“保留中 / 即将到期 / 到期”。
- **结项沉淀**：c01 把可以复用的做法写成投料，交到“知识投料”页，例如“城商行夜间告警托管的取舍要点”。这条投料要走第三级审核：
  1. 去标识；
  2. 知识管理员确认；
  3. Agent 先审；
  4. 非作者知识专家 ke01 拍板。

  投料编号记下来，删除确认时要用。

## 保留期满 删除

- 到期后，worker 自动发起删除申请，lead01 的工作台会出现“资料删除”。
- lead01 打开“删除申请”页确认，选择经验回流情况：已回流（填投料编号）/ 无可回流 / 客户不同意回流。发起人不能自己确认。
- 平台删除对象存储和全部项目数据，包括已签署的交付件。项目代号保留、不再复用。完成后的申请就是可以交给客户的**删除记录**。
- 客户书面要求提前删除的：pm01 填文号发起，lead01 要在 10 个工作日内确认。

## 附录 A 严格档怎么做（模拟 GRID-B，SOC，严格档）

资料不出客户现场，平台只收去标识后的摘要卡。

1. **客户同意**：pm01 登记客户书面同意的文号和日期，不写客户名称。没有有效同意，什么都不能上传。
2. **现场整理**：
   - 顾问在现场用离线网页 `field-tool.html`，按 SOC 评估项填摘要卡：评估项、现状、数量级、现场证据编号、客户审阅日期；
   - 真名用占位符代替；
   - 对照表（占位符与真名）只存在加密的 `.cpwork` 文件里，只留在现场；
   - 页面会自检：机构名、人名、联系方式、IP、系统名和版本号、引号原话。
3. **上传**：客户审阅后，导出 `.cpcard` 上传。任何一张卡不过检查，整批都会被拒收。上传后卡片编号为 S-xx。
4. **交付链**：读摘要卡 S-xx 起草，正文只用占位符，标 `[S-xx]`。出现真名会被判阻断，不保存。
5. **客户撤回同意**：pm01 登记撤回后，平台会清空：
   - 摘要卡；
   - 据摘要卡写成的未签署正文、评审和交付链产出；
   - 未结束的运行（自动取消）。

   已签署的交付件保留。
6. **交给客户**：导出的是占位符版本，由顾问在现场用对照表还原真名，还原后的文件不回传平台。

## 附录 B 自检清单（交给 pm01 签署前）

- [ ] 每条结论都能追到证据编号或 L4 依据，`[推断]` 只出现在建议部分
- [ ] 没有测评、认证结论用语
- [ ] 没有客户真名以外的敏感信息（口令、IP 规划、漏洞细节、个人信息）
- [ ] 引用的法规标准现行有效（平台会拦截，但人也要看一眼版本）
- [ ] 确认卡全部处理完，方案与已确认事项一致
- [ ] 对客户的文件里没有 G-xx、确认卡、“内部”“测试”等字样
- [ ] 严格档：全部用占位符，`[S-xx]` 标注齐全
