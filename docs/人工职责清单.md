# 人工职责清单（目标态，按角色）

版本 1.0（2026-11-15）。依据：《二期开发计划》第十二节“自动化优先原则”、《人工环节复查》（C5）、决策记录 2026-11-15。

**适用范围**：二期全部合并后的平台，包括工作台、项目总览、网页立项、交付链自动发起和评审、知识三级审核、依据时效门禁、运维定时检查与告警。部分功能还在测试中，以《二期开发计划》第四节的状态为准。

配套文件：

- 《知识管理指导书》：知识侧按顺序怎么做。
- 《专家交付指导书》：模拟一个项目，从头到尾怎么做。
- 《专家指导书》v1.0：一期操作细节。

## 总原则：人只做五类事

平台能自动做的都已经自动做了。人只做下面五类事，其余的事情是平台和 Agent 做、人看结果。

| 类别 | 例子 | 为什么必须人做 |
|---|---|---|
| 对客户负责的签字 | 签署交付件、确认删除 | 对外交付和不可逆操作要有人担责 |
| 客户数据 | 去标识确认、客户书面同意、仅现场使用 | 数据保护红线 |
| 只有人知道的事 | 上传证据、访谈纪要、处理确认卡、经验回流 | 信息在人和客户那里 |
| 公司经验的认可 | 项目沉淀、专家经验（L2、L5）发布 | 是不是公司认可的做法只能人判断 |
| 规则变更 | Agent md、权限、工具授权、决策、产品配置 | 负责人审批 |

**每个人每天的入口是工作台**：登录后默认进入工作台。上面汇总了本人各个角色的待办，包括确认卡、待签署、知识审核、补复审、去标识确认和删除申请。

- 本人不能处理的待办会置灰，并写明该由谁处理。例如作者不能审自己的版本，发起人不能确认删除。
- 侧栏“工作台”上的数字是本人能处理的待办数。

## 一、负责人（平台所有者）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 拍板规则变更 | 有 PR 或待决定事项时 | 在 PR 或对话里同意，并写进 `docs/决策记录.md`。范围包括 Agent md（`agents/`）、权限矩阵、工具授权（新迁移）、产品配置从 draft 改为 ready、知识元数据取值 |
| 合并 PR | CI 全绿，且测试助手留了“测试通过”评论 | 在 GitHub 上合并；里程碑验收后打标签 |
| 恢复自动发布 | 管理员硬停了 `KB_SRC_AUTO_PUBLISH` 或 `KB_AGENT_AUTO_PUBLISH` 之后 | 先看抽检问题率已回到 10% 以下、原因已修，再同意恢复 |
| 同意删除数据、改迁移历史、外部服务 | 开发提出时 | 先书面同意，再执行 |
| 定待决定事项 | 《二期开发计划》待决定一节 | 一次批量确认，写进决策记录 |

## 二、项目负责人（project_lead）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 立项 | 合同签订后 | 在“我的项目”点“新建项目”。<br>① 填客户代号，不写客户名称。<br>② 选产品（SOC / ISO / DSM / IRE / NSG），勾选模块（等保 DJBH、行业监管 HYJG、个保 GFYL）。<br>③ **定档**：客户资料能离场的选标准档，否则选严格档。<br>④ 指定首位项目经理。<br>平台会按产品配置建交付件清单，并记下配置版本 |
| 看全局 | 随时 | 在“项目总览”看全部项目的元数据（档位、阶段、交付件进度、保留期）。不是项目成员的看不到项目内容；需要进入的，请项目经理把你加为成员 |
| 确认删除 | 工作台出现“资料删除” | 打开“删除申请”页，核对项目代号和日期，选择经验回流情况后确认：<br>• 已回流：填投料编号；<br>• 无可回流；<br>• 客户不同意回流。<br>注意：<br>• **不能确认自己发起的申请**；<br>• 客户要求提前删除的，要在 10 个工作日内完成；<br>• 确认后不可撤销 |
| 撤销提前删除 | 客户撤回删除要求 | 在删除申请页写理由后撤销。到期删除不能撤销，要改的话由项目经理更正保留期 |

## 三、项目经理（项目内角色 manager）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 组建项目组 | 立项后 | 在项目驾驶舱的“成员”里添加顾问 |
| 严格档登记客户书面同意 | 严格档开工前 | 在驾驶舱的“客户同意”登记文号和签署日期，**不写客户名称**。没有有效同意，平台不收摘要卡 |
| 标“仅现场使用” | 客户书面要求某份资料不能留在平台 | 在证据详情点“标为仅现场使用”，填文号。平台会立即删除文件，此操作不可撤销 |
| 驳回评审 Agent 的阻断 | 认为 Agent 判错时 | 在交付件审阅页逐条写理由（至少 10 字）。平台规则判出的阻断不能驳回，只能改正文 |
| 签署或退回 | 工作台出现“待签署”（D1、D2、D6、D8 门禁通过后平台自动提交；D3、D4、D5、D7 由顾问提交） | 在交付件审阅页通读一遍后签署。不同意就退回，必须写理由。签署后只读 |
| 登记验收 | 客户验收后 | 在驾驶舱登记验收日和保留月数（按合同，默认 6 个月）。平台会计算到期日 |
| 发起提前删除 | 客户书面要求 | 在驾驶舱的“删除”填文号后发起，再由项目负责人确认 |
| 标“客户不同意回流” | 合同或客户不允许沉淀经验 | 在驾驶舱的“经验回流”标记 |

## 四、顾问（项目成员）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 交证据 | 调研期间持续交 | 在驾驶舱的“项目证据”里上传资料，或录入访谈纪要和现场观察。<br>• 访谈只写受访者角色。<br>• **不收**：口令、密钥、漏洞细节、完整 IP 规划、个人信息样本。平台会拦截。<br>• 传错了自己删除，编号保留。<br>证据齐了以后，平台自动发起交付链 |
| 处理确认卡 | 工作台出现“确认卡” | 卡片上已列出选项、推荐、理由和影响。你选一个选项，或写意见。处理完平台自动继续，同一问题本次运行不会再问 |
| 审改交付件 | 交付链写完、平台自动评审后 | 在交付件审阅页逐章看。重点核对三类问题：<br>• 来源标注：`[推断]` 多的章节；<br>• 评审意见里的“重要”项；<br>• `unresolved` 里核对不上的引用。<br>改完平台自动重评；门禁通过后 D1、D2、D6、D8 自动提交签署，D3、D4、D5、D7 由你看过标出的问题后提交 |
| 对话求助 | 随时 | 在顾问对话里提问。咨询师 Agent 会转交专业 Agent；依据查不到的会标“【依据待核实】” |
| 依据换版复核 | 工作台或驾驶舱提醒“依据已更新” | 打开相关章节，换成新依据。引用已废止条款的交付件不能签署 |
| 结项沉淀 | 验收前后 | 把可复用的做法写成投料，交给知识侧（去标识后走第三级审核） |
| 严格档：现场整理摘要卡 | 现场 | 用现场工具 `field-tool.html`（离线）整理摘要卡并自检。对照表只留在现场，上传包只含摘要卡 |

## 五、知识库负责人（专人）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 维护下载清单 | 每批入库前 | 按《知识管理指导书》第二步写 CSV，包括原网址、sha256、文号、现行状态等 |
| 季度官网核对 | 每季度首月 | 产出核对清单，交给知识管理员执行 `kb-basis-check`（见指导书维护一节） |
| 看问题率与运营 | 每周 | 看“知识地图与健康”页：覆盖缺口、抽检问题率、自动发布占比、待复查数 |
| 排萃取和专家时间 | 每月 | 优先保证存疑项和抽检，萃取可以顺延 |

## 六、知识专家（产品专家负责人等）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 审存疑项 | 工作台出现“知识审核（内容）” | 知识审核 Agent 已标出存疑的项目，并附原文对照。你只看标出的几处，按七项清单判断：<br>① 忠于原文；<br>② 不添加要求；<br>③ 引用对得上；<br>④ 资质边界；<br>⑤ 无客户与机密信息；<br>⑥ 不重复不冲突；<br>⑦ 适用条件清楚。<br>不能审自己写的版本 |
| 抽检 | 抽检队列有条目时 | 依据原文 SRC 抽 5%，Agent 审核的抽 20%。对照原文按七项清单看，不通过的退回。不能抽检自己导入的版本 |
| 第三级拍板 | 项目沉淀、专家经验进队列时 | 去标识已由知识管理员确认、Agent 已先审。一位非作者知识专家判断这是否是公司认可的做法，然后发布或退回 |
| 处理待复查 | 顾问常改掉的条目被平台标“待复查”时 | 判断条目本身有错（修改，建新版本），还是不适用该场景（补适用条件） |
| 提供公司做法 | 产品交付包、萃取工作坊 | 给出交付包结构和公司实践，开发线 2 负责起草 |
| 评测题评审 | 每批入库前 | 核对题目和标准答案 |
| 复审 | 条目到期，且 Agent 存疑或属于第三级时 | 确认仍然有效，或修改、下线 |

## 七、知识管理员

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 去标识确认 | 工作台出现“去标识确认” | 在知识投料页看规则词库和脱敏审查 Agent 的报告（只有类别、占位符和次数），对照去标识后的文本确认。**不能是上传者**。确认后平台删除原件 |
| 合规审核存疑项 | 工作台出现“知识审核（合规）” | 看资质边界、机密信息、版权（国标不收全文） |
| 硬停自动发布 | 抽检问题严重、平台未自动停时 | 设开关 `KB_SRC_AUTO_PUBLISH=false` 或 `KB_AGENT_AUTO_PUBLISH=false`，并通知负责人 |
| 依据变更登记 | 每季度 | 执行 `kb-basis-check <核对清单> --as <你>`，先比对；核对无误后加 `--apply` 登记 |

## 八、系统管理员

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 账号与角色 | 有人入职、离职或调岗 | 在“用户与角色”页操作。<br>• 离职人员当天停用，平台不知道谁离职了。<br>• 超过 90 天未登录的账号会被自动停用，需要恢复的在页面上恢复 |
| 重置 TOTP | 用户换手机 | 先当面或电话核实身份，再执行 `python -m app.cli reset-totp` |
| 处理告警 | 收到告警时 | worker 每天自检、校验审计链、检查任务积压和备份时间，告警渠道见《监控》。按《运维手册》处理 |
| 看模型状态 | 告警或用户反馈时 | 打开“模型配置状态”页 |
| 首个管理员、审计员任命 | 部署时 | 只能用命令行（`create-user`、`grant-role --role auditor`） |

## 九、安全审计员

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 查审计 | 每月或有事件时 | 在审计页查看。审计不记原文，只有编号、计数和哈希 |
| 看校验结果 | 有告警时 | 审计链每天自动校验，异常时复核 `verify-audit` 的输出 |

## 十、运维（部署机）

每季度：

- 恢复演练（`scripts/restore.sh` 恢复到测试机）；
- 升级镜像和依赖，并走 PR；
- 换向量模型后执行 `kb-reembed`。

以上属于变更，必须由人做。日常检查已经由 worker 定时执行，见《运维手册》月检表。

## 十一、法务 / 保密部门

书面答复以下三个问题，在答复前项目经验不得进入公司实践：

1. 客户资料能否用于知识沉淀？
2. 合同是否限制使用 AI？
3. 内部制度能否改造成母版？

另外负责维护客户数据告知模板与合同条款（`docs/客户数据告知模板与合同条款.md`）。
