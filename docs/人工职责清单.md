# 人工职责清单（目标态，按角色）

版本 1.1（2026-11-27 按《平台规划刷新设计》刷新，负责人 11-27 确认；1.0 为 2026-11-15）。依据：《二期开发计划》第十二节“自动化优先原则”、《人工环节复查》（C5）、决策记录 2026-11-15。

**适用范围**：二期全部合并后的平台，包括我的任务、项目总览、网页立项、交付链自动发起和评审、知识三级审核、依据时效门禁、运维定时检查与告警。部分功能还在测试中，以《二期开发计划》第四节的状态为准。

**1.1 变化摘要**（详见 `docs/知识中心改版方案.md` v3.1、`docs/决策记录.md` 2026-11-27）：

- 减 9 项：手写下载清单、季度官网核对、每周看健康页、手动硬停、顾问写结项投料、删除时填投料编号、依据换版后手工修改、全量评测题评审、固定比例抽检（改为按类型自适应抽检）。
- 增 8 项：定制项确认、注入命中确认、结项复盘、勘误决定、结项清单与项目终止、专家认可与裁决、投毒处置、负责人处理 Agent 变更 / 系统卡住 / 门槛调整。
- 优化 6 项：统一收件箱、别人的卡隐藏、卡片统一格式、超时不代为决定、按“按推荐处理率”建议 L2 与 L3 升降、每人每日预算。
- 角色：“项目负责人”显示名改为“咨询业务负责人”（编码 `project_lead` 不变）；不设知识库负责人，并入知识管理员。

配套文件：

- 《知识管理指导书》：知识侧按顺序怎么做。
- 《专家交付指导书》：模拟一个项目，从头到尾怎么做。
- 《专家指导书》v1.0：一期操作细节。

## 总原则：人只做五类事

平台能自动做的都已经自动做了。人只做下面五类事，其余的事情是平台和 Agent 做、人看结果。

| 类别 | 例子 | 为什么必须人做 |
|---|---|---|
| 对客户负责的签字 | 签署交付件、确认删除 | 对外交付和不可逆操作要有人担责 |
| 客户数据 | 去标识确认、客户书面同意、仅现场使用 | 数据保护红线 |
| 只有人知道的事 | 上传证据、访谈纪要、处理确认卡、经验回流 | 信息在人和客户那里 |
| 公司经验的认可 | 项目沉淀、专家经验（L2、L5）发布 | 是不是公司认可的做法只能人判断 |
| 规则变更 | Agent md、权限、工具授权、决策、产品配置 | 负责人审批 |

**每个人每天的入口是我的任务**：登录后默认进入我的任务。上面汇总了本人各个角色的待办，包括确认卡、待签署、知识审核、补复审、去标识确认和删除申请。

- 只显示本人能处理的卡，别人的卡直接隐藏，不做灰显（1.1 起）。例如作者不能审自己的版本，发起人不能确认删除，这类卡只出现在另一位处理人那里。
- 卡片统一格式：标题、情况与补充两栏、推荐处理按钮放第一个、影响说明、预计分钟数；同类可批量处理。顶部显示待处理数、预计分钟数与每日预算、本周 AI 已自动办完多少件。
- 超时：3 个工作日提醒，7 天升级，**不替人代为决定**。
- Agent 运行情况默认隐藏；右上角“查看 Agent 运行情况”按键按权限只读显示（知识专家无此键）。失败或卡住不论开关都推卡。
- 侧栏“我的任务”上的数字是本人能处理的待办数。
- 原“工作台”已并入“我的任务”（负责人 2026-11-25 试用反馈），旧链接 /workbench 自动跳到 /my-tasks。

## 二、咨询业务负责人（project_lead，原显示名“项目负责人”）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 立项 | 合同签订后 | 在“我的项目”点“新建项目”。<br>① 填客户代号，不写客户名称。<br>② 选产品（SOC / ISO / DSM / IRE / NSG），勾选模块（等保 DJBH、行业监管 HYJG、个保 GFYL）。<br>③ **定档**：客户资料能离场的选标准档，否则选严格档。<br>④ 指定首位项目经理。<br>平台会按产品配置建交付件清单，并记下配置版本 |
| 看全局 | 随时 | 在“项目总览”看全部项目的元数据（档位、阶段、交付件进度、保留期）。不是项目成员的看不到项目内容；需要进入的，请项目经理把你加为成员 |
| 确认删除 | 我的任务出现“资料删除确认” | 打开“删除申请”页，核对项目代号和日期；平台已自动列出该项目来的知识条目及处理方式（知识侧追溯），核对后确认，不再手填投料编号。<br>注意：<br>• **不能确认自己发起的申请**；<br>• 客户要求提前删除的，要在 10 个工作日内完成；<br>• 确认后不可撤销 |
| 投毒处置审批（置顶） | 知识管理员核实并提出处置意见后 | 看影响范围与处置意见（清除、部分清除或恢复），批准后平台执行。不能批准自己提出的意见；同批投料在发现时已自动冻结 |
| 泄漏事件（置顶） | 已发布条目发现残留客户信息 | 平台已下线并复查同批，确认处置结果 |
| 系统卡住 | 运行自动重试 2 次仍失败 | 看失败类型，决定重跑、暂停或交开发；同一原因合并成一张 |
| Agent 变更上线、门槛与自主度调整 | 回归评测不低于原分数后；平台按“按推荐处理率”给出 L2 与 L3 升降建议时 | 在卡上确认或否决。提示词和模型只有负责人能改，`agents/*.md` 仍按现行规则 |
| 新增或失效来源 | 来源推荐 Agent 推荐的来源属于例外、或来源失效找不到替代时 | 确认或否决 |
| 跨项目运行状态 | 需要时 | 打开“查看 Agent 运行情况”，只看各项目步骤与失败类型元数据，不看内容 |
| 撤销提前删除 | 客户撤回删除要求 | 在删除申请页写理由后撤销。到期删除不能撤销，要改的话由项目经理更正保留期 |

## 三、项目经理（项目内角色 manager）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 组建项目组 | 立项后 | 在项目驾驶舱的“成员”里添加顾问 |
| 严格档登记客户书面同意 | 严格档开工前 | 在驾驶舱的“客户同意”登记文号和签署日期，**不写客户名称**。没有有效同意，平台不收摘要卡 |
| 标“仅现场使用” | 客户书面要求某份资料不能留在平台 | 在证据详情点“标为仅现场使用”，填文号。平台会立即删除文件，此操作不可撤销 |
| 驳回评审 Agent 的阻断 | 认为 Agent 判错时 | 在交付件审阅页逐条写理由（至少 10 字）。平台规则判出的阻断不能驳回，只能改正文 |
| 签署或退回 | 我的任务出现“待签署”（D1、D2、D6、D8 门禁通过后平台自动提交；D3、D4、D5、D7 由顾问提交） | 在交付件审阅页通读一遍后签署。不同意就退回，必须写理由。签署后只读 |
| 登记验收 | 客户验收后 | 在驾驶舱登记验收日和保留月数（按合同，默认 6 个月）。平台会计算到期日 |
| 发起提前删除 | 客户书面要求 | 在驾驶舱的“删除”填文号后发起，再由咨询业务负责人确认 |
| 标“客户不同意回流” | 合同或客户不允许沉淀经验 | 在驾驶舱的“经验回流”标记 |
| 确认结构类定制项 | 顾问登记了增删章节的客户定制项 | 确认后才生效；形式类、口径类顾问确认即生效 |
| 勘误决定 | 已签署交付件引用的条目被下线或有误 | 在勘误卡上决定是否出勘误页；原签署版保留，已签署的不能直接改 |
| 确认卡超时、成员移出 | 确认卡 7 天未处理升级；成员被移出后其待办自动转来 | 处理或再分派 |
| 结项清单与项目终止 | 结项前；项目中止时 | 结项清单列出未签交付件、未关的卡、待复查项，逐项关闭；终止后停止自动推进、关闭待办，保留期从终止日起算 |
| 结项复盘 | 结项时 | 在驾驶舱“结项复盘”勾选平台推荐的候选（做法、常见坑、黄金样例），确认去标识后成批交出。代替原来顾问手写结项投料 |
| 本项目作业流 | 交付链失败或需要排查时 | 打开“查看 Agent 运行情况”，可重跑、暂停本项目交付链；不能改提示词和模型 |

## 四、顾问（项目成员）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 交证据 | 调研期间持续交 | 在驾驶舱的“项目证据”里上传资料，或录入访谈纪要和现场观察。<br>• 访谈只写受访者角色。<br>• **不收**：口令、密钥、漏洞细节、完整 IP 规划、个人信息样本。平台会拦截。<br>• 传错了自己删除，编号保留。<br>证据齐了以后，平台自动发起交付链 |
| 处理确认卡 | 我的任务出现“确认卡” | 卡片上已列出选项、推荐、理由和影响。你选一个选项，或写意见。处理完平台自动继续，同一问题本次运行不会再问 |
| 审改交付件 | 交付链写完、平台自动评审后 | 在交付件审阅页逐章看。重点核对三类问题：<br>• 来源标注：`[推断]` 多的章节；<br>• 评审意见里的“重要”项；<br>• `unresolved` 里核对不上的引用。<br>改完平台自动重评；门禁通过后 D1、D2、D6、D8 自动提交签署，D3、D4、D5、D7 由你看过标出的问题后提交 |
| 对话求助 | 随时 | 在顾问对话里提问。咨询师 Agent 会转交专业 Agent；依据查不到的会标“【依据待核实】” |
| 依据换版 | 我的任务出现“依据已更新，修订稿待接受” | 平台已按新依据出修订稿，对照修订痕迹接受或退回，不再手工改。引用已废止条款的交付件不能签署 |
| 处理补资料卡 | AI 写到一半停下等资料 | 卡上写明缺什么、影响几项，补齐后自动继续 |
| 确认客户定制项 | 在对话里提了客户的定制要求，平台拆成定制项确认卡 | 确认即生效；增删章节的另需项目经理确认；越过红线或资质边界的平台标“不可接受”并说明理由 |
| 确认注入命中 | 资料里有写给 AI 的指令被识别并隔离 | 确认是误报放行，还是保持隔离 |
| 严格档：现场整理摘要卡 | 现场 | 用现场工具 `field-tool.html`（离线）整理摘要卡并自检。对照表只留在现场，上传包只含摘要卡 |

## 五、知识库负责人（1.1 起不设）

负责人 11-27 定：知识侧只有知识专家和知识管理员两个角色。原职责处理如下：下载清单改由来源推荐 Agent 按缺口给出正文网址；季度官网核对改为定时巡检自动做；每周看健康页取消（需要人时推卡）；排萃取和专家时间由平台按每人每日预算排；治理职责并入知识管理员，最终拍板归咨询业务负责人。

## 六、知识专家（产品专家负责人等）

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 审存疑项 | 我的任务出现“知识内容审核”（点“去处理”直接进专家工作台对应的问答卡） | 知识审核 Agent 已标出存疑的项目，并附原文对照。你只看标出的几处，按七项清单判断：<br>① 忠于原文；<br>② 不添加要求；<br>③ 引用对得上；<br>④ 资质边界；<br>⑤ 无客户与机密信息；<br>⑥ 不重复不冲突；<br>⑦ 适用条件清楚。<br>不能审自己写的版本 |
| 抽检 | 我的任务出现抽检卡（每周不超过 5 张） | 抽检比例由平台按类型与差错率自适应调整，不再固定比例。对照原文按七项清单看，不通过的退回。不能抽检自己导入的版本 |
| 认可公司做法与黄金样例 | 我的任务出现认可卡（AI 基线黄金样例可批量） | 一位非作者知识专家判断是否公司认可的做法或写作范本，认可或退回 |
| 冲突裁决 | 审核两次不一致、依据变更引起做法冲突、编写与审核 Agent 意见不一致 | 在裁决卡上选定；每次判定自动补进评测题 |
| 第三级拍板 | 项目沉淀、专家经验进队列时 | 去标识已由知识管理员确认、Agent 已先审。一位非作者知识专家判断这是否是公司认可的做法，然后发布或退回 |
| 处理待复查 | 顾问常改掉的条目被平台标“待复查”时 | 判断条目本身有错（修改，建新版本），还是不适用该场景（补适用条件） |
| 提供公司做法 | 产品交付包、萃取工作坊 | 给出交付包结构和公司实践，开发线 2 负责起草 |
| 评测题复核 | 我的任务出现标“待专家复核”的评测题 | 只复核这批题的题目和标准答案，不再全量评审 |
| 到期复认 | 公司经验到期，且期间引用不足 5 次或有负面反馈（其余自动续期并通知） | 确认仍然有效，或修改、下线 |

## 七、知识管理员

判断“能不能收”，负责治理，只处理例外。暂无人选：试用期间用测试账号顶上，正式上线前必须指定一位，且不能是咨询业务负责人本人（负责人 11-27）。可与知识专家一人兼任，但需双人确认的操作须两个不同的人。

| 做什么 | 何时 | 怎么做 |
|---|---|---|
| 去标识确认 | 我的任务出现“去标识没通过” | 在知识投料页看规则词库和脱敏审查报告（只有类别、占位符和次数），对照去标识后的文本确认或退回。**不能是上传者**。确认后平台删除原件 |
| 合规例外 | 来源不在白名单、抽检差错超过门槛 | 公开资料合规审核由规则与知识审核 Agent 自动做，只有例外推到这里：确认、退回或下线 |
| 投毒事件核实（置顶） | 系统发现疑似投毒，同批已自动冻结 | 核实证据和影响范围（哪些条目受影响、哪些项目引用过），提出处置意见（清除、部分清除或恢复），提交咨询业务负责人审批 |
| 审批新来源、下线条目 | 来源推荐属于例外时；条目确有问题时 | 在卡上确认；下线后依赖条目自动进复审 |
| 知识侧作业流 | 失败卡或需要排查时 | 打开“查看 Agent 运行情况”，可重跑、暂停来源；不能改提示词和模型 |

1.1 起取消：手动硬停自动发布（抽检超标时系统自动停）、每季度手工执行 `kb-basis-check`（依据变更由定时巡检自动比对，异常才推卡）。

## 九、安全审计员

| 做什么 | 何时 | 怎么做 |
|---|---|---|

## 十、运维（部署机）

每季度：

- 恢复演练（`scripts/restore.sh` 恢复到测试机）；
- 升级镜像和依赖，并走 PR；
- 换向量模型后执行 `kb-reembed`。

以上属于变更，必须由人做。日常检查已经由 worker 定时执行，见《运维手册》月检表。

## 十一、法务 / 保密部门

书面答复以下三个问题，在答复前项目经验不得进入公司实践：

1. 客户资料能否用于知识沉淀？
2. 合同是否限制使用 AI？
3. 内部制度能否改造成母版？

另外负责维护客户数据告知模板与合同条款（`docs/客户数据告知模板与合同条款.md`）。
