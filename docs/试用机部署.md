# 试用机部署（测试模式、外部模型）

负责人自用的试用电脑：测试模式运行，对话用外部模型 DeepSeek，重排用硅基流动（决策记录 2026-11-08、2026-11-14）。**只用虚拟客户数据**（BANK-A、GRID-B、MFG-C 等），不放任何真实客户信息；严格档项目在外部模型下拒绝调用模型。这不是生产部署，生产按 `docs/部署手册.md` 执行。

## 一、准备

- Windows 11 + Docker Desktop（WSL2 后端），分给 Docker 的内存 ≥ 12 GB，磁盘 ≥ 40 GB。
- Git。在 Git Bash 里执行下面的命令。
- DeepSeek API 密钥、硅基流动 API 密钥。**只写进 `.env`，不发到聊天、不截图。**

```bash
git clone <仓库地址> consult-platform && cd consult-platform && git checkout main
cp .env.example .env
```

## 二、配置 `.env`

生成随机值（每条运行一次，结果填到对应项）：

```bash
python -c "import secrets; print(secrets.token_urlsafe(24))"     # POSTGRES_PASSWORD、APP_POSTGRES_PASSWORD、KB_POSTGRES_PASSWORD 各一个
python -c "import secrets; print(secrets.token_urlsafe(30))"     # MINIO_SECRET_KEY
python -c "import base64, secrets; print('platform-key:' + base64.b64encode(secrets.token_bytes(32)).decode())"   # MINIO_KMS_SECRET_KEY
python -c "import base64, secrets; print('k1:' + base64.b64encode(secrets.token_bytes(32)).decode())"             # TOTP_KEYS
```

要改的项：

| 项 | 值 |
|---|---|
| `APP_ENV` | `dev`（**不能是 prod**：prod 下外部模型、外部重排都会拒绝启动） |
| `COOKIE_SECURE` | `false`（用 http:// 访问） |
| `WEB_PORT` | `8080`，被占用就换一个；本机还跑别的项目时用 81xx 段：`WEB_PORT=8180`、`BACKEND_DEBUG_PORT=8181`、`WEB_TLS_PORT=8182` |
| `WEB_BIND` | 只自己在本机用就设 `127.0.0.1`，局域网其他电脑访问不到；要给同事用则不设 |
| `POSTGRES_PASSWORD` / `APP_POSTGRES_PASSWORD` / `KB_POSTGRES_PASSWORD` | 上面生成的，三个各不相同 |
| `MINIO_SECRET_KEY` / `MINIO_KMS_SECRET_KEY` / `TOTP_KEYS` | 上面生成的。KMS 密钥另存一份，丢了文件无法解密 |
| `LLM_EXTERNAL` | `true` |
| `LLM_BASE_URL` | `https://api.deepseek.com` |
| `LLM_API_KEY` | DeepSeek 密钥 |
| `LLM_MODEL_REASONING` / `STANDARD` / `LIGHT` | DeepSeek 控制台给的模型 ID |
| `SEED_DEMO_DATA` | `true`（首次启动写入虚拟客户演示数据） |

硅基流动重排，加四行：

```
RERANK_EXTERNAL=true
RERANK_BASE_URL=https://api.siliconflow.cn/v1
RERANK_API_KEY=<硅基流动密钥>
RERANK_MODEL=Qwen/Qwen3-Reranker-8B
```

本地 rerank 容器仍按默认的 int8 模型构建，不受 `RERANK_MODEL` 影响（#87）。国内网络构建慢时，打开 `PIP_INDEX_URL`、`NPM_REGISTRY` 两行的镜像源。

## 三、启动

```bash
docker compose up -d --build        # 首次构建要下载镜像和模型，较慢
docker compose ps                   # 等全部 healthy
```

## 四、首个账号

```bash
docker compose exec backend python -m app.cli create-user --username admin --display-name 管理员   # 口令交互输入
docker compose exec backend python -m app.cli grant-role --username admin --role sys_admin
```

create-user 会在终端显示动态码密钥，用手机认证器（如 Microsoft Authenticator）添加；密钥不要截图外传。浏览器打开 `http://localhost:8080`（改过 WEB_PORT 就用新端口）用 admin 登录。管理员看不到业务数据，所以要在“用户与角色”页另建一个顾问账号（例如 `alex`）来使用。然后立项：

```bash
docker compose exec backend python -m app.cli create-project --code BANK-T --tier standard --manager alex --industry 银行
```

## 五、验证

```bash
docker compose exec backend python -m app.cli selfcheck
curl -s http://localhost:${WEB_PORT:-8080}/api/health
```

`llm`、`rerank`、`embedding` 都应是 ok。之后用顾问账号在对话里提一个问题，能收到回复就说明打通了。

换了重排模型后检索门槛要重新校准：用 `kb-eval` 跑评测集（见 `docs/知识库建设方案.md`），再按结果调 `KB_BASIS_MIN_RERANK`、`KB_SEARCH_MIN_RERANK`。

## 六、日常

```bash
# 二期期间（2026-11-16～12-31）试用机不同步代码，保持 v1.0，不执行 git pull（决策记录 2026-11-14）；
# 要更新由负责人决定，届时再执行：git pull && docker compose up -d --build
docker compose stop                            # 停（数据保留）
docker compose logs --no-color --since 30m backend | tail -100
```

**不要执行 `docker compose down -v`**，这会删除数据。改了 `.env` 要用 `up -d`，`restart` 不会重新读取 `.env`。
