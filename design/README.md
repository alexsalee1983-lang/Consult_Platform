# 界面设计稿（暗色版，正式）

来源：claude.ai 画布《安全咨询 Agent 平台界面》的暗色版 6 屏，2026-11-07 定稿。每屏 1600×900。

| 文件 | 界面 | 在哪个里程碑实现 |
|---|---|---|
| `screens/01-顾问对话` | AI 咨询对话：结论摘要、风险矩阵、整改行动手册、可折叠审计证据；右侧风险雷达、CVSS 仪表、离线导出 | M0 已有简版；M1 加 Agent 切换；M3 接交付件 |
| `screens/02-我的项目` | 项目列表（阶段、数据档位、态势评分）、待我确认、Agent 动态、投料入口 | M0 已有简版；M1 接权限 |
| `screens/03-项目驾驶舱` | 关键数字、NIST CSF 2.0 成熟度、风险矩阵、关键发现、交付件、团队与 Agent 组 | M0 已有简版；M3 接真实数据 |
| `screens/04-交付件审阅` | 目录与来源构成、报告正文（上标证据、四要素建议卡、三线表）、专家审阅卡、签署流程 | M3 |
| `screens/05-知识审批队列` | 待审队列、条目版本差异、Agent 审查意见、发布影响、双人审核 | M2 |
| `screens/06-知识地图与健康` | 关键数字、覆盖矩阵、缺口 TOP 5、来源构成、待复审 | M2 |

每屏有两个文件：`.html` 可直接用浏览器打开（静态稿，链接可在 6 屏之间跳转），`.png` 是截图。实现时以 `.html` 的结构和数值为准，组件化后放进 `frontend/src`。

## 设计规范

| 令牌 | 值 | 用途 |
|---|---|---|
| `--obs` | `#0A0D12` | 页面底色（曜石黑） |
| `--s1` / `--s2` / `--s3` | `#10151C` / `#161D27` / `#1D2633` | 面板、次级面板、选中与填充 |
| `--ln` / `--ln2` | `#232D3B` / `#2E3A4B` | 分隔线、边框 |
| `--tx` / `--tx2` / `--tx3` | `#E6EBF2` / `#A3AEBE` / `#6B7789` | 正文、次要文字、标签 |
| `--amber` | `#F5A524` | 主操作、当前位置、现状、待判断 |
| `--crim` | `#F0454F` | 高风险、证据不足、拦截 |
| `--cyan` | `#22D3EE` | 目标值、实时状态、公司实践 / 业界框架来源 |
| `--ok` | `#3DD68C` | 客户证据、已完成、已签署 |
| `--vio` | `#B49CFF` | 模型推断、来源冲突 |

- 字体：Inter + 思源黑体（Noto Sans SC）；编号、数字用 JetBrains Mono。内网无法访问 Google Fonts 时回退到系统字体，不影响使用。
- 来源颜色是固定语义：绿 = 客户证据，青 = 公司实践 / 业界框架，紫 = 模型推断。正文里的证据用上标编号引用，页脚列出来源。
- 整改建议必须是四栏卡片：优先级、责任部门、周期、验收标准。
- 草稿始终显示“草稿 · 待顾问审核”；数据档位始终可见（标准档青色、严格档猩红）。
- 前端实现只用 `frontend/src/theme.css` 中的令牌，不写硬编码颜色。

界面中的项目、人名、数字均为虚拟客户示例。
